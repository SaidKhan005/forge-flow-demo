# Phase 11a.3 - Supabase Corpus Storage Schema

Updated: 2026-04-25
Owner: Codex planning / advisor infrastructure lane
Status: Complete - migration scaffold landed; no live database apply

## Plain English

The corpus now produces deterministic ingest records; this run creates the
Postgres tables those records will eventually land in. Example:
`source_chunks.jsonl` has a matching `advisor_source_chunks` table with stable
IDs, source hashes, heading paths, risk metadata, provenance, and pending
embedding fields.

## Migration

The scaffold migration is:

```text
supabase/migrations/202604250001_advisor_corpus_storage_schema.sql
```

It prepares:

- `vector` and `pgcrypto` extensions
- conditional `age` extension creation when Apache AGE is available in the
  target Postgres environment
- `advisor_ingestion_runs`
- `advisor_source_documents`
- `advisor_source_chunks`
- `advisor_graph_node_seeds`
- `advisor_graph_edge_hints`
- conservative relational / GIN indexes
- row-level security enablement
- service-role write policies
- global shared methodology read placeholders for authenticated users

The migration is not applied in this slice. It is a repository scaffold for the
future Supabase project/local stack. As of `11a.5`, local Supabase Postgres load
verification showed that `vector` is available while `age` is not available in
the tested Supabase image; AGE graph projection therefore remains staged for a
later slice.

## Stored Record Families

### Source Documents

`advisor_source_documents` stores one row per manifest-included document:

- `doc_id`
- `file_name`
- `source_path`
- `title`
- `scope`
- `restaurant_id`
- `brand_context`
- `content_role`
- `authority_tier`
- `risk_level`
- `audience`
- `chunk_profile`
- `graph_profiles`
- `tags`
- `source_sha256`
- `embedding_status`
- `provenance`

### Source Chunks

`advisor_source_chunks` stores one row per planned chunk:

- `chunk_id`
- `doc_id`
- `source_path`
- `scope`
- `restaurant_id`
- `chunk_kind`
- `chunk_profile`
- `heading_path`
- `start_line`
- `end_line`
- `estimated_tokens`
- `risk_level`
- `content_sha256`
- `embedding_status`
- `embedding_model`
- `embedding`
- `text`
- `provenance`

`embedding` is a pgvector column now locked by `11a.6a` to
`vector(1024)` for the Claude-aligned Voyage `voyage-4-large` embedding
contract. Reranking is not a schema column; the first-pass retrieval contract
uses Voyage `rerank-2.5` after pgvector candidate retrieval. No embeddings are
generated by this schema slice.

### Graph Seeds

`advisor_graph_node_seeds` and `advisor_graph_edge_hints` are relational staging
tables for later Apache AGE ingestion. They preserve:

- stable node / edge IDs
- source document and chunk references
- confidence
- risk level
- graph properties JSON
- optional future AGE graph IDs

This keeps graph creation separate from corpus loading so later slices can
validate graph projection without reopening chunking or source parsing.

## RLS Intent

Phase 9 auth is not live yet, so this migration does not claim final permission
behavior. It enables RLS and adds conservative placeholder policies:

- service role can manage ingestion tables
- authenticated reads can see global shared methodology rows
- operator-scoped corpus rows are structurally supported through
  `restaurant_id`, but final per-operator read policies wait for Phase 9 auth
  claims
