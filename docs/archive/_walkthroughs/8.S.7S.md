# 8.S.7S Walkthrough — 7shifts labor adapter (lifecycle = documented)

**Slice:** 8.S.7S (Phase 8.S — engineer-all-17 Wave B; 7shifts labor /
scheduling adapter; highest-share scheduling vendor; only INTEGRATE
scheduling vendor with autoRegister webhooks)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-04
**Lifecycle target at slice close:** `VendorLifecycle.documented`

This slice ships the 7shifts labor adapter at lifecycle =
`documented` per the engineer-all-17 doctrine
(`memory/project_phase_8_engineer_all_17_doctrine.md`). 7shifts
carries the highest operator share of any scheduling vendor F&F has
audited (35%) and is the **only** INTEGRATE scheduling vendor with
autoRegister webhooks — including the load-bearing
`payroll_period.closed` event the Phase 7.58 Primary Driver audit
binds against. Webhooks require the **Gourmet** pricing tier per
<https://www.7shifts.com/pricing>; the adapter detects the operator's
plan tier at connect time and falls back to polling-only with an
explicit operator-facing note when not on Gourmet.

Live HTTP wiring is deferred to `8.S.7S.live.sandbox` /
`8.S.7S.live.prod` (Wave D); this engineering slice ships
fixture-backed coverage of every framework call so the live diff is
bounded.

The slice respects every Hard Promise from `CLAUDE.md`:

1. Pure transport — the adapter writes existing canonical labor
   tables only; no change to `lib/services/*` business logic.
2. Demo-mode persists — the same vendor-picker chrome renders in
   `kDemoMode = true` and `kDemoMode = false`.
3. No app-logic changes before `7.58` — the adapter adds a labor
   data source; metric formulas are untouched (Primary Driver audit
   slice is the consumer).
4. Per-operator isolation — every gateway call routes through
   `OperatorScopedRepository.withTenant(operatorId, locationId, ...)`.
5. Modular Adaptive Agentic RAG — n/a for this surface.
6. Recommendations not commands — n/a (read-only labor inflow).
7. F&F holds provider keys server-side — F&F's 7shifts OAuth client
   credentials live in Cloud Run env at `8.S.7S.live.prod`; the
   documented slice runs entirely against the test transport.
8. AI infra is general-purpose — n/a (labor adapter, not AI).
9. AI cost metering — n/a.
10. Backend phase ships operator-facing UX before phase close — the
    Vendor Connections widget already renders the "Coming soon" pill
    for `documented`-lifecycle vendors; this slice plugs 7shifts
    into that surface. The connect-time non-Gourmet note copy
    lands in the existing `TestConnectionResult.note` channel that
    the admin widget already surfaces.

### `lib/integrations/labor/seven_shifts_webhook_signature_verifier.dart` (NEW)

- `class SevenShiftsWebhookSignatureVerifier implements VendorWebhookSignatureVerifier`
  — HMAC-SHA256 over the raw body, base64-encoded,
  `X-7Shifts-Hmac-SHA256` header (per
  <https://developers.7shifts.com/reference/webhooks>). Constant-time
  compare via the framework's `constantTimeBytesEquals`.
- Optional `X-7Shifts-Timestamp` (Unix epoch seconds) populates
  `WebhookSignatureVerification.timestamp` so the framework's 24h
  replay ceiling enforces against it; when 7shifts does not bind a
  timestamp into the signed payload the verifier returns null and the
  idempotency UNIQUE on `(vendor_id, operator_id, vendor_event_id)`
  is the duplicate-write defense for legitimate retries.
