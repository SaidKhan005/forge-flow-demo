# 7.58.5 Walkthrough — Variance row purity (folded G.5)

**Slice:** 7.58.5 (Phase 7.58 — Primary Driver audit follow-ups)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-01

This walkthrough exercises the read-model purity fix for
`VarianceWeekProjectionReadService`. Operator-visible UX in this slice
is unchanged on the screen (the projection table does not render
`driverLabel` as its own column today — closed shift detail still
renders `_LeverBadge(lever: s.primaryLever)`); the change is observable
to anyone reading the `ProjectionDaypartRow.driverLabel` read-model
field — CSV exports, API consumers, the advisor (11b), and any future
Driver column that the Variance screen adds. Before 7.58.5, an open or
projected row inherited the most recent closed daypart's lever via a
`lastClosedLever[daypart]` carry-forward; the Architecture Contract
Layer 10 ban on overclaim and the 7.58 Primary Driver Contract
"Row-Status Honesty Rules" both reject that. After 7.58.5 the field
returns the row's own driver (when computable) or
`'Not yet available'`, and never the inherited lever.

  (Variance, lines 343-354): "projected and open rows must not

- `docs/contracts/phase_7_58_primary_driver_contract.md`

- `lib/services/variance_week_projection_read_service.dart` —
  `lastClosedLever` map and the carry-forward branch are deleted.
  `_driverLabel(s, status)` now returns the closed row's lever for
  `RowStatus.closed`, and `'Not yet available'` for any other

  cross-references the contract.
- `test/variance_week_projection_read_service_test.dart` — Group I
  is renamed from "driver carry-forward" to "driver row purity (no
  carry-forward)". Three tests that previously asserted the
  inherited lever (`projected row carries forward closed lever from
  same daypart`, `open row carries forward closed lever from same
  daypart`, `most recent closed lever wins carry-forward`) are
  inverted to assert `'Not yet available'`. Two tests that already
  matched the new contract (`no carry-forward across different
  dayparts`, `no prior closed shift means Not yet available`) are
  preserved. The `7.58.5 acceptance` test from the slice prompt
  (Mon lunch closed COVERS_DOWN + Tue lunch open + Wed lunch
  projected) is added at the end of the group, and asserts both the
  closed-row regression check (Mon stays `'COVERS DOWN'`) and the
  open / projected purity (Tue and Wed both `'Not yet available'`).

## Demo seed shape (relevant for this walkthrough)

`MockReplayDataSeed.generateForDate(<today>)` produces 14 current-week
shifts via `_generateCurrentWeekForDate`. Slots before today are
`closed`; slots after today are `projected`; on today, `lunch` is
`closed` (earlier service) and `dinner` / `late_night` are
`projected`. Closed shifts run through `LaborModel.determineLever` to
get a real lever id (e.g. `COVERS_DOWN`, `CPLH_DOWN`, `PPA_DOWN`);
projected shifts are seeded with the `ON_MODEL` sentinel because no
real lever has been computed yet.

So the lunch daypart in any mid-week run has multiple closed rows
followed by at least one projected row — exactly the daypart
carry-forward scenario the prompt's acceptance test mirrors. With the
default business date `2026-03-27` (Friday in W13), Mon-Thu lunch are
closed with deterministic levers and Fri lunch is projected.

## Click path (text trace)

### Step 1 — Launch the operator app in demo mode

Run the operator app with `--dart-define=DEMO_MODE=true` (or the
`main_forgeflow.dart` demo entry — `kDemoMode = true` already pinned
in `lib/data/app_defaults.dart`). The app boots into the operator
shell with the seeded mock replay data source attached.

**Expected:** the operator home screen renders with seeded current
week `2026-W13` and a mid-week date `2026-03-27`.

### Step 2 — Open Variance → This Week → Full Week Projection

Tap the bottom-nav **Variance** tab. Within Variance, the default tab
is **This Week**. Scroll down past the Primary Driver section to the
**Full Week Projection** table.

**Expected:** the projection table renders one row per day Mon-Sun.
Mon-Thu rows show the closed status color and the per-day status
chips (e.g. `L` `D` for Mon-Thu, `L` `D` `LN` for Fri). Fri-Sun rows
show the projected status color. Thu shows a mixed status because
Thu lunch is closed and Thu dinner is projected.

### Step 3 — Expand the Mon row (closed lunch + closed dinner)

Tap the Mon row to expand its daypart detail.

**Expected:** the Mon lunch detail panel renders the
`_ClosedShiftDetail` widget. Its `_LeverBadge` reads the closed shift's
own primaryLever (e.g. `COVERS DOWN`) — this is unchanged by 7.58.5
because closed rows have always rendered their own lever. The Mon
dinner detail behaves the same way.

`ProjectionDaypartRow.driverLabel` for both children of the Mon row
equals the closed shift's lever string (with underscores replaced by
spaces). This is the regression check — closed rows are unchanged.

### Step 4 — Expand the Fri row (projected lunch + projected dinner + projected late_night)

Tap the Fri row to expand its daypart detail.

**Expected:** the Fri lunch detail panel renders the
`_ProjectedShiftDetail` widget with the `PROJECTED` header. There is
no `_LeverBadge` in the projected/open detail panel — projected rows
have never surfaced an inline driver badge in the UI. The change in
this slice is one layer up:

- **Pre-7.58.5:** `ProjectionDaypartRow.driverLabel` for Fri lunch
  was the carried-forward Mon-Thu lunch most-recent-closed lever
  (e.g. `COVERS DOWN`) — silently overclaiming that the Fri open
  shift had the same driver as Thursday lunch before any Friday
  hours had been worked.
- **Post-7.58.5:** `ProjectionDaypartRow.driverLabel` for Fri lunch
  is `'Not yet available'`. Same string for Fri dinner and Fri
  late_night.

This is observable to any consumer of the read model — CSV exports
that serialize `driverLabel`, API responses that return the
projection table, and the advisor reading the projection state.
On-screen UX is unchanged today.

### Step 5 — Expand the Thu row (mixed: closed lunch + projected dinner)

Tap the Thu row to expand its daypart detail.

**Expected:** Thu lunch detail panel renders `_ClosedShiftDetail`
with its `_LeverBadge` showing Thu lunch's own closed lever. Thu
dinner panel renders `_ProjectedShiftDetail` with the `PROJECTED`
header.

`ProjectionDaypartRow.driverLabel`:

- Thu lunch (closed): Thu lunch's own detected lever string.
- Thu dinner (projected): `'Not yet available'`. **Pre-7.58.5,
  this would have been the carried-forward Mon-Wed dinner
  most-recent-closed lever** — exactly the overclaim the contract
  forbids.

### Edge — daypart with no closed rows yet

Today's seed always has Mon-Thu closed in the lunch and dinner
dayparts, but the contract still must hold for the empty-history
case. The `'no prior closed shift means Not yet available'` test
exercises a single projected Mon dinner with no closed predecessors
and asserts `'Not yet available'`. Verified by
`test/variance_week_projection_read_service_test.dart` group I.

### Edge — closed-only daypart

Sat and Sun in the seeded current week are projected-only because
the seed business date is Friday. Earlier in the week (e.g. running
the app with a Sunday business date), Mon-Sat are all closed. In a
closed-only daypart every `ProjectionDaypartRow.driverLabel` is the
row's own closed lever — there is no non-closed row to carry forward
to. The
`'closed row driverLabel is the actual detected lever'` test in
group C continues to assert this, as does the `7.58.5 acceptance`
regression check on Mon (`'COVERS DOWN'`).
