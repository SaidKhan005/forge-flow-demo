# 7.61.2 Walkthrough — `HistoryTeachingAnalyzer` empty-leak default

**Slice:** 7.61.2 (Phase 7.61 — Driver-key audit fix, Finding F-2)
**Status:** Implemented (pending acceptance)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-03

This slice closes Finding F-2 from
[`docs/phases/phase_7_61/phase_7_61_audit_plan.md`](../phases/phase_7_61/phase_7_61_audit_plan.md):
the empty-state default at
[`history_teaching_analyzer.dart:79`](../../lib/services/history_teaching_analyzer.dart)
initialised `mostCommonLeakId = 'covers_down'` and only overrode it
when `freq.isNotEmpty`. With zero leak records the analyzer still
returned `'covers_down'`, `LearnTeachingAnalyzer` stamped that into
`LearnTeachingSummary.primaryLeakId`, and
[`variance_learn_tab.dart:151-153`](../../lib/screens/variance/variance_learn_tab.dart)
materialised a real `coversDown` leak card on the Learn tab — a leak
the operator had not earned. The fix flips the default to `''`; the
empty id flows through `LeverCards.lookup` → null → the 7.61.1 (F-1)
reset branch, which zeros every leak summary field together. The
renderer's existing `LeverCards.lookup(...) ?? null` gate at
[lines 151-153](../../lib/screens/variance/variance_learn_tab.dart)
then drops the leak card into the `'NO PATTERNS YET'` placeholder card
([lines 165-171](../../lib/screens/variance/variance_learn_tab.dart))
without further code change.

The contract reference is R-CONS-9 in
[`docs/contracts/phase_7_61_driver_key_contract.md`](../contracts/phase_7_61_driver_key_contract.md):
`HistoryTeachingSummary.mostCommonLeakId` carries a catalog id OR an
empty string when no evidence exists. Pre-fix the empty-set path
violated the second clause; post-fix it complies.

`7.61.1` (F-1 — analyzer-side `firstWhere(orElse: …)` cleanup)
landed first; `7.61.3` (F-3 — `demo_fixture_data.dart` cleanup) ships
in its own lane. This walkthrough does not touch their files.

## Demo seed shape (relevant for this walkthrough)

[`lib/dev/fixture_seed_data.dart`](../../lib/dev/fixture_seed_data.dart)
seeds 16 weeks of `historicalClosedShifts` plus a fixed
`historyPatternRecords` list (lines 612-642). Every seeded week
carries at least one leak record (`cplh_down`, `splh_down`,
`ppa_down`, `foh_wage_up`, `boh_wage_up`, or `covers_down` with
`isBenchmark: false`), so under the default seed the analyzer's
`leakRecords` list is never empty and `freq.isNotEmpty` always fires.
The F-2 bug therefore does NOT reproduce from the canonical demo
seed — the contract test is the trip-wire (it synthesises the empty
input directly).

The bug becomes reachable for an operator when:

1. A history window contains **only benchmark / favorable rows**
   (e.g. an operator with one perfect week of all-`cplh_up` /
   `splh_up` / `ppa_up` / `covers_up` shifts, no leaks anywhere).
   `HistoryPatternBuilder` emits the rows, `patternRecords.isEmpty`
   is false, `LearnTeachingAnalyzer` invokes
   `HistoryTeachingAnalyzer.summarize(patternRecords)`, the analyzer
   filters `leakRecords` (`!r.isBenchmark && !_favorableIds.contains(r.leverId)`)
   to an empty list, and the freq map is empty.
2. A vendor connector or admin tool (Phase 8 onwards) writes a week
   of pattern records that all happen to be benchmarks — same shape
   as case 1 but produced from outside the demo seed.

Pre-fix both cases stamped a `coversDown` card onto the Learn tab.
Post-fix both render the `'NO PATTERNS YET'` placeholder card. The
demo seed's persistent leak coverage is exactly why this finding
sat at audit-defensive priority — the canonical seed couldn't reach
it, but a real operator could.

### Step 3 — Synthetic zero-leak history (the F-2 case)

The default seed cannot reach the empty-leak branch (every seeded
week has at least one leak, see "Demo seed shape" above). The
contract test in
[`test/contracts/phase_7_61_driver_key_test.dart`](../../test/contracts/phase_7_61_driver_key_test.dart)
synthesises the input directly:

```
input  : const <HistoryPatternRecord>[]                               (zero records)
output : mostCommonLeakId            = ''                             (was 'covers_down' pre-fix)
         mostCommonLeakCount         = 0                              (was 0 — already correct, now reset path)
         mostCommonLeakSideLabel     = 'No leak pattern yet'          (was 'BOTH SIDES' pre-fix)
         topLeakDayparts             = []                             (was [] — already empty)

input  : 1× HistoryPatternRecord(leverId='cplh_down', isBenchmark=false)   (single-record, edge case (a))
output : mostCommonLeakId            = 'cplh_down'                    (freq.isNotEmpty fires; reset does not)
         mostCommonLeakCount         = 1
```

Downstream effect on
[`learn_teaching_analyzer.dart`](../../lib/services/learn_teaching_analyzer.dart):
`patternRecords.isEmpty` is true on the zero-record input, so
`historySummary` is `null` and the early `historySummary == null`
branch (lines 47-58) sets `primaryLeakId = ''` directly without
calling the analyzer. **In production through this path the F-2 bug
was masked** — `LearnTeachingAnalyzer` short-circuits on empty
patterns. The bug is only reached when:

- `patternRecords.isNotEmpty` (so `LearnTeachingAnalyzer` invokes
  the analyzer), AND
- the analyzer's `leakRecords` filter empties to zero (only
  benchmarks / favorables).

The contract test pins the analyzer-layer behavior directly, so the
fix holds for every consumer of `HistoryTeachingSummary`, present
and future. (Phase 8 connectors that emit pattern records without
going through `LearnTeachingAnalyzer` first will inherit the empty-
state envelope correctly because the analyzer itself produces it.)

### Step 4 — Renderer behavior with `primaryLeakId == ''`

[`variance_learn_tab.dart:151-153`](../../lib/screens/variance/variance_learn_tab.dart)
gates on:

```dart
final leakCard = summary.hasHistoryPatterns
    ? LeverCards.lookup(summary.primaryLeakId)
    : null;
```

With the analyzer flip in place, `primaryLeakId == ''` flows through
`LeverCards.lookup('')`, which returns `null` per the contract at
[`app_defaults.dart:471-479`](../../lib/data/app_defaults.dart)
(`if (id == null || id.isEmpty) return null;`). `leakCard == null`
falls into the [`badgeLabel: 'NO PATTERNS YET'`](../../lib/screens/variance/variance_learn_tab.dart)
placeholder card at lines 165-171 with `summary.primaryFixLine` as
the body. Pre-7.61.2, `primaryLeakId == 'covers_down'` would have
resolved through `LeverCards.lookup` to the real `coversDown` card
and rendered the four-card "Recurring Leak" carousel — fabricating
a leak that the operator's history did not contain.

**Expected:** when `summary.hasHistoryPatterns` is true and zero leak
records exist (case 1 in "Demo seed shape" above), the carousel
renders the **`'NO PATTERNS YET'` placeholder card** ONLY, not the
four-card covers_down sequence.

The "non-empty zero-leak" row is the load-bearing pin: it's the
only test in the F-2 group that reaches the analyzer through the
same path the operator does (non-empty `patternRecords` →
`LearnTeachingAnalyzer` invokes the analyzer → analyzer's
`leakRecords` filter empties → empty default flows through
`lookup`). The `const []` rows pin the analyzer's behavior on the
shorter `LearnTeachingAnalyzer.summarize(patternRecords: [])`
short-circuit path, which never reaches the analyzer in
production but pins the analyzer-layer contract for any future
consumer that bypasses the Learn layer.

The F-1 unknown-id envelope and the F-2 empty-set envelope are now
**byte-identical** for the leak side — both flow through the same
`LeverCards.lookup → null → reset` branch. The two tests pin
different inputs to the same explicit "no pattern" output.
