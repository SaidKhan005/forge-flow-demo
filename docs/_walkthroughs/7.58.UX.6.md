# 7.58.UX.6 Walkthrough — DOLLAR IMPACT footer names the math floor

**Slice:** 7.58.UX.6 (Phase 7.58 — Depth Wave, renderer-only)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-05

This slice relabels the DOLLAR IMPACT card footer so the operator can
read `actual − theoretical` with its math-floor context surfaced
inside the existing chrome. Pre-7.58.UX.6 the footer carried a single
date-context line ("Through Tuesday" / "As of close, Mar 29") and the
"theoretical" labor % above it on the variance banner was easy to
misread as an arbitrary corporate target. Jim Taylor ch. 8 names what
that number always was: the operator's **mathematical labor floor at
the locked target rates and wages**. A target sitting below this
floor is unreachable through execution alone.

7.58.UX.6 surfaces this depth as a triplet inline in the existing
footer region. On the deterministic demo seed
(`MockIntegrationReplaySeed.generateForDate('2026-03-27')`) the WTD
aggregation is on-floor (actual labor matches the math floor), so
the rendered triplet reads:

```
Best Possible: 20.5%  ·  Actual: 20.5%  ·  Closable Gap: +0.0 pts
```

A representative over-floor case (e.g. an unfavourable WTD) renders
the same shape with a positive gap, e.g.
`Best Possible: 24.2%  ·  Actual: 31.4%  ·  Closable Gap: +7.2 pts`.
No new card, no new section, no new tile. The footer line that used
to read "Through Tuesday" is replaced by the triplet whenever the
math floor is known; the date-context fallback renders unchanged on
legacy rows that did not preserve `theoreticalLaborPct`.

## What changed

### `lib/widgets/dollar_impact_card.dart`

- `DollarImpactCard` gains two optional named params:
  `theoreticalLaborPct: double?` and `actualLaborPct: double?`.
  Both default to `null`. The persistence schema, formula seam, and
  call-site contract (`weekImpact` / `monthImpact` / `sixtyDayImpact` /
  `annualizedImpact`) are unchanged — these are renderer inputs only.
- New private `_DepthFooter` widget owns the footer region. When both
  new params are non-null, it renders the triplet:
  `Best Possible: <theoretical>%  ·  Actual: <actual>%  ·  Closable Gap: <variance> pts`
  using `AppTextStyles.body13` + `AppColors.textMuted` (the same style
  the pre-7.58.UX.6 footer used). Variance pts uses the shared
  `Fmt.varPts` helper (one decimal, signed, plural-aware), matching
  the pt-display the variance banner already renders.
- When either new param is null the old `Text(footerText)` renders
  unchanged — the honest fallback for legacy seed rows.

### `lib/screens/variance/variance_this_week_tab.dart`

The Variance > This Week DOLLAR IMPACT card call site (line 225)
forwards `weekData.theoreticalLaborPct` and `weekData.actualLaborPct`
to the new params. `WeekData` already exposes both as non-null
`double` getters; the triplet always renders here on the live WTD
path.

### `lib/screens/week_detail_screen.dart`

The Week Detail DOLLAR IMPACT card call site (line 112) forwards
`week.theoreticalLaborPct` and `week.actualLaborPct`. `WeekRecord`
stores both as non-null `double` columns persisted at week close;
the triplet always renders on every row that hits the closed-truth
fast path.

## Demo seed shape (relevant for this walkthrough)

`MockIntegrationReplaySeed.generateForDate('2026-03-27')` produces a
current week (`2026-W13`) with 9 of 14 shifts closed by Friday lunch.
The WTD aggregation against the active target profile (Meridian
demo wages × derived target CPLH / SPLH / PPA) yields:

- `theoreticalLaborPct` = 20.5% (the math floor at the locked rates)
- `actualLaborPct` = 20.5% (closed shift labor dollars / sales)
- `variancePts` = +0.0 pts

The seed is intentionally on-floor — actual labor matches the
mathematical floor exactly. These are the same numbers the
`VarianceBanner` already renders above the DOLLAR IMPACT card; the
new triplet repeats them with the depth-aware framing.

## Click path (text trace)

### Step 1 — Launch the operator app in demo mode

`lib/main_forgeflow.dart` boots the operator shell with
`MockReplayDataSeed` attached. Default business date `2026-03-27`
(Friday in W13).

**Expected:** the operator home renders with the seeded current-week
data.

### Step 2 — Tap Variance → This Week tab

The sticky `VarianceBanner` reads `weekData.theoreticalLaborPct =
20.5` → `weekData.actualLaborPct = 20.5` and renders the existing
`20.5% → 20.5% [+0.0 pts]` header. Below it the sticky section header
`DOLLAR IMPACT` precedes the `DollarImpactCard`.

**Expected:** the sticky banner is unchanged (this slice does not
touch it). The DOLLAR IMPACT card renders its dollar rows (`this
week` and any of `this month` / `last 60 days` / `annualized` whose
inputs are populated) exactly as before.

### Step 3 — Read the DOLLAR IMPACT card footer

Below the dollar rows the footer region now renders the triplet:

```
Best Possible: 20.5%  ·  Actual: 20.5%  ·  Closable Gap: +0.0 pts
```

The values match the variance banner above to one decimal place.
`Closable Gap` equals `Actual − Best Possible` exactly: `20.5 − 20.5
= 0.0`. The middot separator (`·`, U+00B7) is used per Phase 7.58
hard gate #4 (no em dashes in operator-facing copy). On a different
seeded scenario where actual exceeds the floor (e.g. an unfavourable
week where actual = 31.4% against a 24.2% floor), the same triplet
shape renders with a positive gap of `+7.2 pts`; the under-floor
branch renders a negative gap (e.g. `-1.4 pts`).

**Expected (pre-7.58.UX.6):** the footer read `Through Tuesday`.
**Expected (post-7.58.UX.6):** the triplet replaces it.

### Step 4 — Open Week Detail for a frozen prior week

Tap **Variance > History** (or **Previous Weeks** from the home
screen) and select a closed week. `WeekDetailScreen` builds with the
`WeekRecord` persisted at close. The DOLLAR IMPACT card renders the
locked-at-close 4 dollar rows.

**Expected:** the footer reads
`Best Possible: <weekRecord.theoreticalLaborPct>%  ·  Actual: <weekRecord.actualLaborPct>%  ·  Closable Gap: <variance> pts`
using the values frozen at the moment the 14th shift closed.
`closedAt` legacy rows that pre-date the 7.58.UX.6 widget params
still pass non-null `theoreticalLaborPct` (Phase 7.55q migration
backfilled it), so the triplet renders on every history row the
operator can reach.

### Step 5 — Honest fallback (test fixture only)

The honest-fallback path is exercised by widget test, not the demo
seed: `DollarImpactCard(weekImpact: 478, footerText: 'Through Tuesday')`
with both new params omitted renders `Through Tuesday` unchanged and
no triplet copy. This path exists for hypothetical legacy rows
without preserved theoretical labor — never hit on the demo seed.
