## Engineering anchors — backfill 90-day cap

The adapter enforces Clover's documented 90-day filter cap on the
`/v3/merchants/{mId}/orders` `modifiedTime` filter:

- `BackfillCommand.windowStart = now - 60 days` → adapter issues the
  filter as-is. The framework's V1 lean cut 2 first-connect window
  fits inside the cap.
- `BackfillCommand.windowStart = now - 120 days` → adapter clamps to
  `now - 90 days` BEFORE issuing the filter. The framework does NOT
  raise an error; the operator sees the canonical fact rows for the
  most-recent 90 days plus the framework's per-batch watermark
  commits.

Walkthrough cannot exercise this without live HTTP; the fixture
test `CloverPosAdapter — 90-day filter cap clamp (test 8)` is the
graded anchor.

## Engineering anchors — webhook signature

The verifier exercises four anchors per the contract:

- **Forged signature → 403.** Tampered base64 byte sequence flips a
  single character; HMAC-SHA256 mismatch returns
  `WebhookSignatureVerification(valid: false, failureReason:
  'HMAC-SHA256 mismatch')`. The framework `_failed` path records
  the audit row and dead-letters at attempt 3.
- **Malformed payload drop.** A webhook envelope missing `objectId`
  raises a `FormatException` at the adapter boundary. The framework
  catches it in step 5 and records the failure via
  `connector_sync_log` + `inbound_webhook_dead_letter`. No canonical
  fact is written; no `parse_warnings` flag is recorded (V1 lean
  cut 2 deleted that channel).
- **Future-dated drop.** The framework's step-4 timestamp sanity
  guard fires before the adapter sees the webhook; adapter does NOT
  call `sanityHook` on the webhook path. The audit row marks the
  drop with rule `opened_in_future`.
- **OAuth near-expiry refresh.** The `oauth_refresh_cron.dart`
  scans `vendor_credentials` hourly for tokens with
  `token_expires_at < now() + 24h` and refreshes via
  `POST /oauth/v2/token`. After 3 consecutive refresh failures the
  connection flips to status `error` (operator sees the chip in the
  Vendor Connections widget; email enable is deferred to
  `9.8.email`).

## Engineering anchors — disconnect / reconnect

The disconnect → reconnect smoke (test 5) exercises:

1. **Connect** issues `ConnectResult(status: connected, metadata:
   { merchant_id, webhook_subscription_id })`. The adapter stores
   the merchant id on `connector_connection.metadata.merchant_id`
   (key `kCloverMetadataMerchantIdKey`) and the auto-registered
   webhook subscription id on
   `connector_connection.metadata.webhook_subscription_id` (key
   `kCloverMetadataWebhookSubscriptionIdKey`).
2. **Backfill** writes one canonical sales fact, persists the
   per-batch watermark cursor (`cursor_token = base64url({offset:N})`),
   and returns `BackfillResult(completed: true)`.
3. **Poll** issues no new writes (no orders modified since
   `lastModifiedSeen`); returns the unchanged watermark.
4. **Disconnect** wipes credentials, calls
   `DELETE /v3/apps/{aId}/webhooks/{subscriptionId}`, and returns
   `DisconnectResult(credentialsWiped: true,
   webhookUnregistered: true, watermarkPreserved: true)`. Canonical
   facts and `connector_sync_watermark` rows are intentionally NOT
   deleted so reconnect resumes from the last cursor.
5. **Reconnect** rebinds the credential store with a fresh subscription
   id; the next `pollIncremental` resumes from the persisted cursor
   without rewinding `lastModifiedSeen`.
