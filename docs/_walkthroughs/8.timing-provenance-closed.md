Date: 2026-05-06

Status: Proof PASS on Codex integration branch

## Lane 0 Schema Decision

Current `origin/master` does not contain a real
`business_timing_profile_versions` table. It contains
`business_timing_profiles` and `business_timing_service_periods`.

Lane 0 keeps the model additive and does not introduce a second version table.
For this sprint:

- `business_timing_profile_id` stores `business_timing_profiles.profile_id`.
- `business_timing_profile_version_id` also stores
  `business_timing_profiles.profile_id`.
- `service_period_key` stores the stable service-period key captured at
  bucket time.

The field name `business_timing_profile_version_id` is final for downstream
lanes. Future work may add a dedicated version table, but no Lane 1-4 code may
query `business_timing_profile_versions` unless that table is explicitly added
in a later migration and repository contract.

## Migration Authority

Migration:

- `db/migrations/202605061700_phase_8_timing_provenance_shift_records.sql`

Closed rows:

- Adds nullable `business_timing_profile_id`.
- Adds nullable `business_timing_profile_version_id`.
- Adds nullable `service_period_key`.
- Adds composite foreign keys from the timing ids to
  `business_timing_profiles(operator_id, profile_id)`.
- Adds operator-leading indexes for timing provenance lookups.
- Leaves existing closed rows legacy/null.

Live rows:

- Adds nullable `business_timing_profile_version_id` to
  `open_shift_snapshots`.
- Backfills existing open snapshot rows from `business_timing_profile_id`
  because those rows are provisional live read models, not closed history.
- Keeps the existing `business_timing_profile_id` and `service_period_key`
  model.

## Downstream Lane Contract

Lane 1 carries the closed timing triplet through:

- `ClosedShiftInput.businessTimingProfileId`
- `ClosedShiftInput.businessTimingProfileVersionId`
- `ClosedShiftInput.servicePeriodKey`
- `ShiftFact.businessTimingProfileId`
- `ShiftFact.businessTimingProfileVersionId`
- `ShiftFact.servicePeriodKey`
- `ShiftRecord.businessTimingProfileId`
- `ShiftRecord.businessTimingProfileVersionId`
- `ShiftRecord.servicePeriodKey`

Lane 2 renders closed labels from the saved timing identity when present
and fall back to legacy `daypart` when null.

Lane 3 and Lane 4 use the same version decision for live snapshots:
`business_timing_profile_version_id` equals the profile id until a dedicated
version table exists.
