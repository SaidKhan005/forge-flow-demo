# 8.timing-provenance-closed Walkthrough

Date: 2026-05-06

Status: Lane 0 schema decision complete, implementation lanes still pending

## Lane 0 Schema Decision

Current `origin/master` does not contain a real
`business_timing_profile_versions` table. It contains
`business_timing_profiles` and `business_timing_service_periods`.

Lane 0 keeps the model additive and does not introduce a second version table.
For this sprint:

- `business_timing_profile_id` stores `business_timing_profiles.profile_id`.
- `business_timing_profile_version_id` also stores
  `business_timing_profiles.profile_id`.
- `service_period_key` stores the stable service-period key captured at
  bucket time.

The field name `business_timing_profile_version_id` is final for downstream
lanes. Future work may add a dedicated version table, but no Lane 1-4 code may
query `business_timing_profile_versions` unless that table is explicitly added
in a later migration and repository contract.
