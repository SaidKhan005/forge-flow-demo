# 7.58.UX.9 Walkthrough - Cross-axis carousel data-source swap

**Slice:** 7.58.UX.9 (Phase 7.58 - Depth Wave, Wave B; shipped jointly with 7.58.UX.7)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-05

This slice extends the Variance > Learn `Recurring Leak` carousel
so that, when the cross-axis analyzer (shipped in 7.58.cross-axis.0)
detects a recurring CPLH x SPLH pair pattern that is BOTH
(a) at least 3 contributing records strong AND (b) larger than
the dominant single-axis leak count, the carousel swaps its data
source from `LeverCards` to `CrossAxisPairs`. The operator walks
an identical 4-card teaching rhythm; only the input changes. The
single-axis path stays the default whenever the swap predicate is
false (no pair pattern, weak pair, or single-axis leak still
dominates).

The swap surfaces the joint diagnosis that 7.58.cross-axis.0
makes representable: when CPLH ran below target AND SPLH ran
above target on the same shifts, the recurring story is
"forecast was low, team executed", not a single-axis FOH leak.
Previously the operator only saw the dominant single-axis lever
and had to reason about the joint pattern themselves.

## What changed

### `lib/screens/variance/variance_learn_tab.dart`

- New private widget `_CrossAxisSnapshotCard` mirrors the chrome
  of `_LeakSnapshotCard` but reads its `metric` / `shortLabel` /
  `causeCategory` / `sideLabel` / `whatHappened` / `whatToDo` /
  `teachingNote` from a `CrossAxisPairData` plus the matching
  `CrossAxisPairRecord.count` and `topDayparts` from the
  analyzer summary.
- The Recurring Leak carousel resolver in `_LearnContent.build`
  computes `crossAxisCard` BEFORE the existing single-axis
  branching:

```
final CrossAxisPairData? crossAxisCard =
    (summary.crossAxisPairs.isNotEmpty &&
            summary.crossAxisPairs.first.count >= 3 &&
            summary.crossAxisPairs.first.count > summary.primaryLeakCount)
        ? CrossAxisPairs.lookup(summary.crossAxisPairs.first.pairId)
        : null;
```

  When `crossAxisCard != null`, the carousel renders 4 cards
  (snapshot + `WHAT HAPPENED` + `WHAT TO DO` + `WHAT TO STUDY`)
  whose body copy reads from the swapped pair source. When it is
  null, the existing single-axis path runs unchanged: leak card
  -> 4 single-axis cards, or no recurring leak -> the existing
  `NO PATTERNS YET` branch.
- The badge label on the cross-axis snapshot reads `CROSS AXIS
  LEAK` (the single-axis snapshot still reads `LEAK`). The
  metric-row label reads `PAIR REPEATS` instead of `LEAK
  REPEATS`. Same chrome, distinct labels so the operator can tell
  at a glance whether they are looking at a single-axis or joint
  pattern.

### `test/screens/variance/variance_learn_tab_depth_test.dart`

NEW. Pins the swap predicate and the carousel structure under
both branches. The cross-axis fixture provides 3 weeks of
`(W*, lunch)` buckets each containing one `cplh_down` (leak) +
one `splh_up` (benchmark) record. After the analyzer runs:
`crossAxisPairs.first.pairId == 'cplh_below_splh_above'`,
`count == 6`, `primaryLeakCount == 3`. Both swap conditions
hold (`6 >= 3` AND `6 > 3`), so the carousel renders the
cross-axis copy. The single-axis fixture (recurring `covers_down`
without any SPLH lever in the same bucket) yields
`crossAxisPairs.isEmpty == true`, the predicate is false, and
the carousel renders the single-axis copy.

## Demo seed shape (relevant for this walkthrough)

`MockReplayDataSeed` boots the operator app against
`DemoData.historicalClosedShifts` (116 closed rows) +
`DemoData.weekHistory`. After
`HistoryPatternBuilder.fromClosedShifts` reduces the closed
shifts and `HistoryTeachingAnalyzer.summarize` reduces the
patterns, the demo seed produces:

- `summary.primaryLeakId` = `cplh_down`
- `summary.primaryLeakCount` = 18
- `summary.crossAxisPairs.length` = 1
- `summary.crossAxisPairs.first.pairId` =
  `cplh_above_splh_below` (the `TEAM RAN LEAN. KITCHEN SLOWED.`
  cell)
- `summary.crossAxisPairs.first.count` = 7

The swap predicate evaluates to **false** on the demo seed:
`7 >= 3` is true, but `7 > 18` is false. The recurring single-axis
`cplh_down` leak still dominates the closed-shift history, so the
carousel renders the SINGLE-AXIS path (see
`docs/_walkthroughs/7.58.UX.7.md` for that click-path). This is
correct behavior: the swap is opt-in by strength, not blind. The
operator does not see joint-diagnosis copy when the single-axis
leak is the dominant recurring pattern.

The cross-axis carousel branch is exercised through the widget
test fixture below, which crafts a closed-shift history where
the joint pattern dominates the single-axis leak.

## Click path (text trace)

### Step 1 - Demo seed: confirm the single-axis path is the default

Launch the operator app with `kDemoMode=true`. Tap Variance ->
Learn. The Recurring Leak chapter renders the snapshot card with
the `LEAK` badge and the title:

```
CPLH BELOW TARGET · Repeated 18 of last 116 Thu Dinners
```

The cross-axis swap predicate did NOT fire (count 7 is below
the dominant single-axis leak count 18). No
`CROSS AXIS LEAK` badge is rendered.

**Expected:** the demo seed exercises the single-axis path
(per `docs/_walkthroughs/7.58.UX.7.md`); the cross-axis snapshot
text never appears in this scenario.

### Step 2 - Widget-test fixture: cross-axis swap fires

The widget test
`test/screens/variance/variance_learn_tab_depth_test.dart`
constructs a fake `ShiftDataSource` with the canonical
cross-axis fixture:

```
W1 Tue Lunch -> cplh_down + splh_up (benchmark)
W2 Tue Lunch -> cplh_down + splh_up (benchmark)
W3 Tue Lunch -> cplh_down + splh_up (benchmark)
```

The analyzer reduces this to:

- `summary.crossAxisPairs.first.pairId == 'cplh_below_splh_above'`
- `summary.crossAxisPairs.first.count == 6`
- `summary.primaryLeakCount == 3` (recurring `cplh_down`
  across 3 weeks)
- swap predicate: `6 >= 3 AND 6 > 3` = **true**

The carousel renders the cross-axis 4-card walk.

### Step 3 - Read the cross-axis snapshot card

The first card in the carousel is the
`_CrossAxisSnapshotCard`. Its title reads:

```
FORECAST WAS LOW. TEAM EXECUTED.
```

(per `CrossAxisPairs.cplhBelowSplhAbove.metric`). The badge is
`CROSS AXIS LEAK` (vs the single-axis `LEAK`). The identity
chips render `pairCard.shortLabel` (`FORECAST`),
`pairCard.causeCategory` (`FORECAST`), and `pairCard.sideLabel`
(`BOTH SIDES`). The metric row reads `PAIR REPEATS` with
`pairRecord.count` and `REPEATS IN` with the joined
`pairRecord.topDayparts`.

**Expected (pre-7.58.UX.9):** when the cross-axis pair was the
stronger recurring pattern, the snapshot still surfaced the
dominant single-axis lever; the joint diagnosis was invisible.
**Expected (post-7.58.UX.9):** the snapshot reads the joint
diagnosis whenever the swap predicate fires.

### Step 4 - Read the three teaching cards

Card 1 (`WHAT HAPPENED`) renders
`crossAxisCard.whatHappened`: "CPLH ran below target. SPLH ran
above target. Fewer covers came in than the schedule was built
for, but every guest who walked in spent generously..." (the
canonical Jim Taylor Ch. 7 framing for that cell).

Card 2 (`WHAT TO DO`) renders `crossAxisCard.whatToDo`: "Adjust
the cover forecast for next week before you build the FOH

Card 3 (`WHAT TO STUDY`) renders `crossAxisCard.teachingNote`:
"Jim Taylor Ch. 7: CPLH below + SPLH above is a volume problem,
not an execution problem..."

**Expected:** the operator walks an identical 4-card rhythm to
the single-axis case; only the body copy comes from the
cross-axis catalog.
