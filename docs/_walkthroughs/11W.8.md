## Upstream blockers (read first)

11W.8 depends on two Phase 8.0 upstream pieces that did not land
before this lane started. Both ship the operator-facing chrome that
the surface doc promises; neither is mutable from this lane (the
"Files to leave alone" rule forbids editing
`lib/integrations/ui/vendor_connections/*`). The walkthrough below
describes the **shipped** surface; the **future-state** surface
the surface doc anchors lights up incrementally as each upstream
piece lands.

1. **`VendorConnectionsWidget` does not yet expose an
   `onNotifyMeRequested` callback prop, and the picker has no
   per-row Notify-me CTA.** The shared widget under
   `lib/integrations/ui/vendor_connections/vendor_connections_widget.dart`
   ships a single `_VendorPickerDialog` dropdown whose Continue
   button activates for any picked vendor regardless of lifecycle.
   The surface doc
   (`docs/phases/phase_8/vendor_connections_admin_surface.md`)
   shows per-row chrome with a **Notify me** CTA on `documented` /
   `sandbox_verified` rows, but that chrome is not implemented in
   the widget yet. **What 11W.8 ships:** the standalone
   `VendorLifecycleNotifyMeDialog` widget — fully tested, ready to
   open via `showVendorLifecycleNotifyMeDialog(...)`. **What is
   blocked:** wiring the dialog onto vendor rows inside the picker.
   When the upstream API lands, swap the dialog open call into the
   widget's row-level Notify-me callback handler.
2. **`VendorLifecycleNotificationRepository` is not yet
   implemented.** Phase 8.0.lifecycle shipped the migration
   (`db/migrations/202605040400_phase_8_0_lifecycle_add_vendor_lifecycle_notification.sql`)
   + the `VendorLifecycle` enum on `VendorCapabilityProfile`, but
   not a repository class against the new
   `vendor_lifecycle_notification` table. **What 11W.8 ships:** an
   abstract `VendorLifecycleNotificationRepository` seam declared
   inside
   `lib/operator_web/widgets/vendor_lifecycle_notify_me_dialog.dart`,
   so the dialog can compile + test against an injected fake.
   **What is blocked:** the production class. When the production
   class lands, swap the import to point at it and delete the
   abstract class in the dialog file.
3. **`InMemoryVendorConnectionsGateway` seeds only 3 reference
   stubs** (Lightspeed K-Series, Libro, QuickBooks Time). The
   walkthrough below is written against this 3-stub seed; once the
   gateway is expanded to the full 17-vendor catalog (Wave B
   capability profile lifting), the picker will render all 17 rows
   per the engineer-all-17 doctrine.

The 11W.8 implementation lands every other piece of the operator
mount: screen, permission gate, router rewire, placeholder
deletion, dialog UI, tests, walkthrough.

## Click-path — what 11W.8 ships today

### 1. Land on `/account`

- **Action:** Sign in via the welcome → password → MFA → T&Cs
  click path with the demo magic-link token. The router emits
  `OperatorWebCompleted` and lands the operator on
  `/account` (the post-onboarding default).
- **Expected:** `Key('operator_web_shell_scaffold')` visible;
  side nav shows **Account** (active) and **Vendor connections**.
  Body is the `Key('operator_web_account_placeholder')` (lane
  `11W.7` replaces it).

### 2. Open the Vendor connections route

- **Action:** Click side nav **Vendor connections**
  (`Key('operator_web_nav_item_vendor_connections')`).
- **Expected:** Body switches to
  `Key('operator_web_vendor_connections_screen')`.
  Title **"Vendor connections"** visible
  (`AppTextStyles.display20`); subtitle
  `Key('operator_web_vendor_connections_subtitle')` reads
  **"Configuring connections for Brio - Chicago Loop (primary
  location)."**.

### 3. Vendor connections widget renders

- **Action:** Wait for the in-memory gateway to resolve (one
  frame).
- **Expected:** The widget host
  `Key('operator_web_vendor_connections_widget_host')` renders
  three category sections:
  - `Key('vendor_connections_section_pos')` — POS empty state
    "Connect your Point-of-sale (POS) system" + "Choose your POS"
    button.
  - `Key('vendor_connections_section_reservation')` — Reservations
    empty state + "Choose your reservations vendor" button.
  - `Key('vendor_connections_section_labor')` — "Scheduling and
    labor" empty state + "Choose your scheduling vendor" button.
- Each empty state carries the "Demo" pill
  (`Key('vendor_connections_demo_chip_pos')` etc.) — demo flag
  comes from the in-memory gateway's `demoFlags` map.

### 4. Open the POS picker

- **Action:** Tap **Choose your POS**
  (`Key('vendor_connections_connect_pos')`).
- **Expected:** `Key('vendor_connections_picker_dialog')` opens.
  Dropdown `Key('vendor_connections_picker_dropdown')` renders
  one row: **Lightspeed Restaurant K-Series**
  (lifecycle = `productionCredentialed` per the in-memory gateway
  seed). Continue button
  `Key('vendor_connections_picker_continue')` is disabled until
  a vendor is picked.
- **Future-state anchor (out of scope for 11W.8):** when the
  in-memory gateway is expanded to the full 17-vendor catalog,
  this dropdown will list all 7 POS vendors per
  `docs/phases/phase_8/vendor_connections_admin_surface.md`
  with "coming soon" labels on rows where
  `lifecycle = documented` / `sandbox_verified`. The picker UI
  copy already routes lifecycle through the `_labelFor` switch
  in `vendor_connections_widget.dart`.

### 5. Cancel the picker

- **Action:** Tap `Key('vendor_connections_picker_cancel')`.
- **Expected:** Dialog closes; widget returns to the empty-state
  view.

### 6. Permission gate negative path — `location_manager`

- **Action:** Sign out, sign back in with a `location_manager`
  session (real flow uses the magic-link token issued for that
  role; widget tests pass the role list directly). Tap side nav
  **Vendor connections**.
- **Expected:** Body switches to
  `Key('operator_web_vendor_connections_forbidden')`.
  Friendly copy `Key('operator_web_vendor_connections_forbidden_body')`
  reads:
  > Vendor connections are managed by your operator admin or
  > owner; ask them to set up integrations for this location.
- A secondary callout "Why you are seeing this" explains in plain
  English why the gate exists. No picker is rendered. No widget is
  mounted.

### 7. Notify-me dialog (standalone — invoked from the test
harness today)

- **Action:** From the widget test harness, call
  `showVendorLifecycleNotifyMeDialog(...)` with
  `vendorId: 'toast', vendorDisplayName: 'Toast',
  lifecycle: VendorLifecycle.documented,
  defaultEmail: 'alex@brio-restaurants.com'`.
- **Expected:** `Key('vendor_lifecycle_notify_me_dialog')` opens
  with title **"We'll email you the moment Toast goes live for
  connecting."**. Subline:
  > We've built the integration with Toast but we're still in the
  > partnership process with them. As soon as they issue us
  > production credentials, the Connect button activates and we'll
  > email you.
- Email field `Key('vendor_lifecycle_notify_me_email_field')`
  pre-filled with `alex@brio-restaurants.com`. Helper text:
  "Pre-filled from your sign-in. Edit if a different teammate
  should get this email." Buttons:
  `Key('vendor_lifecycle_notify_me_cancel')` and
  `Key('vendor_lifecycle_notify_me_submit')` ("Notify me").

### 8. Notify-me submit happy path

- **Action:** Tap `Key('vendor_lifecycle_notify_me_submit')`.
- **Expected:** Dialog dispatches
  `repository.insertNotification(operatorId: 'brio-operator',
  vendorId: 'toast', email: 'alex@brio-restaurants.com')`.
  Production target table:
  `vendor_lifecycle_notification(operator_id, vendor_id, email,
  requested_at)`. Dialog closes; awaited `Future` resolves to
  `VendorLifecycleNotifyMeResult(email: '...', outcome:
  inserted)`.

### 9. Notify-me duplicate submit

- **Action:** Re-open the dialog with the same vendor + email and
  tap **Notify me** a second time.
- **Expected:** Repository's UNIQUE
  `(operator_id, vendor_id, email)` constraint blocks the
  duplicate insert; the contract surfaces the no-op as
  `VendorLifecycleNotificationOutcome.alreadySubscribed`. The
  dialog closes; the awaited result carries
  `outcome: alreadySubscribed`. Caller is expected to display
  "We'll email you when this is ready" without inserting twice.

### 10. Notify-me cancel

- **Action:** Re-open the dialog and tap
  `Key('vendor_lifecycle_notify_me_cancel')`.
- **Expected:** Dialog closes with `null` result; repository is
  not called. No row inserted.

### 11. Notify-me invalid email

- **Action:** Open the dialog with a default email like
  `invalid-no-at-sign`. Tap **Notify me**.
- **Expected:** Inline error under the email field reads:
  > Type a valid email address. We use this to email you the
  > moment Toast is ready to connect.
- Repository is not called.

### 12. Responsive resize — tablet 768×1024

- **Action:** Resize the viewport to 768×1024. Re-render the
  Vendor connections route under an `operator_admin` session.
- **Expected:** `Key('operator_web_vendor_connections_screen')`
  remains visible; no overflow exceptions; vertical scrolling
  available via the `SingleChildScrollView` wrapper. The shared
  widget's category cards stack as before.

### 13. Responsive resize — desktop 1024×768

- **Action:** Resize the viewport to 1024×768.
- **Expected:** Same as 1280×800 layout; no overflow exceptions.

## Future-state click-path — once the upstream API lands

When `VendorConnectionsWidget` exposes
`onNotifyMeRequested(vendorId, vendorDisplayName, lifecycle)` and
the in-memory gateway seeds all 17 vendors, the picker dialog
renders 17 rows per the surface doc:

- POS rows: Lightspeed Restaurant K-Series, Toast, Square, Clover,
  Revel, Aloha (NCR Voyix), Oracle MICROS Simphony.
- Reservation rows: Libro, OpenTable, SevenRooms, Tock.
- Scheduling rows: 7shifts, QuickBooks Time, ADP Workforce Now,
  Humanity, Agendrix, Push Operations.

Each row hosts:

- **Connect button** when `lifecycle = production_credentialed`
  or `live_with_operators`.
- **"Coming soon" pill + Notify me CTA** when
  `lifecycle = documented` / `sandbox_verified`.

Tapping **Notify me** invokes `onNotifyMeRequested(...)` on the
widget. The 11W.8 mount wires that callback to
`showVendorLifecycleNotifyMeDialog(...)` with the existing
in-screen repository. After submit, the widget row chrome flips
to **"We'll email <email> when <vendor> is ready"** + a
`[Cancel]` button. Cancel calls
`repository.cancelNotification(...)`. The
`vendor_now_available` email fan-out lands in the `9.8.email`
follow-up; this lane is responsible only for the row insert /
delete.

When a vendor's `*.live.prod` slice promotes lifecycle to
`production_credentialed`, that vendor's row in the picker drops
the "Coming soon" pill and renders the Connect button live. The
walkthrough names this future state without exercising it
(`*.live.prod` slices fire individually in Wave D).
