## What the slice ships

### Pure evaluator

- `lib/services/realtime/outbox_tripwire_evaluator.dart`
  `evaluateOutboxTripwires(OutboxTripwireInputs inputs)` returns
  `OutboxTripwireResult { status, breaches }`. Worst-wins severity
  across the four Q22 metrics; null inputs collapse to green for
  that metric (a stuck-at-unknown producer never on its own trips
  the bridge into degraded state). Q22 thresholds live as constants
  in `kOutboxTripwireDefaultThresholds`; per-metric overrides live
  on `OutboxTripwireInputs.thresholdOverrides` so the demo path
  below can force a metric into red without touching the locked
  numbers. File stays free of `dart:io` / `sqflite` so the badge can
  reach the same evaluator from `lib/main_operator_web.dart`.

### Proxy route

- `tool/advisor_proxy/advisor_proxy.dart` — new
  `realtimeTripwireStatusPath = '/v1/realtime/tripwire-status'`,
  `RealtimeTripwireProxyGateway` interface, and a route handler that
  delegates to the gateway. Read-only GET; returns 503 when the
  gateway is not wired.
- `tool/advisor_proxy/realtime_tripwire_gateway.dart`
  `PostgresRealtimeTripwireGateway` runs the four Q22 metrics through
  the admin pool's `runAsSystem` (platform-wide aggregate, no
  per-tenant filter, no tenant identifiers in the response payload)
  and packs them into the evaluator. Env-var override resolver
  (`resolveTripwireThresholdOverrides(...)`) reads
  `EVENT_OUTBOX_BRIDGE_LAG_*`, `EVENT_OUTBOX_UNDELIVERED_*`,
  `EVENT_OUTBOX_PUBLISH_ERROR_*`, `PG_NOTIFICATION_QUEUE_USAGE_*`
  envelopes and folds them into the evaluator inputs; missing /
  blank / non-positive values fall back to the locked Q22 numbers.
- `tool/advisor_proxy/main.dart` — production wiring constructs the
  Postgres-backed gateway and threads it into `routeRequest` next to
  the existing `realtimePublisher` binding.

### Health-producer alignment

- `tool/advisor_proxy/health_producers/outbox_producers.dart` — new
  `eventOutboxBridgeLagSecondsProducer` registered as
  `event_outbox_bridge_lag_seconds`. Same Q22 thresholds (60s / 300s)
  as the existing `event_outbox_lag_seconds`; the SQL semantic
  differs (`max(picked_up_at)` over undelivered rows here vs the
  existing `min(created_at)`) so the two metrics catch different
  stalls — bridge-side post-pickup vs producer-side oldest-row
  staleness. The other three Q22 metrics already had matching
  thresholds wired in 10a.0 / 10a.2 and stay untouched.
- `tool/advisor_proxy/advisor_proxy.dart` — reserved-metric
  placeholder added for the new metric, plus the surface entry in
  `proxyHealthReservedSurfaces['event_outbox']`.

### Admin observability surface

- `lib/admin/services/realtime_tripwire_admin_gateway.dart` — new
  `RealtimeTripwireAdminGateway` interface with HTTP +
  in-memory implementations. Parses the proxy envelope into a typed
  `RealtimeTripwireSnapshot` so the screen does not redo JSON walking.
- `lib/admin/screens/observability_admin_screen.dart` — extends the
  screen with an optional `tripwireGateway` constructor parameter and
  a new "Realtime bridge tripwires" section above the existing tabs.
  The section renders one row per Q22 metric (label, current value,
  yellow/red thresholds, status pill) plus a worst-wins header pill.
  When the gateway returns an error the section renders an inline
  message; the rest of the screen still works. NO new permission
  keys — the screen still gates on the existing
  `kFfObservabilityAdminReadRoles` set.

### Sync-badge degraded branch

- `lib/widgets/sync_state_badge.dart` — new
  `RealtimeTripwireScope` (sibling of the existing
  `RealtimeConnectionScope`) exposes a
  `Stream<OutboxTripwireStatus>?` to descendant widgets. When the
  scope reports `red` AND the WebSocket connection is `connected`,
  the pill shifts to amber "Degraded" with the tooltip "Realtime
  bridge is dropping events." Yellow tripwires DO NOT shift the
  badge (yellow is "trending bad", red is "events being dropped").
  Connecting / reconnecting still wins over a red tripwire because
  the connection-state pill is the more urgent signal mid-handshake.
  File stays free of `dart:io` / `sqflite` so the badge stays
  reachable from `lib/main_operator_web.dart`.

- `lib/services/realtime/outbox_tripwire_poller.dart` —
  `OutboxTripwirePoller` drives the scope's stream. Takes a
  `OutboxTripwireFetcher` closure (production binds it to a GET
  against `/v1/realtime/tripwire-status`; widget tests / demo
  walkthroughs bypass the poller and drive the scope directly from
  a `StreamController`). Default interval is the
  `kOutboxTripwirePollInterval` constant (60s, per the slice
  contract). `start()` fires an immediate fetch + schedules the
  next at the interval; `dispose()` cancels the timer and closes
  the stream. Fetcher exceptions are swallowed (an `onError`
  callback surfaces them for log triage) so a broken proxy does
  not crash the badge mid-render. Web-compat — no `dart:io`.

### Tests

- `test/services/realtime/outbox_tripwire_evaluator_test.dart` — green

- `test/admin/observability_admin_screen_test.dart` — extended with

- `test/widget/sync_state_badge_test.dart` — extended with three new

- `test/proxy/advisor_proxy_health_envelope_test.dart` — producer

## Click-path

The walkthrough is exercised against the F&F admin shell with the
proxy running locally pointed at a staging Postgres + a feeder
script that writes rows into `event_outbox` without delivering them.

**Step 1 — open admin observability, all green.** Sign in as
`super_admin`, open the Observability admin screen, click "Run
metrics check", confirm the dialog. Section header pill shows
"Green". Each of the four Q22 rows shows a green pill, current value
under threshold, and the threshold copy ("Yellow at 60 s, red at
300 s" etc.).

**Step 2 — seed an undelivered row that fails to publish.** Mirror
`docs/_walkthroughs/10a.2.md` step 1: connect to the staging
Postgres as `forge_admin`, insert one row into `public.event_outbox`
with a payload the bridge will reject (e.g. a `topic` outside the
locked namespace list). The bridge's claim loop picks it up,
publish fails, the row goes back into the unclaimed pool, and
`picked_up_at` floats forward each retry.

**Step 3 — wait ~60s, bridge_lag breaches yellow.** Re-run the
metrics check on the admin screen. The bridge_lag row now shows a
yellow pill and a value above 60. The section header pill is
"Yellow" because yellow is the worst severity across the four
metrics. The producer envelope at GET `/health` confirms the same
state: `metrics.event_outbox_bridge_lag_seconds.status == 'yellow'`.

**Step 4 — admin observability shows yellow on bridge_lag.** No
operator-facing UX changes at this severity — yellow is "trending
bad", not "events being dropped". The sync badge in the operator
shell stays "Live" because yellow is below the degraded-shift
threshold.

**Step 5 — force red via env-var threshold override; sync badge
shifts to "Degraded".** Stop the proxy, re-launch with
`EVENT_OUTBOX_BRIDGE_LAG_RED_SECONDS=10` (and matching
`EVENT_OUTBOX_BRIDGE_LAG_YELLOW_SECONDS=5` to keep the ladder
sensible). The next metrics check on the admin screen shows the
bridge_lag row red and the section header pill red. Curl `GET
/v1/realtime/tripwire-status`; the JSON returns `status: "red"`. The
operator sync badge — which the production app polls every ~60s —
shifts from green "Live" to amber "Degraded" with the tooltip
"Realtime bridge is dropping events." Roll the env vars back to
defaults to clear the demo state.

## Hard Promise this slice realizes

> Every backend phase ships its operator-facing UX before phase
> close.

The bridge tripwires belong on the F&F admin surface (engineers
diagnose), but the operator-facing degraded-state branch on the
sync badge keeps the operator informed when events are being
dropped under their feet — the badge is the same widget Phase
10a.UX.0 wired into the app shell. Both UX exposures land in this
slice.

## Q22 thresholds touched: zero

The four Q22 numbers (60s / 300s lag, 10 000 / 100 000 undelivered,
0.01 / 0.05 publish error rate, 0.10 / 0.25 NOTIFY queue usage)
appear in the evaluator as `kOutboxTripwireDefaultThresholds`
constants and in the producer envelopes' threshold metadata. The
slice does NOT modify them — env-var overrides on top of the
locked defaults exist only so the demo step above can force red
without modifying production data.

## Bridge worker untouched

`tool/advisor_proxy/realtime_bridge.dart` is byte-identical
pre / post slice. NOTIFY stays a wake-up-only signal. `flutter
test test/realtime_bridge_test.dart` runs green as a regression
gate.
