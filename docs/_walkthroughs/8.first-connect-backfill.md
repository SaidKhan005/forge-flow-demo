## Steps

1. Run the harness:

   ```powershell
   flutter test tool\first_connection_backfill_harness\main.dart
   ```

   Expected result: Flutter test exits 0 and prints a JSON summary with
   `"status": "pass"`.

2. Confirm connect enqueue:

   Expected result: summary shows `"connect_jobs_enqueued": 1`. The fixture
   asserts the job window is exactly the bounded 60-day first-backfill window.

3. Confirm zero-row backfill behavior:

   Expected result: the fixture dispatches a zero-row first backfill and demo
   mode does not flip.

4. Confirm POS, labor, and reservation backfill dispatch:

   Expected result: summary shows `"dispatched_jobs": 3` and
   `"canonical_facts_written": 5`.

5. Confirm demo flip policy:

   Expected result: summary shows `"demo_flips": 3`, only after committed
   non-zero first-backfill rows.

6. Confirm closed row projection:

   Expected result: completed canonical period projects one closed row through
   the closed post-commit aggregator/writer seam.

7. Confirm mobile-visible history:

   Expected result: summary shows `"closed_rows_mobile_visible": 1`. The row is
   read through the existing mobile cache shape, not through direct mobile
   Postgres access.

8. Confirm current/open projection:

   Expected result: summary shows `"open_snapshots_projected": 1`, proving the
   open/current period invokes the open snapshot projector seam.
