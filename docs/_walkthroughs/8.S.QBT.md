# 8.S.QBT Walkthrough — QuickBooks Time labor adapter (poll-only, lifecycle = `documented`)

**Slice:** 8.S.QBT (Phase 8.S / Wave B — engineer-all-17 push, reference scheduling adapter)
**Mode:** `kDemoMode = true` (operator app, deterministic seed). No live HTTP — engineering slice.
**Date:** 2026-05-04
**Demo start condition:**
- Business date `2026-W18 Mon` (Monday of ISO week 18, 2026).
- Operator: "Demo Diner Co.", Location: "Toronto Yorkville".
- Shift dashboard scope: whole-day.
- All vendor connections empty. `demo_mode_state.is_demo = true` for `pos`, `labor`, `reservation`.

This walkthrough is a numbered click-path per the
`docs/CODEX_PROMPT_GENERATION_STANDARD.md` Walkthrough Specificity
section. The slice ships at lifecycle = `documented` — the picker
shows QuickBooks under a module sub-dialog because
`VendorCapabilityProfile.modules = ['time']` and the vendor brand
spans Time / Accounting / Payroll. Live HTTP is the responsibility of
`8.S.QBT.live.sandbox` and `8.S.QBT.live.prod`. The engineering
anchors below verify that the adapter framework calls (sanity hook,
idempotency, watermark, OAuth refresh, disconnect/reconnect, module
disambiguation) all satisfy the Vendor Adapter Slice Contract on the
documented path. The poll-only nature replaces the forged-signature
anchor with an explicit "webhooks N/A — pollOnly" acknowledgement.

### 5. Engineering anchor — backfill watermark per batch + sanity-hook reject

- Engineering slice anchor verified by the test file group
  `Sanity hook contract (Tests 1, 2, 3)`.
- Adapter runs a 60-day backfill against a fake transport returning
  two pages: page 1 has 3 punches (`902001`, `902002`, `902003`),
  page 2 has 2 punches (`902004`, `902005`).
- Expected outcome:
  - `command.sanityHook` is called once per record (5 calls);
    `vendorEventId` arguments are `'902001'`, `'902002'`, `'902003'`,
    `'902004'`, `'902005'` in order.
  - All 5 records pass sanity (`alwaysOk` returns true) and are
    upserted via `QuickBooksTimeGateway.writePunchFact`.
  - `BackfillResult.recordsWritten == 5`;
    `BackfillResult.batchesCommitted == 2`.
  - **Expected watermark advance(s):** one `writeWatermark` call
    per page; the persisted `cursor_token` matches the page's
    `nextPage` (serialized to string `'2'` after page 1, `''` after
    page 2 ends the chain).

### 6. Engineering anchor — polling tick reads watermark and resumes

- Engineering slice anchor verified by the same test file group.
- After the smoke-test backfill, `pollIncremental` is invoked with
  `lastModifiedSeen` set to the backfill's persisted value.
- The fake transport returns one empty page on the next tick. The
  adapter:
  - Calls `command.sanityHook` zero times (no records).
  - Skips `writePunchFact`.
  - Calls `writeWatermark` once with `cursorToken = ''` and the
    unchanged `lastModifiedSeen`.
- Expected `PollIncrementalResult.recordsWritten == 0`,
  `sanityDropped == 0`.

### 7. Engineering anchor — idempotency (same payload twice → 1 write)

- Engineering slice anchor verified by the test file group

  the second call returns `false` (no-op).
- **Expected gateway state:** `canonicalFacts.length == 5` after

### 8. Engineering anchor — mid-batch crash resume from cursor

- Engineering slice anchor verified by the test file group
  `Sanity hook contract (Tests 1, 2, 3)`'s `Test 3` case.
- The fake transport throws on page 2 (`crashAfterPageIndex = 0`).
  Page 1 delivers 3 records; page 2 throws.
- Expected behavior:
  - One `writeWatermark` call lands before the throw with
    `cursor_token: '2'` and `last_modified_seen:
    2026-05-01T20:05:00Z`.
  - On resume (next worker invocation), the adapter is constructed
    again with `BackfillCommand.resumeFromCursor = '2'`. The fake's
    `requestedPages` shows the adapter requests page 2 first —
    verified by `transport.requestedPages.contains(2)`.
  - No record is double-written because the canonical UNIQUE
    collapses any retry of page 1 (idempotency holds).

### 9. Engineering anchor — handleWebhook throws (poll-only)

- Engineering slice anchor verified by the test file group
  `handleWebhook (Test 4)`.
- Calling `adapter.handleWebhook(...)` with any payload throws
  `UnsupportedError('QuickBooks Time does not support webhooks; pollOnly')`.
- The framework's `InboundWebhookHandler.dispatch` consults
  `capabilityProfile.webhookSupport` BEFORE dispatch and never
  delivers a webhook to a poll-only adapter; the throw is the
  defense-in-depth signal that catches a future router refactor that
  forgets the gate.
- **Webhooks N/A — pollOnly path; signature reject test skipped.**
  See `webhook_signature.md` (single line N/A) and
  `live_verification_checklist.md` row "Webhook signature
  verification" (checked off ✅ N/A in advance).

### 10. Engineering anchor — OAuth near-expiry refresh via cron

- Engineering slice anchor verified by the existing
  `test/integration/oauth_refresh_cron_test.dart` (framework slice
  8.0; the adapter does not need its own copy — the cron refreshes
  every Wave B vendor's `vendor_credentials` via
  `oauth_refresh_cron.dart`).
- Time-travel the test clock so `vendor_credentials.token_expires_at
  = now() + 30 minutes` for the QuickBooks Time connection.
- The cron job runs `refresh_expiring_inbound_vendor_tokens()` and
  re-mints the access token via
  `POST https://oauth.platform.intuit.com/oauth2/v1/tokens/bearer`
  with `grant_type=refresh_token`.
- Expected outcome:
  - `connector_sync_log` row: `event_kind = 'auth_refresh'`.
  - `vendor_credentials.consecutive_refresh_failures = 0`.
  - Connection stays `connected`.
  - **No advisory lock** (lean cut 2 trim).
  - **No email_outbox row at V1** (deferred to `9.8.email`).
- On three consecutive failures, `connector_connection.status` flips
  to `error`; admin widget surfaces the operator-facing copy "Please
  reconnect QuickBooks Time and sign back in."

### 11. Engineering anchor — disconnect → reconnect watermark preservation

- Engineering slice anchor verified by the connect/disconnect smoke
  test group.
- `adapter.disconnect(...)` returns
  `DisconnectResult(credentialsWiped: true, webhookUnregistered: true,
  watermarkPreserved: true)`.
  - `webhookUnregistered: true` is vacuously true for poll-only
    QuickBooks Time (no webhook subscription was ever registered);
    the field stays `true` to keep the framework disconnect contract
    uniform across vendors.
- After disconnect, the watermark row in
  `connector_sync_watermark` for `(operator, location,
  quickbooks_time)` is preserved (not deleted). On reconnect, the
  next `pollIncremental` is invoked with `lastModifiedSeen` set to
  the persisted watermark; the fake empty-page response confirms
  no record is double-written or skipped.

  - Increments `PollIncrementalResult.sanityDropped`.

### 16. Adversarial — webhook delivery attempt (poll-only)

- A bad actor (or vendor misconfiguration) sends a forged HTTP
  request to
  `/v1/webhooks/quickbooks_time/<operator_id>/<location_id>`.
- The proxy resolves `vendorId = 'quickbooks_time'` and consults the
  registered adapter map. **Forged-signature step replaced by:** the
  framework router reads
  `adapter.capabilityProfile.webhookSupport == VendorWebhookSupport.pollOnly`
  and returns `404` with `WebhookOutcome.vendorNotFound`-equivalent
  semantics — the adapter never receives the request, and
  `handleWebhook` is not invoked. No canonical fact is written.
- This anchor replaces the per-vendor signature-reject test for
  signing vendors. See `webhook_signature.md` (N/A line) and the
  `handleWebhook` test that asserts the throw as defense-in-depth.
