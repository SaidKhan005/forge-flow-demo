# B44 Walkthrough — Graph metrics producer wiring

**Slice:** Phase 9 / 11A.B42 — graph health producer family for the proxy
`/health` envelope.
**Mode:** Backend-only producer family. No UI surface of its own; the
operator-facing consumer is `11A.UX.health` (already shipped) which renders
the AGE Graph traversal section against this envelope. Verification runs in
`flutter test` against the in-process `FakeProxyHealthQueryRunner`.
**Date:** 2026-05-02 (closeout — code landed in commit `e5d8f3f` as part of
the 57-slot deep-health envelope expansion; this walkthrough closes the docs
gap and unblocks 11A.5 from the B44 side).

This walkthrough closes Hard Promise #10 for the B44 producer wiring: the
operator-facing surface (`11A.UX.health` / Health admin screen) was already
shipped in F.1, but the back-of-the-envelope producer that fills its
`AGE Graph traversal` section needed an explicit walkthrough so future
sprints can audit the seam end-to-end without grepping commit history.

The producer family is a pure consumer of the canonical graph tables; it
performs **no mutations** on AGE or any operator-scoped table. Every signal
runs read-only inside a 250 ms producer budget, projects to `status: unknown`
on timeout/error, and never returns operator/location/tenant identifiers
(per the proxy `/health` tenant-identifier invariant).

## Click path (text trace — verification, not UI)

### Step 1 — Boot the proxy with the registry-backed health store

`proxy_bootstrap.dart` constructs the `RegistryProxyHealthCheckStore` with
`producers: buildProxyHealthRegistryProducers()`. The registry pulls
`graphProducers` from `producer_registry.dart` and adapts each function
producer to the registry's runner-based context.

**Expected:** `proxyHealthRegisteredProducerCount()` returns 57 (the
B42 contract pin); the catalog test
`test/proxy/registry_proxy_health_check_store_test.dart` confirms every
graph key is present.

### Step 2 — Call `GET /health` with healthy fixtures

With the canonical graph tables populated and a recent benchmark run
landed (`graph_benchmark_runs.p95_ms = 92`,
`graph_health_metrics.active_edge_count = 4218`, etc.):

```
$ curl -s https://<proxy-host>/health | jq '.metrics | with_entries(select(.key | startswith("graph_")))'
```

**Expected:** nine `graph_*` entries, each with `owner: "B44"`,
`metadata.tier: 2`, `observed_at` populated, `value` populated, `status`
green/yellow/red per the thresholds above. The
`surfaces.graph` block resolves to `status: green` because every populated
metric is green.

### Step 3 — Edge-count yellow band (Decision 30)

Force `graph_health_metrics.active_edge_count = 3500000`:

**Expected:** `metrics.graph_edge_count.status = "yellow"`,
`metrics.graph_edge_count.value = 3500000`,
`metrics.graph_edge_count.thresholds = {"yellow": 3000000, "red": 4000000}`.
The whole-envelope `severity` flips to `yellow` and `status` flips to
`degraded` (`200` HTTP, not `503`). Asserted by
`test/proxy/health_producers/graph_producers_test.dart` test
`graph_edge_count: yellow 3M, red 4M`.

### Step 4 — Edge-count red band (projection rollover trigger)

Force `graph_health_metrics.active_edge_count = 4500000`:

**Expected:** `status: red`, surface flips to red, `severity: red` on the
envelope. The Health admin screen's AGE Graph traversal section renders the
edge-count tile with a red `T2 · red` chip; Decision-30 calls for projection
rollover at this band. Asserted by the same test as Step 3.

### Step 5 — p95 traversal latency on Lock-3 boundary

Force `graph_benchmark_runs.p95_ms = 300` (most recent row):

**Expected:** `graph_traversal_latency_ms.status = "yellow"` with
`metadata.percentile = "p95"`. At `p95_ms = 700` the status flips to red
(p95 > 500 ms is the Lock-3 isolated-perf gate failure). Asserted by
test `graph_traversal_latency_ms p95 thresholds 250/500 (Lock 3 gate)`.

### Step 6 — No-benchmark projection (`status: unknown`)

When `graph_benchmark_runs` has no rows yet (fresh staging, or benchmark
worker not yet wired), the latency producer must NOT silently green-flag
the gate.

**Expected:** `graph_traversal_latency_ms.status = "unknown"`,
`value = null`, `metadata.warning = "no_benchmark_recorded"`. The
`/health` envelope's `severity` is unaffected (unknown does not promote to
degraded). Asserted by the empty-row branch of
`graphTraversalLatencyMsProducer`.

### Step 7 — Producer timeout projection (250 ms budget)

Inject a `FakeProxyHealthQueryRunner` with
`simulatedLatency: const Duration(milliseconds: 300)` and call
`graphTraversalLatencyMsProducer` with
`budget: const Duration(milliseconds: 50)`:

**Expected:** the producer body times out, `runProducer` substitutes the
template `unknown` metric, and `metadata.warning = "producer_timeout"` plus
`metadata.budget_ms = 50` are added. Asserted by test
`producer_timeout projection on slow benchmark runner`.

### Step 8 — Producer error projection (runner throws)

Register `FakeProxyHealthQueryRunner` to throw `StateError('boom')` for the
graph_health_metrics SQL prefix and call `graphEdgeCountProducer`:

**Expected:** the SQL throws, `runProducer` catches, returns the template
with `metadata.warning = "producer_error"`. The exception text is NOT
echoed (no leakage of sensitive substrings). Asserted by test
`producer_error projection when runner throws`.

### Step 9 — Tenant-identifier invariant

The graph producer SQL queries platform-wide functions
(`public.graph_health_metrics()`) and tables that are intentionally
operator-agnostic. None of the queries select an `operator_id` /
`location_id` column.

**Expected:** the rendered envelope contains no operator/tenant/device
identifiers. Cross-cutting check: `test/admin/health_admin_no_tenant_identifier_test.dart`
seeds sentinel identifiers into a metric's `metadata` and walks every
rendered Text widget; the F.1 health admin surface that consumes this
envelope passes. The B44 producer family does not introduce a new leakage
seam because it never emits identifier-shaped values.

### Step 10 — Operator-facing surface (consumer side, already shipped)

Sign in to the admin console as `super.admin@forgeflow.test`, click
`Health`, switch to the `Retrieval` tab. The `AGE graph traversal` section
renders six tiles backed by the producer family:
- `graph_traversal_latency_ms` (p95) → AGE p95 tile.
- `graph_traversal_p99_latency_ms` → AGE p99 tile.
- `graph_node_count` → graph node count tile.
- `graph_edge_count` → graph edge count tile.
- `graph_traversal_timeout_rate` → grey `T2 · unknown` tile in F.1's seed.
- `graph_projection_age_seconds` → grey `T2 · unknown` tile in F.1's seed.

The remaining three (`high_degree_node_count`, `failed_traversals_count`,
`growth_projection_90d_edges`) flow through the same envelope and become

## Permission gating evidence

- Server side (proxy): `/health` is a public unauthenticated endpoint per
  `docs/contracts/proxy_health_contract.md`. The B44 producers add no new
  authentication seam. The envelope is intentionally tenant-free so the
  graph metrics are safe to expose without an admin session.
- Client side (admin console): the consumer surface (`11A.UX.health`) is
  gated by Firebase custom claims (`super_admin` / `ff_support`) per F.1.
  B44 does not change that gate; it only fills metric values the existing
  surface reads.
- AGE side: the producer SQL is read-only (`select`-only) and references
  platform-wide health functions and benchmark/projection tables. There is
  no write path through B44.

## Tenant-identifier invariant

The proxy `/health` envelope MUST NOT carry tenant or operator identifiers
(`docs/contracts/proxy_health_contract.md` is explicit). The B44 producer
family preserves this:
- All SQL queries target tables that exist platform-wide
  (`public.graph_health_metrics()`, `graph_benchmark_runs`,
  `graph_traversal_metrics`, `graph_projection_runs`,
  `graph_growth_projection`).
- No `operator_id` / `location_id` is selected, embedded in `metadata`, or
  echoed in `value`.
- The producer `metadata` slot carries only `{tier: 2}` plus stable labels
  like `percentile: 'p95'` / `warning: '...'`. No free text, no IDs.

The cross-surface guard at
`test/admin/health_admin_no_tenant_identifier_test.dart` would catch a
leakage regression because it walks every rendered Text widget against
sentinel IDs; B44 does not introduce a new leakage path, so the existing
guard remains sufficient.

## Boundary checks

- B44 does NOT touch the proxy `/health` route shape or the contract. The
  producer family slots into the existing 57-producer catalog established
  by B42; the contract reserved keys for B44 ahead of time.
- B44 does NOT touch operator-facing app code. The producers live entirely
  under `tool/advisor_proxy/health_producers/`; the consumer surface
  (`11A.UX.health` / Health admin screen) was already wired in F.1.
- B44 does NOT generate the underlying graph data. The benchmark worker,
  AGE projection rebuild job, growth-projection worker, and traversal
  metrics rollup are separate operational gates owned by `9.0Σ.i` and
  Phase 11A.5. The producer reads what those workers write; absent rows
  project to `status: unknown` rather than silently green.
- The producer SQL uses only `public.graph_health_metrics()` and the
  canonical graph_* tables created by migration `202604280008`. Any rename
  of those surfaces requires a coordinated B44 update.
- 250 ms producer budget is shared across all family members; a slow AGE
  query times out into `unknown` rather than blocking the whole `/health`
  response.
- No tenant identifiers leak into the rendered envelope (see above).
- No tracker updates and no commits inside this slice itself; the closeout
  refresh that pairs with this walkthrough flips `phase_11A_operations_console_plan.md`
  and `PROJECT_TRACKER.md` blocker phrasing from `B44/B45/B47` to
  `B45/B47`.
