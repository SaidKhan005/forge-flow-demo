# 7.58.UX.5 Walkthrough — Variance day-row renderer honesty

**Slice:** 7.58.UX.5 (Phase 7.58 — Primary Driver audit follow-up)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-02

This slice closes the three findings the 7.58.0 contract re-pass left
open: `F-1` / `7.58.0a` (DRIFT, deferred), `F-6` / `7.58.0f` (DRIFT,
deferred), and `F-7` / `7.58.0g` (visual case mismatch, deferred).
Closing them required both a code change AND a coordinated contract
revision — per the plan doc rule "A `.1`-`.5` slice that diverges from
the contract opens a contract revision PR first, then ships the code."

The contract's literal pre-UX.5 Presentation Split rule said
"Rendering MUST use `LeverCards.all.firstWhere(... orElse: …)` … defaults
are `LeverCards.coversDown` / `LeverCards.ppaUp`," which is the exact
silent fall-through F-1 cited as overclaim. The new rule (revised in
this slice) names `LeverCards.lookup(id) → LeverCardData?` and the
`null` → degraded-surface contract. After both the contract revision
and the code fix land together, the audit map's "code vs contract"
column has zero divergence — i.e. zero DRIFT.

The change is operator-visible in three places: the inline `_LeverBadge`
in the closed-shift detail expand (lever metric copy replaces the
upper-snake id), the `ProjectionDaypartRow.driverLabel` for closed rows
(lowercase canonical form replaces upper-snake), and the deep
`LeverCardWidget` surfaces (degrade explicitly to `LeverCardNotYetAvailable`
when the id is `on_model` or unknown rather than silently rendering
"COVERS CAME IN LIGHT").

## What changed

### `lib/data/app_defaults.dart`

- New `LeverCards.lookup(String? id) → LeverCardData?` — case-insensitive
  lookup over the 16 known levers; returns `null` for the `on_model`
  sentinel, an unknown id, or empty/null input. Renderers MUST handle
  the null return as a degraded "Not yet on-model" state.
- New `LeverCards.notYetOnModelLabel = 'Not yet on-model'` — shared
  user-facing label for the degraded state.

### `lib/widgets/lever_card.dart`

- New `LeverCardNotYetAvailable` widget — the deep-card degraded
  shape for the Variance > This Week and Week Detail Primary Driver
  sections when the id is `on_model` or unknown.

## Demo seed shape (relevant for this walkthrough)

`MockReplayDataSeed.generateForDate('2026-03-27')` produces a current
week (`2026-W13`) where Mon-Thu lunch and dinner are closed,
Fri lunch is closed, and Fri dinner / late_night / Sat / Sun are
projected. Closed shifts run through `LaborModel.determineLever` to
get a real lever id (e.g. `COVERS_DOWN`); projected shifts are seeded
with the `'ON_MODEL'` sentinel via
`CurrentWeekState.shiftRecordFromSnapshot`.

## Click path (text trace)

### Step 1 — Launch the operator app in demo mode

`lib/main_forgeflow.dart` boots the operator shell with
`MockReplayDataSeed` attached. Default business date `2026-03-27`
(Friday in W13).

**Expected:** the operator home renders with the seeded current-week
data.

### Step 2 — Variance > This Week → PRIMARY DRIVER (deep card golden path)

Tap **Variance**. The PRIMARY DRIVER section reads
`weekData.primaryLeverId` (lowercase canonical from
`LaborModel.determineLever`), runs it through `LeverCards.lookup`, and
hands the matched `LeverCardData` to `LeverCardWidget`.

**Expected:** the same lever card the user saw before (e.g.
`LeverCardData.coversDown` for the demo W13 seed). Visual unchanged
on the golden path.

### Step 3 — Variance > This Week → FULL WEEK PROJECTION → Tap Tue

Tap **Tue** in the projection table to expand its daypart detail.
Tue lunch and Tue dinner are both closed in the W13 seed. Each
renders `_ClosedShiftDetail`, which ends with the inline `_LeverBadge`
at line 938.

**Expected (F-7 + F-1):**

- The Tue lunch detail panel `_LeverBadge` now reads
  `'PRIMARY LEVER: <metric>'` — for example
  `'PRIMARY LEVER: COVERS CAME IN LIGHT'` for the seeded
  `COVERS_DOWN` shift. Pre-7.58.UX.5 it read
  `'PRIMARY LEVER: COVERS DOWN'` (upper-snake leaked from storage).
- The badge color stays `AppColors.warning` for known levers;
  unknown / `on_model` ids fall to `AppColors.textMuted`.

`ProjectionDaypartRow.driverLabel` for the Tue lunch row equals
`'covers down'` (lowercase canonical) — pre-7.58.UX.5 it equalled
`'COVERS DOWN'`. Round-trips back to the engine id `'covers_down'`
via the contract test's `_displayedLeverIdFromLabel` helper.

### Step 4 — Variance > This Week → FULL WEEK PROJECTION → Tap Fri

Fri dinner / late_night are projected. They render
`_ProjectedShiftDetail` (no inline `_LeverBadge`).
`ProjectionDaypartRow.driverLabel` is `'Not yet available'` for both
— this is the 7.58.5 lift, unchanged in this slice. The new behaviour
this slice adds for these rows is one layer deeper: the storage form
`'ON_MODEL'` is now resolved through `LeverCards.lookup` rather than
falling through to `LeverCards.coversDown` if the `7.58.5` lift were
to regress.

### Step 5 — Inject the on_model sentinel via test fixture (degraded badge)

The on_model sentinel does not appear on a deep-card surface in the
default seed (the 7.58.5 lift catches it at the projection day-row
level). To exercise the new `LeverCardNotYetAvailable` widget on a
deep-card surface, the test suite injects a `WeekRecord` with
`primaryLeverId: 'on_model'` and pumps `WeekDetailScreen`. The screen
renders the degraded card text **'NOT YET ON-MODEL'** and the
**'PENDING'** corner badge. Pre-7.58.UX.5 the same input rendered
`LeverCards.coversDown`'s 'COVERS CAME IN LIGHT' card — the silent
overclaim F-1 forbids.

The defensive widget tests at
`test/variance_history_widget_test.dart`
(group: `Primary Driver degraded surfaces (7.58.UX.5 F-1, F-6)`) pin
this:

```
'NOT YET ON-MODEL'  — findsOneWidget    (LeverCardNotYetAvailable)
'PENDING'           — findsOneWidget    (corner badge)
'COVERS CAME IN LIGHT' — findsNothing   (no silent fall-through)
```

The same test set covers the unknown-id path
(`primaryLeverId: 'unknown_lever_xyz'`) and the WeekHistoryTile short
badge (`'—'` instead of `'COVERS'`).

## Brand styling

`lib/theme/app_theme.dart` is unchanged. The new
`LeverCardNotYetAvailable` widget reuses `AppColors.backgroundMid`,
`AppColors.borderSubtle`, `AppColors.textPrimary`, and
`AppColors.textMuted` — the same palette the rest of the projection
chrome uses for "no data yet" states. The accent stripe at the top of
the card is `AppColors.textMuted.withValues(alpha: 0.40)` instead of
the `AppColors.sunset.withValues(alpha: 0.60)` strip on a real lever
card — the dimmer accent reads as "pending" without competing with
the live cards above it.
