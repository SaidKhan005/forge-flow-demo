# 11A.0 Walkthrough — Flutter Web admin shell, branded + auth-gated

**Slice:** 11A.0 (Phase 11A — F&F Operations Console foundation)
**Mode:** `-DemoMode` opt-in (so the click path runs without
provisioning real `is_super_admin` / `is_ff_support` Firebase users)
**Date:** 2026-04-29

This walkthrough exercises the click path called out in the 11A.0
prompt's *Operator walkthrough (admin surface)* section. The admin
console default is **live Firebase admin auth** — the production
gate, the production deploy, and the production local-dev path all
go through `Firebase.initializeApp(options: kAdminFirebaseOptions)` +
`FirebaseAdminAuthSource`. The demo source is opt-in only; the
deploy script will not publish demo auth onto a public Cloud Run
service silently. The walkthrough below uses `-DemoMode` so it can
run end-to-end without minting real admin custom-claim users.

```powershell
scripts/run_admin_console_dev.ps1 -DemoMode -Device chrome
```

`-DemoMode` swaps in the fixture-login source for the walkthrough.
Without it, the script defaults to live Firebase admin auth (matches
the Cloud Run default) and the click path would need a real
`is_super_admin: true` / `is_ff_support: true` custom-claim user.

**Expected:** A landing surface with:

- the F&F splash icon (`assets/images/forge_flow_splash_icon.png`)
- the wordmark "Forge & Flow" in Playfair Display
- the subtitle "Operations Console" in IBM Plex Mono / sunset-dark
- a sign-in card with email + password fields
- the footer "F&F internal access only."

Enter `super.admin@forgeflow.test` + any password (e.g. `demo`) and
press Sign in.

  Console" subtitle

  Corpus, Integrations, Debug, Observability — each marked "soon")

**Expected:**

- `Home` → empty branded landing card

**Expected:** The Home card with the welcome copy is back in the body.

## Production auth path (default; not exercised in this walkthrough)

`scripts/deploy_admin_console.ps1` (no flags) ships the same shell
with `ADMIN_DEMO_AUTH=false`. `lib/main_admin.dart` then:

1. Calls `Firebase.initializeApp(options: kAdminFirebaseOptions)`.
   The Dart options are mirrored from `web/firebase-config.js`
   because FlutterFire Web does not auto-read that file.
2. Constructs a `FirebaseAdminAuthSource` over
   `FirebaseAuth.instance`.
3. Subscribes to `userChanges()` and, on every user emit, force-
   refreshes the ID-token result and projects the locked Phase 9
   custom-claim shape via `extractRolesFromClaims`:

   ```dart
   if (claims['is_super_admin'] == true) roles.add('super_admin');
   if (claims['is_ff_support'] == true) roles.add('ff_support');
   ```

   No `roles` array, no `role` string. Mirrors
   `lib/services/auth/firebase_auth_login_service.dart` so the
   admin console and the operator app agree on what "admin" means.

The deploy script refuses to flip `ADMIN_DEMO_AUTH=true` without
the `-DemoMode` switch and an explicit `DEPLOY DEMO ADMIN AUTH`
typed acknowledgement; demo auth on an `--allow-unauthenticated`
Cloud Run URL is a privilege bypass.
