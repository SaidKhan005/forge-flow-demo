# 11A.1 Walkthrough - Operator + location admin surface

**Slice:** 11A.1 (Phase 11A - F&F Operations Console)
**Mode:** `-DemoMode` (admin Flutter Web client + in-memory gateway,
no live Cloud Run admin proxy required)
**Date:** 2026-04-29

This walkthrough covers the admin click path called out in the 11A.1
prompt's *Operator walkthrough* section: onboarding a new operator,
adding/editing a second location, suspending and reactivating, and
verifying the non-admin fail-closed path. The demo source is opt-in
(`-DemoMode`); production binds the live Firebase admin auth source
+ HTTP gateway (`HttpOperatorLocationAdminGateway`) against the F&F
admin Cloud Run proxy.

## Permission gating evidence

- Client side (admin console): the operators route is only reachable
  when the auth gate admits the caller (super_admin / ff_support).
  The non-admin fail-closed path is asserted by
  `test/admin_operator_location_screen_test.dart` test
  `non-admin user is blocked by the admin auth gate`.
- Server side (proxy): every `/v1/admin/operators` and
  `/v1/admin/locations` request verifies the Firebase bearer token
  through `_resolveVerifiedClaimsOrWrite` and then
  `_isFfOperatorLocationAdminCaller`. This global 11A.1 surface is
  super-admin-only and does not require tenant `operator_id` /
  `location_id`; `ff_support` is rejected until support-scoped reads
  land. Asserted by `test/advisor_proxy_test.dart` 11A.1 group tests
  for global super-admin admission, non-admin rejection, `ff_support`
  write rejection, and browser CORS preflight.

## Retry semantics (HARD-H follow-up, 2026-05-02)

Every mutating operator/location action — onboard, patch, suspend,
reactivate, add/edit/remove location — now mints a fresh
`Idempotency-Key` per click and forwards it to the proxy. The proxy
reserves the key in `public.admin_request_idempotency` before the
mutation runs and stamps the response payload on completion, so a
network-timeout retry replays the cached response instead of stamping
a duplicate operator/location row + a duplicate `auth_events_audit`
entry. The header is OPTIONAL on the wire (older callers and the
existing test surface still work); when present + the proxy has the
store wired, the shared `_runAdminIdempotent` helper engages — same
envelope as the toggle handler.
