# 11A.12 Walkthrough - Members + Invites (cross-operator admin)

**Slice:** 11A.12 (Phase 11A - F&F Operations Console)
**Mode:** `-DemoMode` (admin Flutter Web client + in-memory members
admin gateway, no live proxy required)
**Date:** 2026-05-05

This walkthrough covers the admin click path for the new `Members`
route mounted at `/admin/members` in `lib/admin/admin_routes.dart`.
The launch slice ships the cross-operator parity surface for
Members + Invites, scoped behind the existing operator picker. F&F
super_admin can pick an operator, narrow the members table by the
locked filter set, exercise every admin-path row action, and send
an invite under the picked operator's tenancy. ff_support lands on
the read-only branch.

## Authority files exercised

- `docs/contracts/team_roles_hierarchy_console_parity_contract.md`
  § Members + Invites (`11W.1` + `11A.12`) - locked filter set,
  locked validation copy, idempotency-key strategy, audit-row
  shape, admin-only actions (`Restore soft-deleted` and
  `Override role grant`).
- `lib/admin/admin_routes.dart` - adds the
  `kAdminMembersRouteId = 'members'` route mounted after the
  operator picker, the `_buildMembers` builder + the
  `_MembersAdminRouteShell` host that runs the picker before the
  members surface, the `membersAdminGateway` field on
  `AdminConsoleServicesScope`, the `membersAdminGatewayOf(context)`
  accessor, and the `_defaultMembersAdminDemoGateway` fallback
  seeded from `kDemoMembersByOperator` /
  `kDemoInvitesByOperator`. No existing routes are modified.
- `lib/main_admin.dart` - resolves
  `HttpMembersAdminGateway` (mirrors the integration / pricing /
  corpus / feature-flags resolvers) and feeds it into
  `AdminConsoleServicesScope.membersAdminGateway`. Live builds
  bind the proxy-backed gateway; the in-memory walkthrough
  fixtures only reach the screen in
  `--dart-define=ADMIN_DEMO_AUTH=true` runs or when the proxy URI
  is missing - never on a live deploy.
- `lib/admin/screens/members_admin_screen.dart` - new
  `MembersAdminScreen` widget. Filter bar (status / role /
  location / mfa_enrolled / search), members table, pending
  invites panel. Per-row actions: `Suspend`, `Reactivate`,
  `Soft delete`, `Reset password`, `Reset MFA`, `Force logout`.
  Admin-only: `Restore soft-deleted`, `Override role grant`. Every
  write surfaces an admin reason dialog before forwarding the
  call.
- `lib/admin/screens/invite_member_admin_dialog.dart` - new
  invite dialog. Same field set as the operator-web sibling
  (`11W.1`) plus an `admin_reason` field; locked validation copy
  pinned by widget tests + the gateway test.
- `lib/admin/services/members_admin_gateway.dart` - new
  `MembersAdminGateway` interface + `HttpMembersAdminGateway`
  carries the bearer token to the proxy `/v1/admin/auth/users`,
  `/v1/admin/auth/invites`, and `/v1/admin/auth/role-grants`
  paths; idempotency key forwarded verbatim; non-forge-admin
  callers throw `MembersAdminForbiddenException` before any HTTP
  call lands. Audit history reads are intentionally NOT in this
  slice — `11A.14` owns the `/v1/admin/auth/audit-log` surface;
  `11A.12` writes audit rows but does not list them. `MemberAdminRow`
  carries `created_by` / `updated_by` / `created_at` / `updated_at`
  per parity contract § "Created_by / updated_by population";
  `MembersAdminAuditEvent` carries `business_date` + `row_hash`
  per § "Audit-row shape". Audit `action` strings live in the
  locked `team.*` / `auth.*` family (`team.users.deactivate`,
  `team.users.reactivate`, `team.users.soft_delete`,
  `team.users.restore`, `team.users.invite`,
  `team.session.force_logout`, `team.roles.assign` (with
  `payload.override = true` for admin overrides),
  `auth.password.reset`, `auth.mfa.reset`) so admin-path and
  operator-self-service writes produce identical canonical fact
  rows differing only in `actor_kind`. HTTP path segments match
  the contract permission keys: `/deactivate`,
  `/reset-mfa-factors`, etc.
- `lib/admin/services/demo_members_admin_gateway.dart` - new
  `InMemoryMembersAdminGateway` plus the demo seed
  (`kDemoMembersByOperator` / `kDemoInvitesByOperator`) so the
  walkthrough runs end-to-end without a backend. Captures audit
  events with `actor_kind = forge_admin` + the calling admin's
  UID + a non-empty `admin_reason` per the parity contract.
- `lib/admin/screens/operator_picker_screen.dart` - reused
  verbatim. The new route opens this picker on first paint and
  remembers the last-picked operator per admin UID.

## Permission gating evidence

- Client side (admin console): the members route is only reachable
  when the auth gate admits the caller (`super_admin` or
  `ff_support`); `operator@forgeflow.test` lands on the forbidden
  surface. The `_buildMembers` builder reads
  `state.session.roles` and computes `canEdit = roles.contains(
  'super_admin')`; the screen consumes `editingEnabled` to drive
  the read-only banner and the visibility of every row action.
- Defence in depth at the gateway seam:
  `MembersAdminGateway.suspendMember` (and every other write)
  throws `MembersAdminForbiddenException` when
  `actorIsForgeAdmin == false`, so even a screen bug that left a
  button visible cannot land a write. Asserted by the gateway
  test "every mutation throws MembersAdminForbiddenException
  when actorIsForgeAdmin is false".
- Defence in depth on `admin_reason`: the gateway throws
  `MembersAdminGatewayError(errorCode: 'admin_reason_required')`
  when the reason is empty - mirrors the proxy-side gate every
  `/v1/admin/auth/*` mutation has.
- Asymmetry pinning: the widget test "Restore soft-deleted action
  surfaces ONLY on soft-deleted rows" + "Override role grant
  surfaces on active rows but never on soft-deleted" pin the
  parity-contract claim that operator self-service (`11W.1`)
  cannot expose those actions.

  `11W.1` owns operator-web and is intentionally scoped out.

  pure-logic team controllers stay reusable for `11W.1`.

  ships.

## UX writing posture

Operator-facing copy in the new screen reads as plain English
(per `docs/frameworks/UX_ADJUSTMENT_FRAMEWORK.md` and the user's writing
standard). The page header subtitle explicitly names the audited
nature of every action so the F&F admin sees their accountability
up front: "Every admin action is audit-logged with your reason."

ZERO em dashes appear in any operator-facing literal in the new
files (test pin: `members_admin_gateway_test.dart` "no
operator-facing literal contains an em dash"). The validation
copy mirrors the parity contract's "Validation copy (locked,
identical across surfaces)" block verbatim.
