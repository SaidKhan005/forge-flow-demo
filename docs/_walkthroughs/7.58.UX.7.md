# 7.58.UX.7 Walkthrough - Coverage denominator caption on the leak snapshot

**Slice:** 7.58.UX.7 (Phase 7.58 - Depth Wave, Wave B; shipped jointly with 7.58.UX.9)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-05

This slice extends the Variance > Learn `_LeakSnapshotCard` so the
recurring-leak metric reads against the population it was drawn
from. Pre-7.58.UX.7 the snapshot title read just `CPLH BELOW
TARGET` and the operator had to mentally divide the LEAK REPEATS
counter by an unknown denominator. 7.58.3 already added the
`coverageCount` field to `LearnTeachingSummary`; this slice
surfaces it inline in the existing snapshot card so a claim like
"leak repeated 18 times" is read against the closed-shift
population that produced it.

The caption appends after the lever metric, separated by a middot
(U+00B7) so the operator reads `<METRIC> · Repeated <count> of
last <coverageCount> <pluralized daypart>`. No new card, no new
tile, no new section. The chrome of the snapshot card is unchanged.

## What changed

### `lib/screens/variance/variance_learn_tab.dart`

- `_LeakSnapshotCard.build` now derives `coverageCaption` via the
  new private helper `_coverageCaption(LearnTeachingSummary)` and
  joins it to `leakCard.metric` with a middot when the helper
  returns non-null.
- `_coverageCaption` returns `null` (omit caption) when ANY of the
  following holds: `summary.coverageCount <= 0`, the recurring
  leak count is zero, or `summary.topLeakDayparts` is empty. The
  copy never asserts a denominator the analyzer cannot back; the
  bare metric renders unchanged on those rows.
- The fallback placeholder for the existing `REPEATS IN` metric
  row (formerly `'—'`) is now an ASCII hyphen `-`, matching
  the depth-wave em-dash ban (hard gate #4). The fallback row no
  longer renders a U+2014 glyph on empty input.
- `_pluralizeDaypart('Tue Lunch') -> 'Tue Lunches'`,
  `_pluralizeDaypart('Wed Dinner') -> 'Wed Dinners'`,
  `_pluralizeDaypart('Thu Late Night') -> 'Thu Late Nights'`. The
  three daypart labels in the canonical catalog cover the plural
  rule: `Lunch` takes `es`, the others take `s`.

### `test/screens/variance/variance_learn_tab_depth_test.dart`

NEW. Pins the rendered caption under a fake data source with
`closedShifts.length == 12` and a recurring `covers_down` leak
across 6 Tuesday lunches. Asserts the snapshot title contains
`COVERS CAME IN LIGHT · Repeated 6 of last 12 Tue Lunches`. A
second test confirms that when patterns + closed shifts are both
empty (the production-realistic zero-coverage state) the
"Leaks will surface here" no-patterns card renders and the caption
copy never appears.

## Demo seed shape (relevant for this walkthrough)

`MockIntegrationReplaySeed` boots the operator app against
`DemoData.historicalClosedShifts` (the same closed-shift list the
LearnTab loader reads via `getHistoricalClosedShifts`) plus
`DemoData.weekHistory`. Reducing the closed shifts through
`HistoryPatternBuilder.fromClosedShifts` and then
`LearnTeachingAnalyzer.summarize` produces:

- `summary.coverageCount` = 116 (`closedShifts.length`)
- `summary.primaryLeakId` = `cplh_down`
- `summary.primaryLeakCount` = 18
- `summary.topLeakDayparts` = `[Thu Dinner, Tue Dinner]`
- `summary.crossAxisPairs.first.count` = 7 (single cell:
  `cplh_above_splh_below`)
- swap predicate `7 >= 3 AND 7 > 18` = **false** -> single-axis
  path is the rendered path on the demo seed; this walkthrough
  exercises that path.

The `LeverCards.cplhDown` catalog entry has `metric: 'CPLH BELOW
TARGET'`; the leak snapshot title concatenates the metric with the
caption.

## Click path (text trace)

### Step 1 - Launch the operator app in demo mode

`lib/main_forgeflow.dart` boots the operator shell with
`MockReplayDataSeed` attached. The `LearnTab.initState` future
resolves four reads in parallel: `getWeekHistory`,
`getHistoryPatternRecords`,
`LearnBenchmarkContextService.instance.resolve()`, and
`getHistoricalClosedShifts`. The closed-shift list length feeds
the coverage denominator.

**Expected:** the operator home renders with the seeded
current-week data.

### Step 2 - Tap Variance -> Learn tab

The `VarianceReport` shell renders the three-tab strip
(`This Week` / `History` / `Learn`). Tap `Learn`.

**Expected:** the Learn tab opens with the hero strip
(`Last <N> tracked weeks` + benchmark chips) at top.

### Step 3 - Read the leak snapshot card

Below the chapter rail (`Recurring Leak` is the default chapter),
the carousel renders four cards. The first card is the
`_LeakSnapshotCard`. Its title now reads:

```
CPLH BELOW TARGET · Repeated 18 of last 116 Thu Dinners
```

The middot (`·`, U+00B7) separates the lever metric from the
coverage caption. `Repeated 18` is `summary.primaryLeakCount`,
`116` is `summary.coverageCount` (the closed-shift list length),
and `Thu Dinners` is the pluralized form of
`summary.topLeakDayparts.first` (`Thu Dinner` -> `Thu Dinners`).

**Expected (pre-7.58.UX.7):** the title read just
`CPLH BELOW TARGET`.
**Expected (post-7.58.UX.7):** the caption joins via middot.

### Step 4 - Read the trailing chips and metric rows

Below the title, the snapshot card's trailing slot still renders
the lever identity chips (`CPLH` / `SCHEDULING` / `FOH ONLY`)
and the two metric rows: `LEAK REPEATS` (18) and `REPEATS IN`
(`Thu Dinner / Tue Dinner`). The chrome and copy of these rows
are unchanged from pre-7.58.UX.7; the caption rides ABOVE them
inside the existing `LearnTeachingCard.title` slot.

**Expected:** chip + metric-row layout unchanged. Caption renders
once on the snapshot card and does not repeat on the three
teaching cards (Step 5).

### Step 5 - Confirm the carousel structure stays 4 cards

Swipe through the carousel to read each teaching card. The
sequence is unchanged: snapshot, `WHAT HAPPENED`, `WHAT TO DO`,
`WHAT TO STUDY`. The three teaching cards read
`leakCard.whatHappened`, `leakCard.whatToDo`, and
`leakCard.teachingNote` from the `cplh_down` catalog entry. The
coverage caption renders ONCE on the snapshot card.

**Expected:** the carousel has exactly 4 `LearnTeachingCard`
widgets in the Recurring Leak chapter (single-axis branch).
The position indicator reads `1 of 4` on the snapshot page. The
test pins this with `find.text('1 of 4')`.

### Step 6 - Honest fallback when coverage is zero

In a production-realistic zero-coverage state (e.g. a
just-onboarded restaurant before any close), `closedShifts` is
empty, `patternRecords` is empty (because
`HistoryPatternBuilder.fromClosedShifts` reads from the same
population), and `summary.hasHistoryPatterns` is false. The
snapshot card does not render at all; the carousel falls back to
the single `Leaks will surface here` no-patterns card. The
caption is suppressed at the source - no half-formed denominator
ever leaks into operator copy.

The widget test pins this branch with empty fixtures:
`expect(find.text('Leaks will surface here'), findsOneWidget)`
and `expect(find.textContaining('Repeated'), findsNothing)`.
