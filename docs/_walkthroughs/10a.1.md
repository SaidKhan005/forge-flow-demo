# 10a.1 Walkthrough — Cloud Pub/Sub realtime publisher adapter

**Slice:** 10a.1 (Phase 10a — Shared Multi-Device State V1, Pub/Sub publisher swap)
**Mode:** Pure transport swap behind the `RealtimeEventPublisher` seam shipped in 10a.0; in-process binding remains demo/local default; Cloud Pub/Sub adapter lights up via `PUBSUB_REALTIME_ENABLED` env flag (default off)
**Date:** 2026-05-03

This walkthrough closes the 10a.1 slice: the Cloud Pub/Sub publisher
adapter explicitly queued in `docs/_walkthroughs/10a.0.md` "Out of
scope" lands here against the existing seam. The swap is a pure
transport change — bridge worker, WebSocket route, and the client
`RealtimeSubscription` are all untouched.

The Hard Promise this slice realizes:

> Phase 8 = pure transport swap. Vendor connectors write existing
> SQLite tables only; cleanup is `7.57`/`7.58`/`7.61`.

The realtime fan-out path is on that same posture: the seam is
defined; the implementation behind it can swap from in-process to
Cloud Pub/Sub with no app-logic moves. Hard Promise #2 (demo mode
persists post-launch) is honored by leaving the in-process binding
as the local/demo default — the env flag is opt-in.

## Files added

- `lib/services/realtime/pubsub_realtime_publisher.dart` —
  `PubsubRealtimePublisher` adapter implementing the existing
  `RealtimeEventPublisher` interface. Constructor resolves every
  locked namespace via an injectable `PubsubTopicNameResolver`
  (default identity — `(ns) => ns`); a resolver that returns empty
  for any namespace fails the boot path with `ArgumentError`.
  `publish(event)` extracts the namespace from the event's dotted
  topic, looks up the resolved Pub/Sub topic name, and hands body +
  attributes (`operator_id`, `topic`, `event_id`) to an injected
  `PubsubMessagePublisher` callback. In-memory `publishedCount` /
  `publishFailedCount` counters drive the existing realtime metric
  path (no new health producer; the existing structured-log + 11A.6
  admin tile already absorbs the realtime envelope shape).
- `test/services/realtime/pubsub_realtime_publisher_test.dart` —
  unit tests pinning interface conformance, topic resolution at
  construction, the locked-namespace gate, custom resolver
  honoring, structured log emission, and counter behavior on both
  success and failure paths. Failure path also verifies the publish
  rethrows so the bridge's lease-based retry can apply.
- `test/services/realtime/realtime_bridge_pubsub_swap_test.dart` —
  selector tests pinning that `PUBSUB_REALTIME_ENABLED` defaults to
  off, recognizes `true` / `1` / `yes` (case-insensitive, whitespace
  tolerant), and that the selected Pub/Sub publisher actually routes
  events through the injected message publisher (the swap is real,
  not just a type change).

## Files changed

- `tool/advisor_proxy/realtime_bridge.dart` — adds the
  `selectRealtimePublisher({...})` helper and the
  `pubsubRealtimeEnabledEnvVar` constant. The helper takes the env
  map plus the in-process publisher plus the Pub/Sub message
  publisher callback and returns the right `RealtimeEventPublisher`
  for the deploy. `RealtimeBridgeWorker` itself is unchanged — it
  still takes a `RealtimeEventPublisher` (the existing seam), so the
  swap is pure construction-time.
- `tool/advisor_proxy/main.dart` — Cloud Run entrypoint now calls
  `selectRealtimePublisher(...)` to construct the bridge's outbound
  publisher (instead of hard-wiring `InProcessRealtimePublisher()`
  as 10a.0 did). The `/v1/realtime` route still subscribes to the
  in-process publisher; only the bridge's outbound side is selected.
  An unwired-stub `PubsubMessagePublisher` is injected because the
  production Pub/Sub binding (Application Default Credentials, GCP
  project + region, `gcloud_pubsub` SDK or REST) lands in a follow-up
  slice. A startup gate immediately after the selector exits with
  `78` (EX_CONFIG) when the resulting publisher is a
  `PubsubRealtimePublisher` — i.e. when `PUBSUB_REALTIME_ENABLED` is
  on but the production adapter is still the stub. This keeps the
  flag-on path fail-close: production cannot accidentally route
  fan-out to the stub. The flag-off path (default) returns the
  in-process publisher and the proxy proceeds to bind exactly as
  it did in 10a.0. A new `_logPubsubRealtimePublisherEvent` helper
  funnels publisher log events into the canonical `log()` shim with
  `realtime.publisher.published` / `realtime.publisher.publish_failed`
  event names, mirroring the existing `realtime.bridge.*` envelope.

## Click path (text trace — swap drill, no UI)

This slice has no operator-facing UI surface; the demonstration path
is the seam swap drill in the proxy's startup wiring.

### Drill 1 — Default off (in-process binding retained)

Without the env flag set, the bridge worker constructs the same
in-process publisher as 10a.0:

```text
PUBSUB_REALTIME_ENABLED  unset
selectRealtimePublisher(...)
  -> InProcessRealtimePublisher (from 10a.0)
RealtimeBridgeWorker(publisher: <in-process>)
/v1/realtime route subscribes to <in-process>
producer enqueues event_outbox row
  -> bridge claims via EventOutboxRepository.claimBatch(...)
  -> publishes through <in-process>
  -> WebSocket client receives frame
```

Identical end-to-end behavior to 10a.0. Demo / local deploys keep
working without reaching for a Cloud Pub/Sub project (Hard Promise
#2 — demo mode persists post-launch).

### Drill 2 — Flag on (Cloud Pub/Sub adapter swapped in)

Setting `PUBSUB_REALTIME_ENABLED=true` swaps the bridge's outbound
publisher. **Today the proxy fails the boot with exit 78** because
the production Pub/Sub message publisher (Application Default
Credentials, GCP project + region, `gcloud_pubsub` SDK or REST) is
still the unwired stub — that wiring is the next slice. The seam
swap itself is real; the gate just refuses to run with a stub
behind it.

```text
PUBSUB_REALTIME_ENABLED  true
selectRealtimePublisher(...)
  -> PubsubRealtimePublisher (this slice)
       constructor resolves every locked namespace
         auth.session       -> <topicNameResolver(auth.session)>
         auth.user          -> <topicNameResolver(auth.user)>
         usage.cap          -> <topicNameResolver(usage.cap)>
         rollup.invalidate  -> <topicNameResolver(rollup.invalidate)>
         advisor.candidate  -> <topicNameResolver(advisor.candidate)>
         workflow.event     -> <topicNameResolver(workflow.event)>
         internal.health    -> <topicNameResolver(internal.health)>
       (any resolver miss -> ArgumentError, bridge fails to start)
main.dart startup gate:
  realtimeBridgePublisher is PubsubRealtimePublisher  -> true
  log: startup.failed
       phase = realtime_pubsub_message_publisher_unwired
       env_flag_name = PUBSUB_REALTIME_ENABLED
       resolved_topics = { 7 locked namespaces -> topic names }
  exitCode = 78
  return
```

Once the production Pub/Sub message publisher lands and the gate is
removed, the boot proceeds:

```text
RealtimeBridgeWorker(publisher: <pubsub>)
producer enqueues event_outbox row
  -> bridge claims via EventOutboxRepository.claimBatch(...)
  -> publishes through <pubsub>
       PubsubMessagePublisher(
         topicName: <resolved Pub/Sub topic>,
         body: <RealtimeEvent.encode()>,
         attributes: { operator_id, topic, event_id },
       )
  -> bridge marks delivered_at on Pub/Sub ack
```

The WebSocket route still subscribes to a (now-empty) in-process
publisher; the multi-instance Pub/Sub → WebSocket consumer wiring
is a downstream slice. The slice's seam swap is the bridge's
outbound side — that's what this slice ships.

### Drill 3 — Invented topic still rejected

A producer that drops a topic outside the locked namespace set
(say `invented.namespace.kind`) hits the publisher's locked-set
gate before reaching Pub/Sub:

```text
publisher.publish(event(topic="invented.namespace.kind"))
  -> _resolvedTopics["invented.namespace"] == null
  -> StateError("topic ... is outside the locked namespace set ...")
  -> publishFailedCount += 1
  -> publish_failed structured log emitted
  -> rethrown so the bridge applies lease-based retry
     (the row stays unsealed; eventual consumer fix re-publishes)
```

This is the contract's "Producers MUST NOT invent topics" rule
enforced at the publisher boundary, not just at the producer's
enqueue site.

## Trace summary (text evidence)

What the seam swap proves end-to-end:

- **Pure transport.** The bridge worker, the WebSocket route, the
  client subscription, and the `RealtimeEvent` wire shape are all
  byte-identical between Drill 1 and Drill 2. Only the bridge's
  outbound publisher swaps.
- **Fail-closed boot.** A misconfigured topic-name resolver
  (returns empty for any locked namespace) fails the bridge's
  startup with `ArgumentError`. Tests pin this. Production gets
  the misconfiguration as an exit-78 startup failure (matches the
  shape of the existing dependency probes in `main.dart`).
- **Locked-set discipline.** A topic outside the contract's locked
  namespace list throws `StateError` at publish time; the message
  publisher callback is never invoked. Tests pin this both directly
  (publisher unit test) and through the selector path (swap test).
- **Operator scoping.** Pub/Sub message attributes carry
  `operator_id`, `topic`, and `event_id`. The contract's
  "subscribers never see cross-operator events" requirement is
  enforced by the subscription filter on the consumer side; this
  slice ships the publisher half (the attributes the filter matches
  on).
- **At-least-once semantics preserved.** Publish failures rethrow,
  the bridge does not call `markDelivered`, and the lease window
  re-claims the row. The contract's
  "consumers dedupe via `event_id`" rule is honored because
  `event_id` flows through the attribute set on every message.

## Permission gating evidence

This slice ships no operator-facing route, so no permission-key
catalog entries change. The relevant gates are structural rather
than per-permission:

- **Locked namespace gate.** The publisher refuses topics outside
  `defaultLockedNamespaces` (the contract's locked set) with a
  `StateError`. A producer trying to mint a namespace by accident
  hits the gate before any Pub/Sub call. Tests:
  `pubsub_realtime_publisher_test.dart` →
  `rejects topics outside the locked namespace set with StateError`,
  and the swap-side equivalent in
  `realtime_bridge_pubsub_swap_test.dart` →
  `selected Pub/Sub publisher honors the locked namespace check`.
- **Topic-shape gate (`<kind>` suffix + lower-snake-case).** The
  contract locks every namespace as a wildcard (`auth.session.*`,
  `rollup.invalidate.*`, ...) and pins
  "Topics are dot-separated lower-snake-case strings." The
  publisher enforces both halves: every topic must have at least
  three dotted segments, and every segment must match
  `[a-z][a-z0-9_]*` (lowercase letter followed by lowercase
  letters / digits / underscores). The following all fail with
  `FormatException` routed through the same failure counter +
  structured-log path as a Pub/Sub ack failure:
  - namespace-only topics (`rollup.invalidate`)
  - empty dotted segments (`rollup.invalidate.`,
    `rollup..variance_week`, `.rollup.invalidate.x`)
  - non-lower-snake-case segments (`rollup.invalidate.VarianceWeek`,
    `rollup.invalidate.variance-week`, `rollup.invalidate.bad value`,
    `Rollup.invalidate.variance_week`, `rollup.invalidate.123_kind`,
    `rollup.invalidate._leading_under`)

  Tests: `pubsub_realtime_publisher_test.dart` →
  `rejects malformed (non-dotted) topics`,
  `rejects namespace-only topics (no <kind> suffix)`,
  `rejects topics with empty dotted segments`,
  `rejects non-lower-snake-case topics`, and
  `accepts well-formed lower-snake-case topics including digits and
  underscores in the <kind> suffix` (positive sanity check that
  the regex does not over-restrict valid producers).
- **Operator scoping carrier.** Every Pub/Sub message attaches
  `operator_id` as a Pub/Sub attribute so subscription filters can
  enforce per-tenant fan-out at the consumer boundary. Test:
  `pubsub_realtime_publisher_test.dart` →
  `translates topic to locked namespace + hands body + attributes
  to the message publisher`.
- **Boot-path failure on misconfiguration.** Constructor throws
  `ArgumentError` if any locked namespace fails to resolve to a
  Pub/Sub topic name. Test:
  `pubsub_realtime_publisher_test.dart` →
  `throws ArgumentError when resolver returns empty for any namespace`
  + `throws ArgumentError when resolver throws for any namespace`.

## Boundary checks

- **No new persistence imports outside
  `lib/infrastructure/persistence/postgres/`.** The Pub/Sub adapter
  is purely a publisher; it does not touch Postgres. The bridge's
  Postgres path (`EventOutboxRepository.claimBatch` /
  `markDelivered`) is unchanged. CI lint that bans raw
  `package:postgres` outside the persistence folder still passes.
- **Bridge contract preserved.** `RealtimeBridgeWorker.publish` ↔
  `markDelivered` ordering, lease semantics, and the
  "rethrow on publish failure" rule are unchanged. The Pub/Sub
  adapter rethrows on failure so the lease window picks the row up
  again (contract: "On graceful Pub/Sub failure, worker increments
  attempt_count, writes last_error_at + last_error, and re-NULLs
  picked_up_at" — the `attempt_count` ledger half is the explicit
  Phase 10a follow-up; the lease-based half lands today).
- **Topic-shape contract preserved.** `defaultLockedNamespaces`
  matches the contract's "Topic Shape" locked list verbatim. A
  test pins the constant against the contract list; a future
  drift between the publisher and the contract document fails the
  test.
- **WebSocket route untouched.** `tool/advisor_proxy/realtime_route.dart`
  takes `InProcessRealtimePublisher` as before. The route is the
  consumer side of the Pub/Sub leg (downstream slice), not the
  publisher side this slice ships.
- **`main.dart` wires the selector but stays fail-close.** The
  selector is now called every startup so the env flag swap is real
  rather than dead code; the production Pub/Sub message publisher
  callback is the next slice. Until it lands, the startup gate
  exits `78` whenever `PUBSUB_REALTIME_ENABLED` is on, so a stray
  flag flip cannot route fan-out to a stub.
- **Malformed-topic counter parity.** The publisher's
  `_namespaceOf` throws on non-dotted topics; this slice routes
  that through the same `publishFailedCount` + structured-log path
  as a Pub/Sub ack failure so the realtime metric path sees one
  failure shape regardless of whether the failure was upstream
  (malformed topic), at the gate (locked-set rejection), or at the
  Pub/Sub call. Test:
  `pubsub_realtime_publisher_test.dart` →
  `rejects malformed (non-dotted) topics with FormatException AND
  updates failure counter + emits structured log`.
- **No tracker / contract / phase-doc edits.** Slice prompt
  forbids; no-tracker discipline preserved.
