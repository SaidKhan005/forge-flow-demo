# 10.5.6 Walkthrough — OPZ matrix grid + cross-axis sub-label

**Slice:** 10.5.6 (Phase 7.58 depth wave, Wave A)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-05

This walkthrough closes the OPZ depth surface that the Phase 7.58
depth wave plan owes. The Shift Dashboard whole-day OPZ tile already
shows a status pill (`BELOW OPZ` / `IN OPZ` / `ABOVE OPZ`) and a
single sentence of teaching copy. 10.5.6 lifts the Jim Taylor 2x2
diagnosis (CPLH x SPLH) into the same tile so the operator reads the
joint pattern instead of cross-referencing CPLH and SPLH metric cards
in their head.

The Hard Promise this slice keeps:

> Shift's whole-day view is authoritative. 10.5 adds depth alongside,
> never replacing.

The whole-day primary lever, gauge, status pill, sub-label, and the
surrounding dashboard chrome are all preserved. The new matrix grid
and the cross-axis sub-label swap render inside the existing OPZ
tile. No new tile, card, or section is added.

The 7.58 contracts the slice honors:

- **Single Source of Truth.** The matrix reads `opzStatus` (already
  computed from `actualCPLH` vs `opzFloorCPLH` / `opzCeilingCPLH`)
  and `splhState` (newly classified from `actualSPLH` vs
  `targetSPLH`). No alternate productivity formula is introduced;
  the bands are pure presentation derived from values the read model
  already builds.
- **Presentation Split.** The matrix widget consumes typed enums
  (`OpzCplhBand` / `OpzSplhBand`); the read model emits
  `String?` state values that round-trip cleanly through the
  existing read-model API. The single-axis sub-label sentences are
  preserved unchanged for the seven cells where the two axes agree
  or SPLH is null.
- **Honest fallback.** When BOH is not punched in (`actualBohHours
  <= 0`) or `targetSPLH <= 0`, `splhState` is null. The grid renders
  9 dim cells with no active marker, and the sub-label falls back to
  the single-axis CPLH sentence. The slice never paints a phantom
  active cell off a missing axis.
- **No em dashes.** Every sentence the resolver returns is pinned by
  test against U+2014.

MODIFIED:

- `lib/models/shift_dashboard_read_model.dart` — adds `currentSplh`,

## Click path (text trace)

### Step 1 — Launch the operator app in demo mode

Run `lib/main_forgeflow.dart` (kDemoMode is pinned in
`lib/data/app_defaults.dart`). The app boots into the operator
shell with the seeded mock replay data source attached and the
active target profile bootstrapped.

**Expected:** Shift dashboard renders with whole-day metrics on
screen. The scope toggle defaults to **Whole Day**. SHIFT OUTPUTS
and SHIFT INPUTS sections render byte-identical to pre-10.5.6.

### Step 2 — Scroll to FOH PRODUCTIVITY

Scroll the Shift surface until the FOH PRODUCTIVITY sticky header
pins. The OPZ tile renders below it.

**Expected:** Inside the same OPZ tile, in this top-down order:

1. `CURRENT CPLH` label and the live CPLH value.
2. The OPZ status pill (`BELOW OPZ` / `IN OPZ` / `ABOVE OPZ`).
3. The CPLH gauge (zone bar with current dot, floor / target /
   ceiling ticks). Unchanged from pre-10.5.6.
4. The new `CPLH x SPLH` matrix label, then a 3x3 grid with column
   headers `SPLH LOW` / `SPLH ON` / `SPLH HIGH` and row labels
   `CPLH OVER` / `CPLH OPZ` / `CPLH UNDER`.
5. The cross-axis sub-label sentence below the grid.

### Step 3 — Inspect the active cell on the demo seed

The demo seed's whole-day numbers resolve to a specific
`(opzStatus, splhState)` pair. The grid highlights the matching
cell in `AppColors.sunset` with the eight others rendering dim
middots.

**Expected:** Exactly one cell is highlighted. The sub-label below
the grid reads either the single-axis CPLH sentence (when the two
axes agree on direction or sit `(in, on)`) or one of the four
cross-axis Jim Taylor diagnoses:

- `(below, above)`: "Below OPZ floor. Team executed. Volume
   problem, not staffing. Fix the forecast."
- `(above, below)`: "Above OPZ ceiling AND kitchen slowed. Pull
   ticket times before adding hours."
- `(in, below)`: "In OPZ. PPA dropped. Watch upselling."
- `(in, above)`: "In OPZ. Kitchen running strong. Document this
   shift."

### Step 4 — Force the cross-axis "fix the forecast" cell

In `lib/dev/demo_fixture_data.dart` (kDemoMode editor seam), pick a
shift where covers ran light and BOH was on top of tickets so:

- `actualCPLH < opzFloorCPLH` (CPLH band: below)
- `actualSPLH > targetSPLH * 1.05` (SPLH band: above)

Hot-restart the operator app. Scroll to FOH PRODUCTIVITY.

**Expected:**

- Status pill reads `BELOW OPZ`.
- Matrix grid: the bottom-left cell (`CPLH UNDER` row x
  `SPLH HIGH` column) is highlighted in `AppColors.sunset`. Eight
  other cells render dim middots.
- Sub-label below the grid swaps to:
  ```
  Below OPZ floor. Team executed. Volume problem, not staffing.
  Fix the forecast.
  ```
  No em dash anywhere in the sentence.

### Step 5 — Force the BOH-not-punched-in fallback

Edit the same demo seed so `actualBohHours == 0` (BOH crew not yet
on shift) while keeping the FOH covers and CPLH inputs. Hot-restart.

**Expected:**

- Status pill still reads its CPLH-driven label (e.g., `IN OPZ`).
- Matrix grid renders with all 9 cells dim. No cell is highlighted
  in sunset. The middot pattern is intentional: the operator sees
  the matrix shape but the slice refuses to paint a CPLH-only cell
  as if SPLH were known.
- Sub-label swaps back to the single-axis CPLH sentence
  (e.g., "Team is producing. Watch covers." for the on-target CPLH
  band). No cross-axis diagnosis is painted while SPLH is missing.

### Step 6 — Switch to Daypart and back

Tap **Daypart**.

**Expected:** SHIFT OUTPUTS / INPUTS / FOH PRODUCTIVITY (and the new
matrix grid inside the OPZ tile) collapse. The daypart cards from
10.5.0 - 10.5.3 render unchanged. Tap **Whole Day** to restore. The
matrix grid re-mounts and reflects the current
`(opzStatus, splhState)` pair.

  `LaborModel.attributeDollarImpactByAxis`, and

  engine seam.

  changed.

  `no-data state renders 9 dim cells when SPLH is null` and the
  resolver tests for `splhState: null` across the three CPLH bands.
