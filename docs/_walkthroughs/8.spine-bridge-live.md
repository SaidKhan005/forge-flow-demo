# 8.spine-bridge-live Walkthrough

Date: 2026-05-06

Status: Proof PASS on Codex integration branch

## Scope

This walkthrough covers the live current-state path for
`8.live-and-closed-truth-core`:

1. Canonical POS, labor, and reservation facts enter the server projector.
2. `OpenShiftSnapshotProjector` resolves the server-side business timing
   profile and stable service-period key.
3. The projector writes `public.open_shift_snapshots` rows for each active
   service period plus a whole-day rollup.
4. The mobile operational sync proxy returns timing provenance from the server
   rows.
5. Mobile parses and persists the rows into the existing SQLite
   `open_shift_snapshots` cache.

Mobile SQLite is a cache. Server-side Postgres timing and open snapshot rows
remain the source of truth.

## Evidence

The lean proof harness is `tool/payload_harness/main.dart`.

Covered proof paths:

- POS payload: `OpenShiftCanonicalFactKind.pos` rows drive covers, sales, PPA,
  and service-period snapshot writes.
- Labor support path: `OpenShiftCanonicalFactKind.labor` rows drive FOH/BOH
  hour splits and CPLH/SPLH denominators.
- Reservation support path: `OpenShiftCanonicalFactKind.reservation` rows
  contribute forecast covers to the whole-day rollup without replacing POS
  current covers.
- Idempotency replay: duplicate canonical ids do not duplicate metrics.
- Small burst: multiple facts in one service period upsert one row.
- Cross-tenant isolation: facts for another operator/location are ignored.
- Missing timing profile: projector returns an unavailable result and writes no
  demo truth.
- Proxy/mobile: open snapshot timing provenance survives proxy JSON parsing and
  SQLite persistence.

## Non-Goals

- No push notification proof.
- No large pressure suite.
- No duplicate `open_shift_snapshots_cache` table.
