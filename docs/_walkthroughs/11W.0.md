# 11W.0 Walkthrough — Operator Web Console shell + onboarding click-path

**Slice:** 11W.0 (Phase 11W — Operator Web Console foundation)
**Mode:** `OPERATOR_WEB_DEMO_AUTH=true` (live Firebase auth source seam ships in `11W.0.live`; the `11W.0` deploy script refuses non-demo builds until that follow-up lands)
**Date:** 2026-05-03

This walkthrough is a numbered click-path per the
`docs/CODEX_PROMPT_GENERATION_STANDARD.md` *Walkthrough Specificity*
section. Each step names the user action, the resulting URL, the
widget under test (by `Key`), and the on-screen copy the operator
sees. Bar: `docs/_walkthroughs/7.58.UX.5.md`.

## Demo seed shape (relevant for this walkthrough)

`DemoOperatorWebAuthSource.atWelcome()` boots the auth source on
`OperatorWebSignedOut`. The demo accepts exactly one magic-link
token, exactly one TOTP code, and exactly one operator session:

| Fixture | Value |
| --- | --- |
| Magic-link token (only one accepted) | `demo-magic-link-token` (`DemoOperatorWebAuthSource.kDemoMagicLinkToken`) |
| TOTP verification code (only one accepted) | `123456` |
| Operator session UID | `demo-operator-owner` |
| Operator email | `owner@demo.forgeflow.test` |
| Display name | `Demo Operator Owner` |
| Operator id | `demo-operator` |
| Business name | `Demo Restaurant Group` |
| Primary location id | `demo-location` |
| Primary location name | `Demo Main Street` |
| Role claim | `operator_owner` |
| Active T&Cs version id | `demo-tos-v1` |
| Active T&Cs scope | `inbound_vendor_universal` |
| Active T&Cs version number | `1.0.0` |
| Active T&Cs effective date | `2026-05-03` |

Forbidden fixture (`DemoOperatorWebAuthSource.forbidden()`) lands a
session whose only role is `staff` — used to exercise the
`OperatorWebForbidden` branch.

## Click path — happy path

### Step 1 — Operator opens the magic-link from the invite email

**Action.** Operator clicks the invite link in the SendGrid welcome
email. Browser navigates to:

```
https://app.forgeflow.app/onboarding/welcome?token=demo-magic-link-token
```

`lib/main_operator_web.dart:_parseMagicLinkToken()` reads `Uri.base`
and lifts the `?token=` parameter off the URL. The router boots in
`OperatorWebSignedOut` and renders `WelcomeScreen` with the parsed
token pre-filled.

  `Invite code`, helper text `The code from your invite email,

## Adversarial — route guard

### Adversarial #1 — Signed-out operator hits `/account` directly

**Action.** Operator pastes `https://app.forgeflow.app/account` into
the URL bar (perhaps an old bookmark from a future post-V1 build).

The auth source's current state is `OperatorWebSignedOut`. The
router's `switch (state)` arm matches `OperatorWebSignedOut` and
calls `_buildWelcome(state.lastErrorMessage)` — it does **not** read
the URL path. Effective URL after the rebuild is treated as
`/onboarding/welcome` (the welcome surface is what the router
renders).

**Expected visual state.**

- `Key('operator_web_shell_scaffold')` — **not** present
- `Key('operator_web_account_placeholder')` — **not** present
- `Key('operator_web_step_pill')` — text reads `Step 1 of 4 — Welcome`
- `Key('operator_web_welcome_token_field')` — present, value empty
  (no `?token=` on the URL)
- `Key('operator_web_welcome_submit')` — present

The route guard's enforcement axis is **state**, not URL. Whatever
the operator types into the address bar, the auth state determines
what renders. Because the auth source is `OperatorWebSignedOut`, the
operator lands on the welcome surface — no leaked Account placeholder.

### Adversarial #2 — Signed-in-without-T&Cs operator hits `/account` directly

**Action.** Operator has completed password + MFA but has not yet
ticked the T&Cs checkbox (auth state =
`OperatorWebAcceptingTos`). They paste
`https://app.forgeflow.app/account` into the URL bar.

The router's `switch (state)` arm matches `OperatorWebAcceptingTos`
and renders `TosAcceptScreen` with the active T&Cs version. URL is
treated as `/onboarding/tos`.

**Expected visual state.**

- `Key('operator_web_shell_scaffold')` — **not** present
- `Key('operator_web_account_placeholder')` — **not** present
- `Key('operator_web_step_pill')` — text reads
  `Step 4 of 4 — Authorize data access`
- `Key('operator_web_tos_summary')` — present
- `Key('operator_web_tos_body_panel')` — present, scrollable
- `Key('operator_web_tos_agreement_checkbox')` — present, unchecked
- `Key('operator_web_tos_submit')` — present, button labelled
  `Continue to Forge & Flow`

The Account surface only renders when the auth source emits
`OperatorWebCompleted`. Pre-completed states never expose it,
regardless of URL.

### Adversarial #3 (additional) — Staff role hits the post-onboarding shell

**Action.** A user whose role catalog is `<String>['staff']` (not
in `kOperatorWebAdmittedRoles`) lands on any post-onboarding URL
after authenticating. Auth source emits `OperatorWebForbidden`
carrying their session.

**Expected visual state.**

- `Key('operator_web_shell_scaffold')` — **not** present
- `Key('operator_web_account_placeholder')` — **not** present
- `Key('operator_web_forbidden_card')` — present
  - Title `Operator web access not available`
  - Body explains the operator owners / operator admins / location
    managers gate and points them at the Forge & Flow mobile app
- `Key('operator_web_forbidden_signout')` — `OutlinedButton`
  labelled `Sign out` that routes through
  `OperatorWebAuthSource.signOut()`

## Out-of-scope follow-ups (not done, intentionally)

- **`11W.0.live`** — bind a `FirebaseOperatorWebAuthSource` against
  the existing Phase 9 proxy routes (`/v1/auth/magic-link/verify`,
  `/v1/auth/password/*`, `/v1/auth/mfa/*`,
  `POST /v1/auth/tos/accept`). Until that ships, the deploy script
  refuses to publish a non-demo build (mirrors Phase 11A.0 →
  Phase 11A.1 cadence).
- **Browser URL synchronisation (Router 2.0)** — `11W.0` parses
  `?token=` once at startup; full path-changes-with-state would
  widen `11W.0` scope. Tests don't depend on URL sync, and the
  router's switch arm already enforces "state determines what
  renders" (see Adversarial cases).
- **TOTP QR-image widget** — `11W.0a` follow-up. The screen renders
  the otpauth URI as `SelectableText` so 1Password / Google
  Authenticator deep-link import still works on copy/paste.
