# 11W.5 Walkthrough — Audit Log surface

**Slice:** 11W.5 (Phase 11W — Operator Web Console; Self-Service Parity block)
**Mode:** demo (`OPERATOR_WEB_DEMO_AUTH=true`)
**Date:** 2026-05-06

This slice ships the web parity for the mobile Settings → Audit Log
section. The Operator Web Console gains an `Audit log` route in the
side-nav. Operator owners and managers see every change someone made
to their team, roles, hierarchy, and sign-in security, with the
locked filter set + cursor pagination + humanized action labels +
copyable target ids documented in the parity contract.

**Wiring honesty (read this first):** `11W.5` ships the Audit Log
*surface* against the in-memory `DemoWebTeamAuditLogGateway`. The
live HTTP gateway (`WebTeamAuditLogGatewayLive`) is built in this
slice and pinned by the gateway tests so the wire contract is fixed
today, but the live `FirebaseOperatorWebAuthSource` mixes the gateway
in via the new `OperatorWebTeamAuditLogGatewayProvider` interface in
the `11W.5.live` follow-up — the same gateway-follows-shell pattern
the rest of the 11W.x slices use. No new proxy routes were added; the
live gateway hits the existing `/v1/auth/audit-log` route Phase 9
already shipped. CSV export is rendered client-side and copied to the
clipboard on this slice (the self-service path has no server-side
exporter; admins gate that on `admin.audit_log.export` via the
`/v1/admin/auth/audit-log/export` route the 11A.14 slice uses).

**Cross-console pair:** `11A.14` Audit log tab (F&F Operations Console
audited support actions) is the matched sibling per the parity
contract acceptance gate #7 ("the pair lands together or both stay
active"). This walkthrough covers the operator-side surface only; the
F&F admin Audit Log inspect lands in `11A.14` against the same parity
contract section. Both must reach acceptance before either merges.

## What changed

### `lib/operator_web/services/web_team_audit_log_gateway.dart` (new)

Narrow `WebTeamAuditLogGateway` interface plus the live
`WebTeamAuditLogGatewayLive` impl built on `package:http`. Hits the
existing Phase 9 `/v1/auth/audit-log` route. The query shape exposes
the locked filter set:

- `actorUserIds` — multi-select user picker (live route currently
  clamps to caller; demo gateway applies it client-side; gateway
  forwards it as a query param so the proxy can adopt it server-side
  when it widens).
- `actions` — multi-select action enum. The live gateway maps a
  single-action selection onto the existing `event_kind` query param
  for the coarse server-side bucket and forwards the fine-grained
  action so future server-side filtering can land additively.
- `targetKind` / `targetId` — free-text contains filter (demo gateway
  applies locally; live gateway forwards on the wire).
- `timeWindow` — last 24h / 7d / 30d / 90d / custom date range.
  Mapped onto the existing `from` / `to` query params.
- `actorKinds` — `team_member` / `forge_admin` / `service_principal`.
  Self-service surface fixes this to `team_member`; the F&F admin
  surface (11A.14) widens it.

Cursor pagination is offset-based on the wire (the live route is
offset-based; the proxy clamp is 100 rows/page today) but the
gateway exposes opaque `next_cursor` strings to the screen so a
future swap to a server-side cursor leaves the screen contract
unchanged. The gateway encodes `offset:<int>` and the screen treats
the value as opaque.

CSV export pages through every matching row and renders RFC 4180
CSV client-side with the locked column order
(`created_at,action,actor_user_id,actor_display_name,actor_email,actor_kind,target_kind,target_id,admin_reason,payload`).
The `Idempotency-Key` is forwarded on the first page so a replay of
the same export hits the proxy `proxy_requests` UNIQUE-key cache.

`WebAuditLogActionLabels.labelFor` projects two label families:

- `team.*` actions (the new audit_logs.action enum) render in the
  verb-object form documented in `§ Audit Log`
  (`team.users.invite` -> Invited team member).
- `auth.*` events (the existing auth_events_audit ledger that mobile
  already renders) reuse the mobile mappings from
  `AuthEventLabels.labelFor` verbatim
  (`auth.user.signed_in` -> Sign-in,
  `auth.password_changed` -> Password changed,
  `auth.session_revoked` -> Session revoked,
  `auth.mfa_totp_enrolled` -> MFA enrolled (authenticator)).
  A unit test pins this mapping so future mobile changes catch the
  drift.

New server-side actions fall back to a humanized version of the raw
string so the screen stays readable.

### `lib/operator_web/services/demo_team_audit_log_gateway.dart` (new)

In-memory `DemoWebTeamAuditLogGateway` reading the shared fixture
file. Applies the full filter set client-side (multi-select actions,
multi-select actors, target_kind/target_id contains match, time
window). Idempotency-keyed export caches the CSV body and writes its
own `audit.export.requested` row so the export-is-itself-audited
rule renders in the walkthrough.

### `lib/operator_web/services/demo_team_fixtures.dart`

Extended additively with the ~50 audit-log entries the parity
contract § Demo-mode fixtures calls for. Spans 2026-04-06 → 2026-05-05
(the last 30 days), covers every action documented in
`WebAuditLogActions.catalog` (invite, role-grant, password-change,
mfa-enroll, session-revoke, soft-delete, etc.), and stamps a mix of
actors so the actor + action filter chips have variety.

### `lib/operator_web/widgets/audit_log_row.dart` (new)

One audit_logs row, rendered per the parity contract `§ Audit Log`
row shape:

- `created_at` in operator-local timezone (per
  `phase_7_55_time_boundary_contract.md`).
- Actor display_name + email.
- `actor_kind` chip (team / F&F admin / service) — self-service rows
  always render the `team` chip; the F&F admin path lights up the
  red `F&F admin` chip on its rows.
- Action humanized via `WebAuditLogActionLabels.labelFor`.
- Target `target_kind:target_id` with a copy-to-clipboard button
  (`operator_web_audit_log_row_<id>_copy_target`) that surfaces a
  snackbar confirming the paste-buffer write.
- Inline `admin_reason` line on `forge_admin` rows.
- `View payload` toggle that expands a pretty-printed JSON pane
  inline.

### `lib/operator_web/screens/audit_log_screen.dart` (new)

Operator Web Audit Log screen. Renders:

- Header (`operator_web_audit_log_subtitle`) explaining the surface.
- `Export CSV` button — gated on `team.audit_log.export` (with a
  role-tier fallback for the demo flavor and live bootstrap stage:
  `operator_owner` / `operator_admin`).
- Filters card (`operator_web_audit_log_filters`):
  - Time window chip row (24h / 7d / 30d / 90d / Custom range).
    The Custom chip opens `showDateRangePicker`; the picked range
    converts local-day boundaries to UTC inclusively so timezones
    west of UTC do not chop off the early hours of the local day
    (mirrors the mobile audit-log section's startOfDay/endOfDay
    helpers).
  - Action multi-select chip rail (`operator_web_audit_log_action_*`).
  - Actor multi-select chip rail (`operator_web_audit_log_actor_*`),
    populated dynamically from the actors surfaced on the latest
    page.
  - Target kind / Target id free-text fields
    (`operator_web_audit_log_filter_target_kind` /
    `operator_web_audit_log_filter_target_id`).
- Result list (`operator_web_audit_log_list`) paged 200 rows at a
  time, each row keyed `operator_web_audit_log_row_<entryId>`.
- Load-more button (`operator_web_audit_log_load_more`) wired to the
  cursor returned by the gateway.

The screen takes optional `idempotencyKeyFactory` + `copyToClipboard`
+ `onCsvReady` overrides so tests pin the idempotency key, the
clipboard call, and the (router-provided) Blob-anchor downloader
without reaching into platform plugins.

### `lib/operator_web/router/operator_web_router.dart`

- New nav id `kOperatorWebNavAuditLog = 'audit_log'`.
- New nav item between Sessions and Vendor connections.
- New `/audit-log` body branch instantiating `AuditLogScreen` with
  the resolved gateway.
- New `OperatorWebTeamAuditLogGatewayProvider` interface so the auth
  source can supply a live or demo gateway implementation.
- Router-owned lazy `DemoWebTeamAuditLogGateway` fallback so the
  demo flavor never crashes when an auth source forgets to mix in
  the provider.

### `lib/main_operator_web.dart`

`_DemoOperatorWebAuthSourceWithTeamSurfaces` now also implements
`OperatorWebTeamAuditLogGatewayProvider`. Live mode keeps returning
`FirebaseOperatorWebAuthSource`; the live gateway plumbing lands in
`11W.5.live`.

## Click path (numbered steps)

### Step 1 — Sign in on web

Open `app.forgeflow.app` in a browser tab. Sign in via the demo
magic link; the demo source lands on `/account` after onboarding.

**Expected:**

- The web shell renders the side nav with an `Audit log` entry
  between Sessions and Vendor connections.

### Step 2 — Click Audit log in the side nav

**User action:** click `Key('operator_web_nav_item_audit_log')`.

**Expected:**

- Body swaps to `Key('operator_web_audit_log_screen')`.
- `Key('operator_web_audit_log_filters')` renders with the time
  window chip row defaulting to `Last 30 days`.
- `Key('operator_web_audit_log_list')` renders the freshest 50
  fixture rows (the screen requests 200 per page; the demo gateway
  serves up to 50 in this fixture set).
- The newest row (`auth.user.signed_in` at 2026-05-05 14:00 UTC)
  renders first; the action label reads `Signed in`.

### Step 3 — Filter by team.users.invite

**User action:** click
`Key('operator_web_audit_log_action_team_users_invite')`.

**Expected:**

- The list narrows to invite rows only.
- `demo-audit-002` ("Invited team member" → avery.lopez) renders.
- `demo-audit-001` (the sign-in row) is gone.
- The chip is highlighted in the sunset accent color.

### Step 4 — Page forward

**User action:** scroll to the bottom of the list, click
`Key('operator_web_audit_log_load_more')`.

**Expected:**

- The next page of invite rows appends below the existing list.
  (In the demo fixture set this surfaces older invite rows like
  `demo-audit-008`, `demo-audit-016`, `demo-audit-021`.)
- The Load next page button hides once there are no more matching
  rows.

### Step 5 — Export CSV

**User action:** click
`Key('operator_web_audit_log_export_button')`.

**Expected:**

- The button label flips to `Exporting` while the export runs.
- A snackbar `Audit log CSV ready (forge_flow_audit_log_<ts>_utc.csv).`
  flashes.
- An export message ("Copied audit log CSV to your clipboard...")
  renders below the header.
- The list refreshes and the new top row reads `Exported audit log`
  with the CSV filename as the target id (the
  `audit.export.requested` row written server-side per the parity
  contract).

### Step 6 — Copy a target id

**User action:** click the copy icon on any row's target line
(`Key('operator_web_audit_log_row_<id>_copy_target')`).

**Expected:**

- A snackbar `Copied <target_id> to clipboard.` flashes.
- The clipboard now carries the row's stable id (e.g. an invite id
  or session id) so support tickets can paste it without retyping.

### Step 7 — Toggle the payload

**User action:** click `View payload` on any row
(`Key('operator_web_audit_log_row_<id>_payload_toggle')`).

**Expected:**

- The payload pane expands inline and shows the pretty-printed JSON
  body of the audit row's payload.
- The toggle label flips to `Hide payload`; clicking again collapses
  the pane.

## Permission gating evidence

The Phase 9 proxy route already enforces gates server-side. The
client-side gate in `kAuditLogViewPermissionKey` +
`kAuditLogViewAdmittedRoles` is the friendly-error layer per the UX
writing standard.

| Role                  | View audit log | Export CSV |
| --------------------- | -------------- | ---------- |
| `operator_owner`      | yes            | yes        |
| `operator_admin`      | yes            | yes        |
| `operator_manager`    | yes            | hidden     |
| `operator_supervisor` | forbidden      | hidden     |
| `operator_staff`      | forbidden      | hidden     |
| `location_manager`    | yes            | hidden     |

When the live `OperatorWebSession.permissions` snapshot is hydrated
by the proxy, the gate consults `team.audit_log.view` for read and
`team.audit_log.export` for export. The role-tier fallback above
applies only when the snapshot has not been hydrated yet (demo
flavor + live bootstrap stage).
