## What changed

### `lib/integrations/reservation/libro_reservation_adapter.dart` (NEW)

- `LibroReservationAdapter` implements `ReservationAdapter`.
- Capability profile declares: `vendorId='libro'`,
  `displayName='Libro Reserve'`, `category=reservation`,
  `authMode=oauth`, `grantScope=perLocation`,
  `webhookSupport=autoRegister`, `coversFieldExposed=false`,
  `partnershipGated=false`,
  `timestampPolicyDocId='libro'`.
- `kLibroLifecycleAtShip = 'documented'` exposes intent until
  `8.0.lifecycle` extends `VendorCapabilityProfile` with the enum.
- `LibroHttpClient` + `LibroReservationGateway` interfaces let the
  adapter stay free of `package:postgres` and `package:http` while
  binding to `OperatorScopedRepository.withTenant` semantics in
  production.
- `LibroIanaConverter` wires `IanaTimezoneConverter` for
  business-date projection and `package:timezone` for wall-clock →
  UTC conversion (Libro emits no tz hint per
  `vendor_timestamp_policy['libro']`).
- `pollIncremental` and `backfill` consult `command.sanityHook(...)`
  before every canonical fact write; returning `false` skips the
  write.
- `handleWebhook` does NOT re-call sanity (the framework enforces
  inline at step 4 of the dispatch sequence in
  `inbound_webhook_handler.dart`).
- Watermark is recorded after every successful page commit via
  `gateway.recordWatermark(...)` so a Cloud Run Job restart resumes
  from the last persisted cursor.
- `disconnect` calls `LibroHttpClient.unregisterWebhook` +
  `revokeCredential`, wipes the credential row, and preserves the
  watermark + canonical reservation facts (reconnect resumes from
  the last cursor).

### `lib/integrations/reservation/libro_webhook_signature_verifier.dart` (NEW)

- Implements `VendorWebhookSignatureVerifier` for Libro.
- Header: `X-Libro-Signature: t=<unix_seconds>,v1=<lowercase_hex_hmac_sha256>`.
- HMAC-SHA256 over `<timestamp>.<raw body>` (UTF-8).
- Constant-time compare via `constantTimeBytesEquals`.
- Returns the parsed timestamp so the framework's
  `kInboundWebhookReplayCeiling = 24h` enforces replay rejection.

### `test/integrations/reservation/libro_reservation_adapter_test.dart` (NEW)

- Eight test groups covering all six mandatory framework calls plus
  the connect → backfill → poll → disconnect → reconnect smoke and
  the malformed-webhook drop.

### `test/integrations/reservation/fixtures/libro_reservations_fixture.dart` (NEW)

### Step 3 — Adapter behavior is fixture-tested (no live HTTP yet)

- The adapter is exercised by
  `test/integrations/reservation/libro_reservation_adapter_test.dart`.
- Run: `flutter test test/integrations/reservation/`.
- Each test group corresponds to a row of the slice contract's
  Mandatory test discipline:
  1. **`sanityHook` call count** — `pollIncremental` + `backfill`
     both call `command.sanityHook(...)` exactly once per fixture
     row; backfill passes `isDeliberateBackfill: true`, polling
     passes `false`.
  2. **`sanityHook` reject path** — returning `false` skips the
     canonical fact write; `gateway.upserts` stays empty;
     `result.sanityDropped` matches the row count.
  3. **Idempotency replay** — same fixture page sequence twice →
     `gateway.upserts.length` unchanged; second
     `pollIncremental.recordsWritten == 0` because the
     `(vendor_id, vendor_entity_id, vendor_modified_at)` UNIQUE
     collapses the replay.
  4. **Watermark mid-batch resume** — fixture `_Fixture.crashAfterFirstPage`
     throws `StateError` on the second page request; the assertion
     `gateway.watermarks.last['cursor_token'] == 'cursor-page-2'`
     proves the first batch's watermark persisted before the throw.
  5. **Signature reject** — `LibroWebhookSignatureVerifier` returns
     `valid: false` for tampered body, tampered signature, missing
     header, or malformed `t=...,v1=...` shape. The framework's
     existing `inbound_webhook_handler_test.dart` covers the
     boundary mapping (verifier `valid: false` → 403 + dead-letter
     after 3 attempts).
  6. **Capability profile** — every required field declared and
     non-default; `lifecycle` constant `'documented'` matches the
     slice contract.
  7. **Test connection** — fixture sample populates
     `fieldMapping['party_size'] / ['reservation_at'] / ['status']`
     and completes well under 30 s on the offline path (no live
     HTTP).
  8. **Connect → backfill → poll → disconnect → reconnect smoke** —
     watermark cursor + last_modified_seen unchanged across the
     disconnect call; reconnect re-poll writes 0 fresh rows.

### Step 4 — Anchor scenario A — forged signature (covered by verifier reject + framework dead-letter)

- The fixture `signLibroWebhook(...)` computes the documented header
  shape. A test mutates the final hex character.
- **Widget under test:** verifier `LibroWebhookSignatureVerifier`.
- **Expected:** `WebhookSignatureVerification(valid: false,
  failureReason: 'signature mismatch')`.
- Framework boundary: when wired into `InboundWebhookHandler`, three
  consecutive 403 responses dead-letter the event. That dispatch
  sequence is owned by the framework slice's existing
  `test/integration/inbound_webhook_handler_test.dart`; the Libro
  verifier slots in transparently.

### Step 5 — Anchor scenario B — malformed payload

- The webhook fixture `wh-evt-malformed` posts an event envelope
  missing the `reservation` object.
- **Widget under test:** `LibroReservationAdapter.handleWebhook`.
- **Expected:** `HandleWebhookResult(recordsWritten: 0)`;
  `gateway.upserts.isEmpty`.
- Per V1 lean cut 2, malformed payloads drop at the boundary with a
  `connector_sync_log` row — no `parse_warnings` JSONB, no
  `parse_partial` flag.

### Step 6 — Anchor scenario C — future-dated event

- A poll fixture row would emit `reservation_at = now() + 5d` (out
  of scope for this slice's fixture set; covered by the framework's
  sanity-guard test
  `test/integration/inbound_webhook_handler_test.dart` "sanity drop:
  future-dated event" and by the adapter's `sanityHook` reject path
  in test group 1.2 above).
- **Expected:** `command.sanityHook(...)` returns `false`,
  `gateway.upserts` stays empty, the framework records
  `sanity_log.rule = 'opened_in_future'` and a
  `connector_sync_log.event_kind = 'sanity_drop'` row.

### Step 7 — Anchor scenario D — OAuth near-expiry

- The shared `oauth_refresh_cron.dart` is owned by the framework
  slice. The adapter's `disconnect` call exercises the
  `revokeCredential` path; the refresh cron exercises the proactive
  refresh path. Live verification of the refresh round-trip is
  deferred to `8R.LB.live.sandbox` (`live_verification_checklist.md`
  row "Token refresh.").
