# 9.8.email Walkthrough — Transactional email pipeline

**Slice:** `9.8.email` (Phase 9.8 — Compliance & Legal, email-provider lane)
**Mode:** F&F internal staging deploy + `kAdminDemoAuth = true` operator app for the rotation card
**Date:** 2026-05-04

This slice stands up SendGrid + the `EmailProvider` abstraction + 8 V1 templates + `email_outbox` durable queue + `email_event` delivery log + the `POST /v1/admin/integrations/email/test` admin route + 11A.4 SendGrid key rotation in the F&F Operations Console. Production cutover for live SendGrid sending waits on the operator-action checklist at the bottom (DNS records on `mail.forgeflow.app` + production SendGrid account + production API key); everything else is exercised in this walkthrough end-to-end on staging.

The `vendor_connection_auto_disabled` template ships in this slice as a Markdown file at `tool/advisor_proxy/email_templates/vendor_connection_auto_disabled.md` so the Markdown source is reviewable + unit-tested in `email_template_renderer_test.dart`, but the EMITTER that would enqueue an `email_outbox` row when Phase 8.0's OAuth refresh cron 3-strikes a vendor is **deferred per `project_v1_lean_cut_2_2026_05_03.md`**. Phase 8 lean cut 2 is explicit: at V1 the operator sees the `error` state in the admin Connected services card; the email follow-up lands when volume justifies the engineering work. The dispatcher's own 3-strike retry rule (`EmailOutboxDispatcher.maxAttempts = 3`) is for SendGrid send retries — unrelated to OAuth refresh strikes.

## What ships

### `lib/services/email/email_provider.dart`

- `EmailProvider` abstract class. `send(EmailSendRequest) → EmailSendResult` and `getDeliveryStatus(providerMessageId) → EmailDeliveryStatus`.
- `EmailFailureKind` taxonomy (`network`, `providerInternal`, `providerRateLimit`, `providerBadRequest`, `providerAuth`, `providerProtocol`, `unknown`) — dispatcher branches on this.
- `classifyEmailFailure(error)` maps thrown errors to a kind for accounting.

### `lib/services/email/sendgrid_email_provider.dart`

- Concrete SendGrid v3 adapter. Bearer-token auth, per-call API key fetch (no long-lived cache per Hard Promise #7), 202 → `X-Message-Id` surfacing, `mail_settings.sandbox_mode.enable` toggle, `Retry-After` honored on 429, GET `/v3/messages/<id>` → `EmailDeliveryStatusKind`.

### `lib/services/email/email_template_renderer.dart`

- `EmailTemplateRenderer.render(templateId, data)` returns `RenderedEmail{subject, htmlBody, textBody}`.
- `EmailTemplateIds.all` lists the 8 V1 template ids in slice-doc order. The constant `vendorConnectionAutoDisabled` carries a docstring noting the V1 deferral (this iteration's amendment).
- Tiny Markdown subset (paragraphs, headings, bullets, bold, italic, links). Variables interpolated through HTML-escape; missing variables raise `MissingTemplateVariableError`.

### `lib/services/email/email_outbox_dispatcher.dart`

- `drainBatch()` → `List<EmailDispatchOutcome>`.
- 3-strike retry on transient failures, immediate dead-letter on permanent failures (auth / bad-request / protocol / render).
- `EmailDispatchAlertSink` notified on dead-letter so the proxy log emits `email_dispatch.failed`.

### `db/migrations/202605040200_phase_9_8_email_provider.sql`

- `email_credentials`: single-row pgcrypto-envelope ledger; partial unique on `(provider_kind) where is_active`.
- `email_outbox`: durable queue with operator-leading partial index `(operator_id, status, scheduled_for) where operator_id IS NOT NULL`, system-only index `(status, scheduled_for) where operator_id IS NULL`, RLS leakproof wrapper policies (`app_current_operator()`), and the `email_outbox_notify` trigger emitting `pg_notify('email_outbox', …)` on every pending INSERT.
- `email_event`: SendGrid delivery webhook log; per-tenant RLS via join on `email_outbox`.
- `email_outbox_tick()` SQL function + `forge_email_outbox_tick` `pg_cron` schedule (`* * * * *`) — NOTIFY-only kickoff; the Dart dispatcher claims rows.

### `tool/advisor_proxy/email_templates/`

- `vendor_connection_auto_disabled.md` ships as a complete template; the wiring that would enqueue it is **deferred** per Phase 8 lean cut 2.

### Step 8 — Failure path: rotate to an invalid SendGrid key, exercise 3-strike

This step exercises the `EmailOutboxDispatcher` retry / dead-letter rule. The admin `Test connection` POST in Step 4 goes through the `EmailProvider` directly (no `email_outbox` enqueue), so to trigger the dispatcher we use the operator-invitation flow (the only V1-active enqueue path):

1. Stop the proxy. Set `SENDGRID_API_KEY` to a malformed value (e.g. `SG.invalid-token-revoked-9999`). Restart.
2. Trigger an operator invitation that enqueues an `email_outbox` row (the live trigger is `Phase 11A.1 operator creation`; for the walkthrough you can also `INSERT` directly via the admin SQL tool):
   ```sql
   INSERT INTO public.email_outbox (
     email_id, operator_id, recipient_email, template_id,
     template_data, status, scheduled_for
   ) VALUES (
     gen_random_uuid(), NULL, 'engineering+strike-test@forgeflow.app',
     'operator_invite_first_admin',
     '{"recipientName":"Strike Test","businessName":"Test Inc","setupUrl":"https://app.forgeflow.app/test","linkExpiryHumanReadable":"in 24 hours"}'::jsonb,
     'pending', now()
   );
   ```
3. The pg_cron tick fires `email_outbox_tick()` → `pg_notify('email_outbox_tick', …)`. The dispatcher claims the row via `SELECT … FOR UPDATE SKIP LOCKED` and calls `SendGridEmailProvider.send`.

**Expected after attempt 1:**

- SendGrid returns `401 Unauthorized` (or equivalent for the invalid key shape).
- `SendGridEmailProvider._classifyFailure` returns `EmailProviderException(kind: providerAuth, statusCode: 401)`.
- `EmailOutboxDispatcher._dispatchOne` sees `_isPermanent(providerAuth) == true` → outcome is `EmailDispatchStatusKind.failed`, `attemptCount = 1`.
- `repository.recordOutcome` runs `UPDATE email_outbox SET status='failed', attempt_count=1, last_error=<repr>, last_attempt_at=now() WHERE email_id=<id>`.
- `alertSink` fires with `EmailDispatchAlert{templateId: 'operator_invite_first_admin', failureKind: providerAuth, attemptCount: 1}`. The proxy log emits `email_dispatch.failed`.

> **Auth = immediate dead-letter:** providerAuth is in the permanent-failure set (alongside providerBadRequest and providerProtocol). Fresh rows fail-closed on the first attempt. The 3-strike rule applies to TRANSIENT failures.

To exercise the 3-strike rule explicitly, swap the key for one that produces a transient `502 Bad Gateway` (e.g. point `SENDGRID_API_KEY` at a SendGrid endpoint that's transiently down via DNS sinkhole, or use the test fixture `EmailProviderException(kind: providerInternal)` directly):

| tick # | dispatch outcome | row state after |
| --- | --- | --- |
| 1 | `pendingRetry` (`providerInternal`) | `status='pending'`, `attempt_count=1`, `last_error=…providerInternal…` |
| 2 | `pendingRetry` (`providerInternal`) | `status='pending'`, `attempt_count=2`, `last_error=…providerInternal…` |
| 3 | `failed` (`providerInternal`) | `status='failed'`, `attempt_count=3`, `last_error=…providerInternal…`, alert fires |

The dispatcher test `test/services/email/email_outbox_dispatcher_test.dart::3rd attempt failure flips to failed with alert` pins the exact transition; a row at `attempt_count = 2` whose 3rd attempt fails transiently flips to `failed` and surfaces a single `EmailDispatchAlert` to the sink.
