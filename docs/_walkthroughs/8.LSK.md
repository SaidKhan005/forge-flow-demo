## Click path

### Connect (happy path, demo-mode flip)

1. Operator opens **Settings → Vendor Connections**. The Vendor
   Connections widget renders one card per documented vendor.
2. Operator taps the card with `Key('vendor_picker_lightspeed_lsk')`,
   labelled **Lightspeed Restaurant K-Series**. The card chrome reads
   "Coming soon" until `8.LSK.live.sandbox` promotes the lifecycle to
   `sandbox_verified`; for the engineering slice the demo-mode build
   includes a debug-only "Sign in (demo)" button so the rest of the
   click-path is exercisable.
3. Operator taps **Sign in with Lightspeed** (or the demo-only
   variant). The flow opens the Lightspeed sandbox OAuth screen at
   `https://api.trial.lsk.lightspeed.app/oauth/authorize` (stubbed to
   the test-double `LightspeedLskOAuthClient.completeAuthorization`).
4. The stub returns:
   - `business_id: lsk-biz-7c2f`
   - `access_token_credential_id: cred-access-1`
   - `refresh_token_credential_id: cred-refresh-1`
   - `token_expires_at: now + 25 minutes`
   - `scopes: [orders-api, financial-api, offline_access]`
5. The card flips to **Connected**; the green check mark animates in.
   `connector_connection.metadata.business_id` reads `lsk-biz-7c2f`.
   `connector_sync_log` gains one row with `event_kind = 'connect'`.
6. The Vendor Connections widget enqueues a 60-day backfill (the
   adapter's `backfill` method runs against the
   `LightspeedLskOrdersClient` fixture). Five canonical sales rows
   land in the Postgres operator-scoped fact table:
   - `covers: 3`, `opened_at: 2026-05-04T22:45:00Z`,
     `closed_at: 2026-05-04T23:42:00Z`, `actual_sales: 142.55`
   - …4 more rows from the fixture batch.
   `business_date = 2026-05-04` (location-local, 4 AM rollover).
7. Operator returns to **Shift dashboard**. Sales / Covers / PPA
   cards flip from `MetricCardNotYetAvailable` to live numbers. The
   top-left honesty pill reads only "Labor: not yet connected" —
   Sales and Covers degradation lines drop because Lightspeed is
   live for both. Cards stay visually clean (no per-card chrome) per
   `metric_card_honesty_contract.md`.

### Forged-signature webhook → 403 + audit + no fact write

1. The vendor delivers a webhook to
   `https://api.forgeflow.app/v1/webhooks/lightspeed_lsk/<connection_id>`
   with payload claiming `business_id: lsk-biz-7c2f` and
   `accountFiscId: A65315.99`, **but the signature header has one
   nybble flipped** (test fixture
   `tamperedLightspeedLskWebhook`).
2. `InboundWebhookHandler.dispatch` step 1 runs
   `LightspeedLskWebhookSignatureVerifier.verify`. The verifier
   computes the expected HMAC-SHA256 over the raw body and runs
   `constantTimeBytesEquals` — the result is **false**.
3. The handler records a failed attempt via
   `gateway.recordFailedAttempt` (audit row written), returns
   `WebhookOutcome.signatureInvalid` with status code **403**.
4. **No canonical-fact write occurs.** `connector_sync_log` shows no
   `webhook_received` row for this `vendor_event_id`. Shift
   dashboard cards remain unchanged.

### Malformed payload → log row + dropped

1. The vendor delivers a webhook whose signature passes but the
   payload omits `accountFiscId`
   (test fixture `lightspeedLskMalformedSale`).
2. The handler reaches step 5 and calls
   `LightspeedLskPosAdapter.handleWebhook`. The adapter's
   `_projectCanonicalRecord` returns null because `accountFiscId` is
   missing.
3. The adapter returns `HandleWebhookResult(recordsWritten: 0)`. The
   framework's dispatch unwind writes a `connector_sync_log` row with
   `event_kind = 'webhook_received'`, `records_count = 0`.
4. **No canonical-fact write occurs.** Shift dashboard cards remain
   unchanged. No `parse_warnings` JSONB column is touched (V1 lean
   cut 2 deletes that channel).

### Future-dated event → log row + dropped via sanity hook

1. The vendor delivers a webhook whose signature passes and payload
   parses cleanly but `timeOfOpening` is 5 days in the future
   (test fixture `futureDatedLightspeedLskWebhook`).
2. `InboundWebhookHandler.dispatch` step 4 runs
   `VendorTimestampSanity.evaluate`. Rule 2 (`opened_in_future`)
   fires.
3. The framework writes a `sanity_log` row + `connector_sync_log`
   `event_kind = 'sanity_drop'` row. The handler returns
   `WebhookOutcome.sanityDropped` with status code **200**.
4. **The adapter's `handleWebhook` is not called.** No canonical-
   fact write. Shift dashboard cards remain unchanged.

### OAuth near-expiry → cron refreshes within 1 hour

1. The OAuth refresh cron runs at 5 minutes past every hour. The
   query `vendor_credentials.token_expires_at < now() + 24h` returns
   the Lightspeed K-Series row (TTL = 25 minutes; refresh window =
   24 hours).
2. The cron calls
   `LightspeedLskOAuthClient.refresh(refreshTokenCredentialId:
   cred-refresh-1)`. The stub returns a new envelope:
   - new access token credential id: `cred-access-2`
   - new (rotated) refresh token credential id: `cred-refresh-2`
   - `token_expires_at: now + 25 minutes`
3. The gateway atomically writes the new envelope; the prior
   ciphertext is discarded. `consecutive_refresh_failures` resets to
   0. `connector_sync_log` gains an `auth_refresh` row.

### Disconnect → reconnect preserves watermark

1. Operator opens **Settings → Vendor Connections** and taps
   **Disconnect** on the Lightspeed K-Series card.
2. The adapter calls
   `LightspeedLskWebhookClient.unregister(subscriptionId: sub-1)` —
   best-effort; vendor-side unregister failure does not block the
   local credential wipe.
3. The adapter calls
   `LightspeedLskOAuthClient.revoke(accessTokenCredentialId:
   cred-access-2)` — best-effort.
4. The gateway runs `wipeCredentialsAndDisconnect`:
   `connector_connection.status = 'disconnected'`, credentials
   wiped, **`connector_sync_watermark` row preserved**.
5. Shift dashboard cards flip back to `MetricCardNotYetAvailable`.
   The top-left honesty pill re-includes "Sales: not yet connected.
   Covers: not yet connected." Labor line stays.
6. Operator taps **Reconnect**; OAuth flow runs again. The adapter's
   first `pollIncremental` after reconnect passes the preserved
   `connector_sync_watermark.cursor_token` to
   `LightspeedLskOrdersClient.fetchSalesPage`. **No sale rows are
   re-fetched / re-written**; backfill picks up exactly where it
   left off (test
   `smoke: connect → backfill → poll → disconnect → reconnect`).
