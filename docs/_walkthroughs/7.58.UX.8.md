# 7.58.UX.8 Walkthrough — OPZ-aware row annotation on PRIMARY DRIVER card

**Slice:** 7.58.UX.8 (Phase 7.58 — Depth Wave, render-side wiring)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-05

This slice extends the per-axis dollar attribution shipped by 7.58.UX.1.
When the operator sees a favorable `+$32 cplh` row in the breakdown,
that row reads as a "labor savings" — but if actual CPLH crossed the
OPZ ceiling, those savings came at workload cost (Bold by Design Ch.
10: "When Productivity Is Too High"). 7.58.UX.8 surfaces that trade-off
inline by suffixing the row label with ` : team was stretched` whenever
the cplh / splh axis actual exceeds its OPZ ceiling.

The narrative on the card body already says this in plain English; the
row itself now matches.

## What changed

### `lib/widgets/lever_card.dart`

`LeverCardWidget` gains four optional named params:

- `actualCPLH: double?` — the row's actual CPLH for the displayed
  period.
- `opzCeilingCPLH: double?` — the ceiling of the active OPZ band.
- `actualSPLH: double?` — the row's actual SPLH counterpart.
- `opzCeilingSPLH: double?` — the SPLH ceiling counterpart.

All four default to `null`, which preserves the pre-7.58.UX.8 row
rendering exactly. Existing call sites that do not opt in stay green
without modification.

When `dollarImpactByAxis` is non-null, the params thread into
`_DollarAttributionSection`. Per-axis the section computes a strict
`actual > ceiling` predicate (inputs both non-null AND actual greater
than ceiling). When true and the axis label is `cplh` or `splh`, the
row's label is rendered as `'<axis> : team was stretched'` instead of
the bare label. The dollar amount widget is unchanged; the annotation
sits on the same line, separated from the axis label by a literal
space-colon-space `' : '`.

The predicate is intentionally per-axis: a stretched cplh row stays
stretched regardless of whether splh is in or out of band, and vice
versa.

### `lib/screens/variance/variance_this_week_tab.dart`

The `LeverCardWidget` call inside the PRIMARY DRIVER `SliverToBoxAdapter`
now passes `actualCPLH: weekData.avgCPLH` and `opzCeilingCPLH:
activeProfile?.opzCeilingCPLH` whenever the existing
`ActiveTargetProfileNotifier?` read returns a non-null profile. When
the notifier is out of scope (legacy widget tests), all four
annotation params resolve to `null` and the row renders unchanged —
the same backward-compat posture 7.58.UX.1 set when introducing the
per-axis breakdown.

`actualSPLH` and `opzCeilingSPLH` stay `null` here: `ActiveTargetProfile`
does not yet model an SPLH OPZ band, so the splh row's annotation
honestly stays off until the band is added. No silent re-modeling.

### `lib/screens/week_detail_screen.dart`

The `LeverCardWidget` call inside the closed-week PRIMARY DRIVER
`SliverToBoxAdapter` now passes `actualCPLH: week.avgCPLH` and
`actualSPLH: week.avgSPLH` from the closed `WeekRecord`. The two
ceiling params stay `null` because `WeekRecord` does not yet preserve
the OPZ ceiling alongside its locked target rates. This matches the
existing locked-target null fallback in the same Builder: legacy /
unpersisted ceiling fields render the row unchanged rather than
silently substituting the current active profile's ceiling, which
would mis-label closed weeks if the cycle's OPZ band has shifted
since.

### `test/widgets/lever_card_test.dart`

Five new tests pin the renderer contract:

1. **`cplh row appends ': team was stretched' when actual > ceiling AND
   cplh_up row > 0`** — fixture has `cplh_up = 50.0` (so the cplh axis
   passes the $1 row filter and contributes via the unfavorable half),
   `actualCPLH = 6.4`, `opzCeilingCPLH = 5.8`. Asserts
   `find.text('cplh : team was stretched')` returns
   `findsOneWidget` and bare `find.text('cplh')` returns `findsNothing`
   (the annotation replaces the bare label on that row).
2. **`cplh row renders unchanged when actualCPLH is null`** — same
   `dollarImpactByAxis` map but the four annotation params omitted.
   Asserts the bare `cplh` label renders and the annotated form does
   not.
3. **`cplh row renders unchanged when actualCPLH is at-or-below the
   ceiling`** — `actualCPLH = 5.8`, `opzCeilingCPLH = 5.8`. The strict
   `>` predicate returns false at equality; row renders unchanged.
4. **`favorable cplh row also annotates when actual > ceiling (the
   +$32 narrative case)`** — pins the doctrine's lead example:
   `cplh_down = -32.0` (favorable, renders as `+$32`), `actualCPLH =
   6.4 > opzCeilingCPLH = 5.8`. Asserts both `+$32` and `cplh : team
   was stretched` render. Confirms the predicate is sign-agnostic and
   that favorable dollars do not silently mask above-ceiling workload
   risk (Bold by Design Ch. 10).
5. **`annotation does NOT render when cplh axis is absent from
   attribution (hard gate 6: row must appear)`** — `cplh_down = 0.40`
   (sub-$1 → row filtered out), `actualCPLH = 6.4 > opzCeilingCPLH =
   5.8`. Asserts neither bare `cplh` nor the annotated form render —
   pins the depth wave plan's hard gate 6 ("OPZ adornment only
   renders when actual > ceiling AND that axis appears in the dollar
   attribution").

The six pre-existing 7.58.UX.1 tests keep their omitted-param posture
and stay green.

## Click path (text trace)

### Step 1 — Launch the operator app in demo mode

`lib/main_forgeflow.dart` boots the operator shell with
`MockIntegrationReplaySeed` attached and
`ActiveTargetProfileNotifier` provided at the app root. Default
business date `2026-03-27` (Fri W13).

**Expected:** the operator home renders with seeded current-week data.
`ActiveTargetProfileNotifier?.profile` is non-null at the Variance tab.
`profile.opzCeilingCPLH = 5.8`.

### Step 2 — Tap **Variance** → **This Week** tab

Scroll past `WEEK-TO-DATE vs PLAN` and `DOLLAR IMPACT` to reach the
`StickySectionDelegate('PRIMARY DRIVER')` header.

**Expected:**

- The PRIMARY DRIVER section renders a single `LeverCardWidget`.
- The `DOLLAR ATTRIBUTION` section (shipped 7.58.UX.1) renders with
  the primary sentence + per-axis breakdown rows.
- For seed mixes where `weekData.avgCPLH <= 5.8`, every row label
  renders bare (`cplh`, `splh`, etc.) — the pre-7.58.UX.8 layout is
  preserved.

### Step 3 — Drive `weekData.avgCPLH` above the OPZ ceiling

The simplest deterministic way to push WTD CPLH above 5.8 in the
demo seed is to reduce the seeded `totalFohHours` on the most recent
closed shift via `MockIntegrationReplaySeed.output.shiftRecords`
(or the equivalent fixture knob). After the shift closes,
`ShiftService.getWeekToDate` recomputes `avgCPLH = totalCovers /
totalFohHours` and the value crosses 5.8.

**Expected:**

- The PRIMARY DRIVER card re-renders.
- In the breakdown rows, the `cplh` row now reads
  `'<sign>$<value>'` followed by the label
  **`cplh : team was stretched`** instead of the bare `cplh` label.
- All other rows (`covers`, `ppa`, `splh`, `foh wage`, `boh wage`,
  `foh hours`, `boh hours`) are unchanged.
- The `splh` row stays bare because `actualSPLH` / `opzCeilingSPLH`
  are not threaded by this slice (no SPLH OPZ band on
  `ActiveTargetProfile` yet) — honest gap, no silent annotation.

### Step 4 — Verify per-axis isolation

Hold CPLH above ceiling but seed an SPLH that stays inside its band.
The `splh` row label stays bare; only the `cplh` row carries the
annotation. The predicate is per-axis, not card-wide.

### Step 5 — Open Week Detail (closed-week path)

From the operator home, navigate to **History** (or **Previous Weeks**
on the Variance shell) and tap any closed week tile.
`WeekDetailScreen(week: <WeekRecord>)` opens. Scroll to the
`StickySectionDelegate('PRIMARY DRIVER')` section.

**Expected:**

- For seed `WeekRecord`s without locked targets (legacy path):
  `dollarImpactByAxis` stays null, no `DOLLAR ATTRIBUTION` section
  renders, and the new annotation is not exercised.
- For post-lock records: the breakdown renders, but every row label
  renders bare. `WeekRecord` does not yet preserve the OPZ ceiling
  alongside its locked target rates, so `opzCeilingCPLH` /
  `opzCeilingSPLH` resolve to `null` and the predicate returns false.
  This is the documented honest gap: a future slice that persists
  the OPZ ceiling at week close will light up the annotation on the
  closed-week surface without further renderer change.

### Step 6 — Null fallback case (regression guard)

The widget test `cplh row renders unchanged when actualCPLH is null`
pins the omitted-param path: the bare `cplh` label still renders and
no annotation is shown. This is the path Variance > This Week takes
when `ActiveTargetProfileNotifier` is out of scope (legacy widget
tests) and the path Week Detail takes for every record (since the
ceiling is null at the call site).

## Permission gating evidence

No role-specific UX in this slice. Both call sites sit inside the
operator shell behind the operator-shell auth gate. 7.58.UX.8 only
adds renderer-layer text on an existing card; it does not add,
remove, or reorder any role gate, route, or permission key.

## Brand styling

`lib/theme/app_theme.dart` is unchanged. The annotation re-uses the
same `AppTextStyles.body13(color: AppColors.textSecondary)` style the
bare row label already uses — only the string content changes.
