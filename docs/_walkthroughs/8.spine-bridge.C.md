# 8.spine-bridge.C Walkthrough — F&F Ops Console Data Accuracy + Polling & Pricing

**Slice:** 8.spine-bridge.C (Phase 8 spine-bridge sprint)
**Mode:** `kDemoMode = true` (admin console; Firebase auth source bypassed by demo fixture)
**Date:** 2026-05-05

This slice ships the F&F-internal admin surfaces for the per-location
data accuracy seam introduced by Lane .A and consumed by Lane .B
(operator web). The admin surface has TWO top-level routes:

- **Tab 1 — Data accuracy** (`/data-accuracy`) — operator-controlled
  override view. F&F admin can inspect every operator-location's
  covers source per daypart and wage source, override either, and read
  the audit trail.
- **Tab 2 — Polling & pricing** (`/polling-pricing`) — F&F-controlled
  tier model. Tier definitions, per-(operator, location) tier
  assignments, margin rollup, and operator-submitted change requests.
  Operators NEVER see this tab.

Both routes are gated on `forge_admin` (super_admin) role; ff_support
sees them read-only. Every write inserts an `audit_logs` row with
`actor_kind = 'forge_admin'`, the diff payload, and the reason note.

## Architecture exposed

The admin surfaces sit between Firebase auth (admin shell) and the
Lane .A repositories:

```
Flutter admin web client (super_admin role)
            │
            ▼
DataAccuracyAdminGateway  (lib/admin/services/data_accuracy_admin_gateway.dart)
   ├─  in-memory impl     —  kDemoMode walkthrough + widget tests
   └─  HTTP impl (future) —  /v1/admin/data-accuracy/* + /v1/admin/polling-tiers/*
                              admin proxy → Lane .A repos → Postgres + audit_logs
```

The gateway interface is the seam this slice introduces. Every method
that mutates state takes `actorIsForgeAdmin: bool` and throws
`DataAccuracyAdminForbiddenException` when the flag is false. The
screen layer also gates the affordance on `editingEnabled` (super_admin
→ true; ff_support → false) so the UI matches the gateway contract.

## What changed

### `lib/admin/screens/per_location_data_accuracy_screen.dart` (new — Tab 1)

`PerLocationDataAccuracyScreen` — two cards in this order:

1. `PerLocationDataAccuracyTable` — sortable, multi-operator,
   multi-location. Edit affordance per row gated on `editingEnabled`.
2. `DataAccuracyAuditHistoryPanel` — most-recent-first list of every
   admin override + tier write captured by the gateway.

Override dialog collected the original three daypart fields (lunch /
dinner / late-night), wage source (vendor / manual_mix), and reason note
(required for the audit log). Supersession note: active Covers settings now
use keyed service-period rows; the named `covers_source_*` fields below are
historical walkthrough evidence, not the live schema shape. Submit → gateway
`overrideDataAccuracy(...)` → captured audit event with
`eventType = 'admin.data_accuracy.override'` and a diff that names exactly
which fields changed.

### `lib/admin/screens/polling_and_pricing_admin_screen.dart` (new — Tab 2)

`PollingAndPricingAdminScreen` — six cards top-to-bottom, matching
the contract Card 1 through Card 5 (plus the always-on-top explainer):

1. `PlainEnglishExplainerCard` — the verbatim two-paragraph contract
   text (`kExplainerParagraph1` / `kExplainerParagraph2` are public
   `static const` so test C pins them, plus an ordering assertion that
   this card renders ABOVE every other card).
2. `TierDefinitionsCard` — three tier subcards (standard / premium /
   custom). Each Edit button opens `TierDefinitionEditDialog` which
   embeds `PerVendorCadenceEditor` for the cadence-per-vendor JSONB.
   Submit on `standard` / `premium` requires a non-empty cadence map
   (the contract's "presets baked in code" rule). Custom is allowed
   empty — admin sets per-assignment.
3. `PerLocationTierAssignmentTable` — every operator-location appears
   here, with or without an existing assignment. Action button reads
   "Assign" for never-assigned rows, "Update" for assigned rows.
   Filter bar: tier, margin band, **location count** (single /
   multi), operator-name search. Assign / Update inline opens
   `_TierAssignmentDialog` (in the screen file) with tier dropdown +
   custom cadence editor + price/cost overrides + admin notes + reason
   note. Column labels carry the contract verbatim units —
   "Price override (USD/month)", "Cost basis override (USD/month)".
4. `MarginRollupCard` — "Total monthly tier revenue (USD)", "Total
   monthly vendor API cost basis (USD)", "Net monthly margin (USD)"
   (green/red/muted), "Margin %". Per-tier subtable + per-vendor
   cost subtable. Per-vendor allocation uses floor + carry-the-
   remainder so `sum(perVendor) == totalCost` exactly. Export-to-CSV
   button gated on `forge_admin`.
5. `TierChangeRequestsCard` — operator-submitted "Request tier change"
   tickets from Lane .B. Approve / Deny / Open negotiation buttons per
   pending row. Each resolution writes one audit event of type
   `admin.polling_tier_change_request.resolve`.
6. `DataAccuracyAuditHistoryPanel` (titled "Audit history") —
   Contract Card 5. Filtered to `admin.polling_*` /
   `admin.margin_rollup.*` events. Diff display formats cent fields
   (`monthly_price_cents`, `vendor_api_cost_estimate_cents_monthly`,
   `default_monthly_price_cents`) as dollar amounts (`$X.XX`) so
   "prior price → new price" reads in operator-friendly currency.
   Tab 1's audit panel is filtered to `admin.data_accuracy.*` so the
   two surfaces never bleed into each other.

## Permission gating evidence

The admin shell already authorizes the route table behind
`AdminAuthGate` per Phase 11A.0. This slice extends the catalog with
two routes both gated through the same `super_admin` / `ff_support`
membership check the rest of the admin console uses. Mutate
affordances on Tab 1 + Tab 2 are gated on the session carrying the
`super_admin` role; ff_support lands on the read-only branch (banner
renders, buttons absent). The gateway is the second line of defense:
every write throws `DataAccuracyAdminForbiddenException` if
`actorIsForgeAdmin: false` slips through.

## Documented contract gaps

These divergences are deliberate or unavoidable in Lane .C and are
called out here so the next slice does not re-flag them:

- **Walk-in handling mode column on Tab 1.** Closed by the
  2026-05-07 mobile reservation-demand slice: additive migration
  `202605080300_phase_8_data_accuracy_walk_in_settings.sql` adds
  `walk_in_handling_mode` and `walk_in_manual_entries` to
  `data_accuracy_settings`; the admin table now renders the mode and
  the override dialog can update it.
- **In-memory `assignTier` history shape vs production Postgres.** The
  in-memory gateway preserves the prior assignment in
  `_assignmentHistory` with `effectiveUntil` stamped, which mirrors
  the production Postgres path. Tests E now assert on this. The HTTP
  gateway (out of scope for this lane) will write the same shape.
- **Per-vendor API cost allocation in margin rollup.** The contract
  asks for "vendor name, total monthly cost basis across all locations".
  Each assignment carries a single `vendor_api_cost_estimate_cents_monthly`
  number rather than per-vendor breakdowns, so the rollup spreads the
  cost evenly across the cadence-named vendors using floor + carry-
  the-remainder. The per-vendor sum equals the per-assignment total
  exactly; the allocation is best-effort within the data the schema
  carries.
