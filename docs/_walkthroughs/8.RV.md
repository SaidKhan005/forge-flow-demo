# 8.RV Walkthrough — Revel Systems POS adapter (lifecycle = documented)

**Slice:** 8.RV (Phase 8 — engineer-all-17 Wave B; Revel POS adapter)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-03
**Lifecycle target at slice close:** `VendorLifecycle.documented`

This slice ships the Revel POS adapter at lifecycle = `documented` per
the engineer-all-17 doctrine
(`memory/project_phase_8_engineer_all_17_doctrine.md`). Live HTTP is
deferred to `8.RV.live.sandbox` / `8.RV.live.prod` (Wave D, rolling).
Operator-facing chrome stays at "Coming soon" until those slices
fire and promote the lifecycle.

The slice respects every Hard Promise from `CLAUDE.md`:

1. Pure transport — the adapter writes existing canonical Postgres
   tables only; no business logic in `lib/services/*` is touched.
2. Demo-mode persists — the same vendor-picker chrome renders in
   `kDemoMode = true` and `kDemoMode = false`, and the connect flow
   tells the operator the connection will flip them out of demo.
3. No app-logic changes before `7.58` — this slice adds a vendor
   adapter; metric formulas are untouched.
4. Per-operator isolation — every gateway call routes through
   `OperatorScopedRepository.withTenant(operatorId, locationId, ...)`.
5. Modular Adaptive Agentic RAG — n/a for this surface.
6. Recommendations not commands — n/a (POS data inflow only).
7. F&F holds provider keys server-side — wrong way around at the
   per-operator level: each operator issues their own Revel
   `client_id` / `client_secret` and the proxy stores ciphertext.
8. AI infra is general-purpose — n/a (POS adapter, not AI).
9. AI cost metering — n/a.
10. Backend phase ships operator-facing UX before phase close — the
    Vendor Connections widget already renders the "Coming soon" pill
    for `documented`-lifecycle vendors; this slice plugs Revel into
    that surface without UX-layer changes.

## What changed

### `lib/integrations/pos/revel_pos_adapter.dart` (NEW)

- `class RevelPosAdapter implements PosAdapter` — all 7 framework
  methods (`connect`, `testConnection`, `backfill`, `pollIncremental`,
  `handleWebhook`, `disconnect`, plus the capability-profile getter).
- `VendorCapabilityProfile`: `vendorId: 'revel'`,
  `category: pos`, `authMode: oauth`, `grantScope: perLocation`,
  `webhookSupport: autoRegister`, `coversFieldExposed: true`,
  `partnershipGated: false`, `modules: <String>[]`,
  `timestampPolicyDocId: 'docs/integrations/revel/field_mapping.md'`.
- `VendorLifecycle` enum (local declaration; deferred-merged into
  `lib/services/integration/integration_adapter_common.dart` by slice
  `8.0.lifecycle`'s integration commit). Adapter's `lifecycle` getter
  returns `VendorLifecycle.documented`.
- `documentedPerRevelV1` constant Map — every field-mapping
  assumption captured with vendor field path + canonical field +
  doc URL + retrieval date. Mirrored in
  `test/integrations/pos/fixtures/revel_orders_fixture.dart`
  (`documentedPerRevelV1FieldMapping`). `*.live.sandbox` diffs
  observed responses against this constant.
- `revelTimestampPolicy` constant — `AmbiguousTimestampConvention.asUtc`
  with documentation note. Local declaration, deferred-merged into
  `vendorTimestampPolicy` catalog at integration commit.
- `RevelTransport` abstract surface — production wires HTTP via the
  `*.live.*` slices; tests inject `_FakeRevelTransport`. Methods
  cover: `exchangeClientCredentials` (24h JWT bearer),
  `listOrders` (paginated backfill / poll), `fetchOrder` (webhook
  fall-through), `registerWebhook` (auto-register), `unregisterWebhook`
  (disconnect tear-down), `sampleOrder` (test-connection probe).
- `RevelGateway` abstract surface — production wires
  `OperatorScopedRepository`-backed implementation; tests inject
  `_FakeRevelGateway`. Adapter NEVER opens its own database
  connection or imports `package:postgres` (banned-items test pins
  this).
- `RevelOAuthRefresher implements VendorOAuthRefresher` — Revel's
  `client_credentials` grant has no refresh token; "refresh" is a
  fresh exchange. The framework's hourly cron picks up tokens with
  `token_expires_at < now + 24h` (`kRefreshExpiryHorizon`) and
  fires this implementation.

### `lib/integrations/pos/revel_webhook_signature_verifier.dart` (NEW)

- `class RevelWebhookSignatureVerifier implements VendorWebhookSignatureVerifier`
  — HMAC-SHA1 over the raw body, lowercase hex, `X-Revel-Signature`
  header. Constant-time compare via the framework's
  `constantTimeBytesEquals`.
- Returns `WebhookSignatureVerification.timestamp = null` because
  Revel does not bind a timestamp into the signed payload. The
  framework's 24h replay ceiling
  (`kInboundWebhookReplayCeiling`) is bypassed for Revel events;
  duplicate-write defense rests on the idempotency UNIQUE on
  `inbound_webhook_idempotency(vendor_id, operator_id, vendor_event_id)`.

### Step 3 — Engineering anchor: test-connection sample

The `*.live.sandbox` slice will exercise the full test-connection
path; this engineering slice exercises the offline path against
`revelSampleOrder`:

```
testConnection(operator, location, vendor='revel')
  → transport.sampleOrder(...)  # returns revelSampleOrder
  → _canonicalize({'order': revelSampleOrder})
  → TestConnectionResult(
      authValid: true,
      fieldMapping: {
        covers: 3,
        opened_at: 2026-05-02T18:45:00.000Z,
        closed_at: 2026-05-02T19:31:00.000Z,
        actual_sales: 64.30,
        vendor_entity_id: '8842301',
      },
      elapsedMs: < 30000,
    )
```

**Expected:** `result.fieldMapping['covers'] == 3`,
`result.fieldMapping['opened_at'] == '2026-05-02T18:45:00.000Z'`,
`result.fieldMapping['closed_at'] == '2026-05-02T19:31:00.000Z'`,
`result.elapsedMs < 30000`. Pinned in the test
"Test 6 — populates fieldMapping ... returns under 30s on the
offline path".

### Step 4 — Engineering anchor: forged signature → 403

```
verify({rawBody=revelOrderFinalizedRawBody, headers={x-revel-signature: 'beefcafe...' x40}})
  → WebhookSignatureVerification(valid=false, failureReason='X-Revel-Signature HMAC mismatch')

InboundWebhookHandler.dispatch(...) with the same tampered headers
  → WebhookOutcome.signatureInvalid (statusCode 403)
  → gateway.failedAttempts['evt-revel-tampered'] == 1
  → adapter.handleWebhook NOT called
  → no canonical-fact write
```

**Expected:** Pinned in the test "Test 4 (framework end-to-end) —
tampered HMAC dispatched through InboundWebhookHandler returns 403
+ audit row + no canonical write".

### Step 5 — Engineering anchor: malformed payload drop

If a webhook arrives whose `command.payload['order']` is missing or
not a Map, `handleWebhook` returns
`HandleWebhookResult(recordsWritten: 0)`. The framework's
`appendSyncLog` records the drop; no canonical fact is written.

**Expected:** No `parse_warnings` flag (banned per V1 lean cut 2).
The adapter either writes a clean canonical fact or refuses.

### Step 6 — Engineering anchor: future-dated event drop (sanity guard)

`revelFutureDatedOrder` has `created_date: '2026-06-15T12:00:00Z'`,
which is 30+ days after the test's `nowFixed`. When this row flows
through `pollIncremental` with the framework's `sanityHook`:

```
sanityHook(vendorEventId='9999', payload={'opened_at': '2026-06-15T12:00:00Z', ...}, isDeliberateBackfill: false)
  → false  (rule: opened_in_future)
adapter.pollIncremental skips writeOrderFact for this row
```

**Expected:** `result.sanityDropped >= 1`, no canonical fact for
order `9999`.

### Step 7 — Engineering anchor: OAuth near-expiry → 24h token refreshed by cron

Test `Test 8 — token at expires_at = now + 30min triggers refresh`
seeds `vendor_credentials` with `token_expires_at = nowFixed + 30min`.
The framework's `OAuthRefreshCronRunner.runOnce()`:

```
findExpiringCredentials(now=nowFixed, horizon=24h)
  → 1 row (revel)
RevelOAuthRefresher.refresh(...)
  → transport.exchangeClientCredentials(...)
  → VendorRefreshOutcome.success(newAccess=ciphertext('refreshed-token-001'),
                                 newExpiresAt=nowFixed + 24h)
gateway.recordRefreshSuccess(...)
```

**Expected:** `tick.refreshSuccesses == 1`,
`tick.refreshFailures == 0`,
`utf8.decode(newAccessCipher) == 'refreshed-token-001'`. Pinned in
"Test 8 — token at expires_at = now + 30min triggers refresh by the
cron runner".

### Step 8 — Engineering anchor: disconnect / reconnect watermark preservation

```
backfill → recordsWritten = 3, watermark commits per batch
poll (empty page) → records = 0, watermark advances lastModifiedSeen
disconnect → credentials wiped, watermark preserved
reconnect → fresh JWT bearer, same watermark visible to next poll
```

**Expected:** `postReconnectWatermark.lastModifiedSeen ==
preDisconnectWatermark.lastModifiedSeen`. Pinned in
"Test 5 — full lifecycle preserves watermark across disconnect /
reconnect".

## Permission gating evidence

which is invoked by the proxy's webhook + sync-worker surfaces. The
permission gate (`integrations.configure` per

admin route that wires the connect / disconnect calls; this slice
neither adds nor changes those routes. Live verification of the gate
is in `live_verification_checklist.md` row "Permission gate" (filled
in at `8.RV.live.sandbox`).
