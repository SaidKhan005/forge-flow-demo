# 11A.2 Walkthrough - Pricing tier admin surface

**Slice:** 11A.2 (Phase 11A - F&F Operations Console)
**Mode:** `-DemoMode` (admin Flutter Web client + in-memory pricing
gateway, no live Cloud Run admin proxy required)
**Date:** 2026-04-30

This walkthrough covers the admin click path called out in the 11A.2
prompt's *Admin walkthrough* section: viewing operator subscription
tier + cap rows, applying a tier template, editing one cap row
inline, and verifying that non-super-admin demo identities cannot
edit. The demo source is opt-in (`-DemoMode`); production binds the
live Firebase admin auth source + HTTP gateway
(`HttpPricingTierAdminGateway`) against the F&F admin Cloud Run
proxy.

## Authority files exercised

- `lib/main_admin.dart` - production binds
  `HttpPricingTierAdminGateway` against
  `--dart-define=ADMIN_PROXY_BASE_URI=...` and wraps
  `AdminConsoleApp` in `AdminConsoleServicesScope` with both the
  operator/location and pricing gateways. Demo falls back to the
  seeded in-memory pricing gateway in `admin_routes.dart`.
- `lib/admin/admin_routes.dart` - Pricing route promoted from
  placeholder to live; `AdminConsoleServicesScope` grows a
  `pricingTierGateway` field and a default in-memory demo seed.
- `lib/admin/screens/pricing_tier_admin_screen.dart` - the pricing
  tier + cap row admin surface. Templates, inline edits, read-only
  banner, action error banner.
- `lib/admin/models/pricing_tier_admin_models.dart` -
  `PricingOperatorBundle`, `UsageCapRow`, command shapes
  (`OperatorTierPatchCommand`, `UsageCapUpsertCommand`,
  `ApplyTierTemplateCommand`), and the locked
  `kPricingTierTemplates` catalog (Pilot / Starter / Premium / Elite
  / Pro / Enterprise) from
  `docs/phases/phase_11a/phase_11a_decision_register.md` Pricing
  Tier Model section.
- `lib/admin/services/pricing_tier_admin_gateway.dart` - HTTP +
  in-memory gateway implementations.
- `lib/infrastructure/persistence/postgres/repositories/usage_caps_repository.dart`
  - cross-operator `usage_caps` SELECT and UPSERT through
  `withSystem`. UPSERT writes the post-9.0Σ.g schema columns
  (`billing_owner_org_unit_id`, `scoped_org_unit_id`, `cap_id`
  surrogate, `staff_id`, `workflow_id`) and uses
  `ON CONFLICT ON CONSTRAINT usage_caps_two_slot_uq` so NULL
  staff/workflow rows still collide on the cap identity (UNIQUE
  NULLS NOT DISTINCT). UPSERT preserves `created_by`, rewrites
  `updated_by` to the actor user ID. The proxy gateway resolves the
  operator's root `org_units` row and passes its id for both
  billing-owner and scoped axes (corp pays for corp scope).
- `tool/advisor_proxy/advisor_proxy.dart` -
  `/v1/admin/pricing/operators`, `/v1/admin/pricing/operators/{id}`,
  `/v1/admin/pricing/operators/{id}/apply-template`, and
  `/v1/admin/pricing/usage-caps` route handlers; CORS preflight with
  `PUT` admitted via the dedicated `_setAdminPricingCorsHeaders`
  helper; method-scoped role gate (`kFfPricingAdminReadRoles` =
  `super_admin` + `ff_support` for `GET`; `kFfPricingAdminWriteRoles`
  = `super_admin` for `PATCH` / `PUT` / `POST`); structured 4xx for
  invalid `subscription_tier`, `tier_key`, money fields, and
  `no_primary_location`.
- `tool/advisor_proxy/proxy_bootstrap.dart` -
  `RepositoryPricingTierAdminProxyGateway` binding wired from
  `OperatorsRepository` + `UsageCapsRepository` +
  `OrgUnitsRepository` + `AuthEventsAuditRepository` over the admin
  pool. `applyTierTemplate` validates every precondition (operator
  exists, has `primary_location_id`, has a root `org_units` row)
  before any write so a failure can never leave the operator with
  `subscription_tier` partially flipped and no cap rows seeded.

## Demo identities

Demo auth fixture emails (any password accepted in demo mode); admit
decisions match the 11A.0 / 11A.1 walkthroughs.

| Email                         | Roles            | Admit decision     | Pricing edit |
| ----------------------------- | ---------------- | ------------------ | ------------ |
| `super.admin@forgeflow.test`  | `super_admin`    | Admin shell        | Yes          |
| `support@forgeflow.test`      | `ff_support`     | Admin shell        | No           |
| `operator@forgeflow.test`     | `operator_owner` | Forbidden surface  | n/a          |

The default in-memory pricing gateway is seeded with two fixture
operators (`Demo Diner Co.` and `Sunset Cafe Group`). Sunset Cafe
Group ships with a single Pilot-template cap row; Demo Diner Co. has
no caps yet so the walkthrough exercises the "Apply template" path.

`ff_support` is admitted to the admin shell but the Pricing route
proxy gates the edit endpoints to `super_admin` only. Production
wires the read-only screen for `ff_support` automatically: the
Pricing route builder reads `AdminConsoleServicesScope.adminAuthSource`
and uses a `StreamBuilder` over `source.stream` to compute
`editingEnabled = roles.contains('super_admin')` on every auth state
change. `main_admin.dart` always wraps `AdminConsoleApp` with
`AdminConsoleServicesScope`, plumbing the source for both demo and
live modes; the demo `support@forgeflow.test` fixture lands on the
read-only branch end-to-end. The behaviour is asserted by
`test/admin_pricing_tier_screen_test.dart` test
`admin shell with ff_support source renders pricing in read-only
mode` (and the `super_admin` counterpart).

Launch the admin console with `-DemoMode -Device chrome` and sign in
as `super.admin@forgeflow.test`.

**Expected:** branded admin shell renders with the side nav
including a `Pricing` item that is now live (no longer the
"Tier admin lands in 11A.2" placeholder subtitle).

### Step 2 - Open Pricing

Click `Pricing` in the side nav.

**Expected:**

- Body region renders the new `Pricing` surface
  (`Key('admin_pricing_screen')`).
- Header reads `Pricing` with a subtitle
  `Subscription tier + per-(operator, location, usage_class) usage
  caps. Apply a tier template to seed defaults, or edit individual
  cap rows inline.`.
- Operator list (left column) shows the two seeded operators,
  `Demo Diner Co.` (tier `launch`, 0 cap rows) and `Sunset Cafe
  Group` (tier `pilot`, 1 cap row).
- Detail card (right column) defaults to `Demo Diner Co.`. Detail
  rows show subscription tier, preferred currency, primary location.
  A `Tier templates` row exposes six outlined buttons: `Pilot`,
  `Starter`, `Premium`, `Elite`, `Pro`, `Enterprise`.
- A `Usage caps` card below shows the empty-state message
  "No cap rows yet. Apply a tier template to seed defaults, or add
  cap rows individually." plus an `Add cap row` button.

### Step 3 - Apply the Premium template

Click the `Premium` button under `Tier templates`.

**Expected:** a confirmation dialog opens
(`Key('admin_pricing_confirm_dialog')`) with the title
`Apply Premium template?` and a body summarising the change
("Sets subscription tier to premium and replaces 1 cap row on Demo
Diner Co. ..."). Click `Apply`.

**Expected:**

- The dialog closes.
- A `Premium template applied.` SnackBar shows.
- The detail card subscription tier flips to `premium` and the cap
  row card now shows one row keyed off `advisor_qa` with monthly cap
  `$200.00` and per-call cap `$0.20`. `updated by` shows the actor
  user id.
- The operator list row count text grows to `1 cap row`.

### Step 4 - Edit the cap inline

Click the pencil icon on the new `advisor_qa` row.

**Expected:** the `Edit cap row` dialog opens
(`Key('admin_pricing_cap_dialog')`) with `Usage class`, `Monthly cap
(USD)`, `Per-invocation cap (USD)` populated from the existing row.
The `Usage class`, `Staff ID`, and `Workflow ID` fields are
disabled because the upsert is keyed on those axes plus the location.

Change `Monthly cap (USD)` to `250.00`, click `Save`.

**Expected:**

- The dialog closes.
- A `Cap row updated.` SnackBar shows.
- The cap row tile re-renders with `$250.00 monthly`.

Click `Add cap row` on Demo Diner Co.'s `Usage caps` card.

**Expected:** workflow rows appear (`workflow_pl`, `workflow_schedule`)

### Step 7 - Verify support identity sees read-only Pricing

Sign out, sign in as `support@forgeflow.test`.

**Expected:** the admin shell still renders (`ff_support` is
admitted to the console). Click `Pricing`. In live mode the Pricing
screen issues `GET /v1/admin/pricing/operators`, which the proxy
admits because `ff_support` is in `kFfPricingAdminReadRoles`. The
data renders, and the screen is in **read-only mode**: the
`View-only: pricing edits require the super_admin role.` banner
shows (`Key('admin_pricing_readonly_banner')`), the `Add cap row`
button is absent, the six tier-template buttons are absent, and
every cap row's `Edit` icon is absent. Asserted by
`test/admin_pricing_tier_screen_test.dart` test
`admin shell with ff_support source renders pricing in read-only

`test/advisor_proxy_test.dart` test
`11A.2 GET /v1/admin/pricing/operators admits ff_support (read-only)`.

Server-side defence-in-depth: any edit attempt that bypassed the UI
would still be rejected by the write-only gate
(`kFfPricingAdminWriteRoles`), asserted in
`test/advisor_proxy_test.dart` tests
`11A.2 PATCH .../operators/{id} rejects ff_support with 403`,
`11A.2 PUT /v1/admin/pricing/usage-caps rejects ff_support with 403`,
and `11A.2 POST .../apply-template rejects ff_support with 403`.

### Step 8 - Verify non-admin fail-closed

Sign out, sign in as `operator@forgeflow.test`.

**Expected:** the branded forbidden card renders. The Pricing

## Permission gating evidence

- Client side (admin console): the pricing route is only reachable
  when the auth gate admits the caller (`super_admin` or
  `ff_support`); `operator@forgeflow.test` lands on the forbidden
  card. The screen exposes an `editingEnabled` flag (default `true`)
  that hides every mutate affordance and renders a `View-only:
  pricing edits require the super_admin role.` banner; the read-only
  branch is asserted in `test/admin_pricing_tier_screen_test.dart`.
- Server side (proxy): every `/v1/admin/pricing/*` request verifies
  the Firebase bearer token through `_resolveVerifiedClaimsOrWrite`
  and then evaluates a method-scoped role set —
  `kFfPricingAdminReadRoles` (`super_admin` + `ff_support`) for
  `GET`, `kFfPricingAdminWriteRoles` (`super_admin` only) for every
  mutation method. The split lets `ff_support` load the read-only
  pricing view live without weakening the billing-posture write gate.
  Pricing routes use a dedicated `_setAdminPricingCorsHeaders` helper
  whose `Access-Control-Allow-Methods` includes `PUT` (the
  `/v1/admin/pricing/usage-caps` upsert verb); the 11A.1
  operator/location helper stays unchanged. Asserted by
  `test/advisor_proxy_test.dart` 11A.2 group tests for
  `operator_owner` GET rejection (403), `ff_support` GET admission
  (200), `ff_support` PATCH / PUT / POST rejection (403),
  unauthenticated (401), CORS preflight `PUT` admission, invalid
  `subscription_tier` (400), invalid `tier_key` (400), invalid
  monthly cap (400), and `no_primary_location` (400 via
  `PricingTierAdminGatewayValidationError`).

## Boundary checks

- No Phase 9 operator Settings/Team/MFA/org hierarchy files were
  touched. `lib/screens/auth/`, `lib/screens/settings*`,
  `lib/screens/team/`, and `lib/auth/` are unchanged.
- The 11A.1 admin operator/location surface (`/v1/admin/operators`,
  `/v1/admin/locations`) is untouched. The new pricing routes live
  on a disjoint path prefix (`/v1/admin/pricing/*`) and do not
  reorder any existing route handlers.
- `admin_routes.dart` only promotes the Pricing route from
  placeholder to live and adds a service lookup
  (`pricingTierGatewayOf`); the rest of the catalog and order is
  preserved.
- `main_admin.dart` only wires the pricing gateway into
  `AdminConsoleServicesScope`; the existing fail-closed live wiring,
  Firebase admin auth, and demo-mode behaviour is preserved.
- `tool/advisor_proxy/advisor_proxy.dart` only adds
  `/v1/admin/pricing/*` constants, dispatch, validation, CORS, and
  the gateway interface. Existing `/v1/admin/operators` and auth
  routes are untouched.
- `tool/advisor_proxy/proxy_bootstrap.dart` only binds the new
  pricing repository / gateway into production bindings; auth and
  operator/location bindings are untouched.
- Tier templates exposed in the screen are exactly the locked six
  from the decision register (Pilot, Starter, Premium, Elite, Pro,
  Enterprise); proxy + screen catalogues are pinned by tests
  (`test/admin_pricing_tier_gateway_test.dart` test
  `contains exactly the locked six tiers` and proxy 11A.2 group
  `unknown_tier_template` rejection).
- Admin Flutter never accesses Postgres directly. The screen calls
  the gateway, the production gateway is `HttpPricingTierAdminGateway`,
  the proxy delegates to `RepositoryPricingTierAdminProxyGateway`
  which is the only path that reaches `usage_caps` /
  `operators` / `org_units` rows.
- `usage_caps` writes target the post-9.0Σ.g schema: the upsert
  inserts/updates `billing_owner_org_unit_id` and `scoped_org_unit_id`
  (NOT NULL after the constraint flip) and uses
  `ON CONFLICT ON CONSTRAINT usage_caps_two_slot_uq` to honour the
  UNIQUE NULLS NOT DISTINCT contract on the wider logical key. Both
  org-unit axes resolve to the operator's root `org_units` row for
  the launch UX (corp pays for corp scope).
- `applyTierTemplate` validates every precondition (operator exists,
  has `primary_location_id`, has a root `org_units` row) BEFORE
  writing. A 400 from `no_primary_location` or `no_org_unit_root`
  cannot leave the operator with `subscription_tier` partially
  flipped and no cap rows seeded.
- `AdminConsoleServicesScope` is now mounted in both demo and live
  modes from `main_admin.dart` so the route builder always has
  access to the `AdminAuthSource` for role-based UI gating.
- Every admin write threads `actorUserId` into `created_by` /
  `updated_by` and into the `auth_events_audit` row inserted via
  `AuthEventsAuditRepository.insertSystemEvent` under an
  `admin.pricing.*` event type with the
  `admin.pricing.<METHOD>:<actor>:...` reason string.
- No tracker updates and no commits.
