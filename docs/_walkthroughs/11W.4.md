# 11W.4 Walkthrough — Sessions surface

**Slice:** 11W.4 (Phase 11W — Operator Web Console; Self-Service Parity block)
**Mode:** demo (`OPERATOR_WEB_DEMO_AUTH=true`)
**Date:** 2026-05-05

This slice ships the web parity for the mobile Settings → Active
Sessions section. The Operator Web Console gains a `Sessions` route
in the side-nav. Operator owners, admins, and any team member with
`team.session.force_logout` see two stacked sections: their own
active sessions plus every team-member session within scope. Other
team members see only their own sessions. Mobile and web sessions
appear together so the operator can revoke either from one place.
Revoking the current web session triggers `signOut()` only after
the proxy returns 200, mirroring the mobile click path.

**Wiring honesty (read this first):** `11W.4` ships the Sessions
*surface* against the in-memory `DemoWebTeamSessionsGateway`. The
live HTTP gateway (`WebTeamSessionsGatewayLive`) is built in this
slice and unit-tested against `MockClient` so the wire contract is
pinned today, but the live `FirebaseOperatorWebAuthSource` mixes
the gateway in via the new
`OperatorWebTeamSessionsGatewayProvider` interface in the
`11W.4.live` follow-up — the same gateway-follows-shell pattern
Phase 11A.0 → 11A.1 used. No new proxy routes were added; the live
gateway hits the existing `/v1/auth/sessions`,
`/v1/auth/team/sessions`, and `/v1/auth/session/revoke` routes
Phase 9 already shipped.

**Cross-console pair:** `11A.13` Sessions tab (F&F Operations
Console Roles + Hierarchy + Sessions inspect) is the matched
sibling per the parity contract acceptance gate #7 ("the pair
lands together or both stay active"). This walkthrough covers the
operator-side surface only; the F&F admin Sessions inspect lands
in `11A.13` against the same parity contract section. Both must
reach acceptance before either merges.

**Privacy posture:** the `WebTeamSessionEntry` shape exposed by
the gateway carries no `ip` field at all — the proxy may include
one in its response payload, but the gateway drops it at the seam
so the screen has no path to render it. The screen renders the geo
hint at city + country granularity only. The widget test pins this
by walking every rendered `Text` widget and asserting none of them
match a dotted-quad IPv4 substring; the gateway test pins it
structurally (`WebTeamSessionEntry.ip` does not exist) so a future
schema regression cannot leak one through.

## What changed

### `lib/operator_web/services/demo_team_fixtures.dart`

Extended additively with the 4-row session ledger snapshot the
parity contract § Demo-mode fixtures calls for. Two rows belong to
the demo owner (web + mobile, walkthrough's "concurrent web +
mobile" step), one to the Downtown manager (mobile only), one to
the North Loop location manager (mobile only). Each fixture row
carries a city-level geo hint (Toronto / Mississauga + CA) and
deliberately omits IP. New constants:

- `kDemoTeamSessionThisSessionId` — pins the row the demo flavor
  treats as the current web session so `(this session)` lights up
  on a known row.
- `kDemoTeamSessionOwnerMobileId` — pins the row the walkthrough
  revokes first so the mobile device drops to login while the web
  session keeps rendering.

### `lib/operator_web/services/web_team_sessions_gateway.dart` (new)

Narrow `WebTeamSessionsGateway` interface plus the live
`WebTeamSessionsGatewayLive` impl built on `package:http`. Hits the
existing Phase 9 routes:

- `GET  /v1/auth/sessions`        — actor's own sessions.
- `GET  /v1/auth/team/sessions`   — team-wide sessions, gated
  server-side on `team.session.force_logout`.
- `POST /v1/auth/session/revoke`  — revoke a single session,
  carries `Idempotency-Key`.

Every revoke accepts a caller-minted `Idempotency-Key` and threads
it through as the request header. The gateway never mints keys
internally so the proxy `proxy_requests` UNIQUE-key replay surfaces
the original write on retry. `WebTeamSessionsError.isCannotRevokeSelf`
is the typed flag the F&F admin path's `validation_failed/cannot_revoke_self`
maps to so a future cross-console caller can react without
string-matching. No `dart:io`, no `sqflite`.

### `lib/operator_web/services/demo_team_sessions_gateway.dart` (new)

In-memory `DemoWebTeamSessionsGateway` reading the shared fixture
file. `listOwnSessions` strips the `target_user_*` columns to mirror
the live route shape. `listTeamSessions` returns every fixture row
with the target-user identity attached. Revokes cache the response
by idempotency key so a re-submission of the same revoke returns
the original outcome rather than mutating again.

### `lib/operator_web/screens/sessions_screen.dart` (new)

Operator Web Console Sessions screen. Renders:

- Header (`operator_web_sessions_screen` →
  `operator_web_sessions_subtitle`) explaining mobile + web
  sessions appear together.
- `Your sessions` section
  (`operator_web_sessions_own_section`, always visible) — one row
  per `auth_sessions` row belonging to the actor. The row whose
  `sessionId` matches the `currentSessionId` provided by the auth
  source carries the `(this session)` chip
  (`operator_web_sessions_this_chip`). Revoking that row triggers
  `onSignOut()` after the gateway returns 200; revoking any other
  row refreshes the list and surfaces a confirm snackbar.
- `Team sessions` section
  (`operator_web_sessions_team_section`, conditional) — visible
  only when `OperatorWebSession.permissions` carries
  `team.session.force_logout`, with an `operator_owner` /
  `operator_admin` role-tier fallback for the demo flavor and the
  live bootstrap stage. Each row shows the target user's display
  name + email above the device label so the actor knows whose
  session they are about to end.

Each row exposes:

- Device fingerprint as `deviceLabel` (browser + OS) with a
  `userAgent` fallback.
- Geo hint as `city, country` only — the gateway drops the raw IP
  and the rendered text never carries a dotted-quad substring (see
  privacy posture above).
- `last_active_at` humanized to `just now` / `Nm ago` / `Nh ago` /
  `Nd ago` / `Nw ago` / `Nmo ago` so a glance answers "is this
  device live."
- `Revoke` button (`operator_web_sessions_revoke_<sessionId>`)
  that mints a fresh idempotency key per click and threads it
  through the gateway. The current session row shows
  `Sign out this session` instead of `Sign out`.

### `lib/operator_web/router/operator_web_router.dart`

- New nav id `kOperatorWebNavSessions = 'sessions'`.
- New nav item between Members and Vendor connections.
- New `/sessions` body branch instantiating `SessionsScreen` with

## Click path (numbered steps)

### Step 1 — Sign in on web AND mobile concurrently

Open `app.forgeflow.app` in a browser tab. Sign in via the demo
magic link. Side-by-side, sign in on the Forge and Flow mobile app
under the same operator owner identity. Both sessions are now
active.

**Expected:**

- The web shell renders the side nav with a `Sessions` entry between
  Members and Vendor connections.

### Step 2 — Click Sessions in the side nav

**User action:** click `Key('operator_web_nav_item_sessions')`.

**Expected:**

- Body swaps to `Key('operator_web_sessions_screen')`.
- `Key('operator_web_sessions_own_section')` renders with two rows:
  the owner web session (with the `(this session)` chip via
  `Key('operator_web_sessions_this_chip')`) and the owner mobile
  session.
- `Key('operator_web_sessions_team_section')` renders below with
  the Downtown manager + North Loop location manager mobile
  sessions, grouped under each member's display name + email.

### Step 3 — Revoke the mobile session

**User action:** click
`Key('operator_web_sessions_revoke_demo-session-owner-mobile')`.
The confirm dialog (`Key('sessions_confirm_dialog')`) opens. Click
`Key('sessions_confirm_dialog_confirm')`.

**Expected:**

- Snackbar `Signed out Forge and Flow on iPhone.` flashes.
- The mobile row vanishes from the own-sessions section.
- On the mobile device, the next request fails the refresh-token
  check and the app drops to the login screen (this is the live
  proxy + Phase 9 ledger path; demo mode mirrors the snackbar but
  cannot drop a real device).

### Step 4 — Revoke the current web session

**User action:** click
`Key('operator_web_sessions_revoke_demo-session-owner-web')`. The
button label reads `Sign out this session` for this row. The
confirm dialog opens with the body
`Signing out this session will return you to the welcome screen.
You can sign back in anytime.` Click
`Key('sessions_confirm_dialog_confirm')`.

**Expected:**

- The gateway returns 200.
- The router immediately calls `OperatorWebAuthSource.signOut()`
  and the welcome screen
  (`Key('operator_web_welcome_token_field')`) re-renders.

### Step 5 — Permission gate negative path

**User action:** sign back in on web as the demo
`location_manager` (via
`DemoOperatorWebAuthSource.completedAsLocationManager()` —
already exposed by the auth source for the `11W.7` Account
read-only walkthrough). The widget test additionally pins
`operator_supervisor` and `operator_staff` against the same code
path so the role-tier fallback for non-owner roles is exercised.

**Expected:**

- `Key('operator_web_sessions_screen')` renders.
- `Key('operator_web_sessions_own_section')` is visible.
- `Key('operator_web_sessions_team_section')` is NOT rendered (the
  actor lacks `team.session.force_logout`).

## Permission gating evidence

The Phase 9 proxy routes already enforce role + permission gates
server-side. The client-side gate in
`kSessionsTeamForceLogoutPermissionKey` +
`kSessionsTeamForceLogoutAdmittedRoles` is the friendly-error
layer per the UX writing standard.

| Role                  | Own sessions | Team sessions |
| --------------------- | ------------ | ------------- |
| `operator_owner`      | read+revoke  | read+revoke   |
| `operator_admin`      | read+revoke  | read+revoke   |
| `operator_manager`    | read+revoke  | hidden        |
| `operator_supervisor` | read+revoke  | hidden        |
| `operator_staff`      | read+revoke  | hidden        |
| `location_manager`    | read+revoke  | hidden        |

When the live `OperatorWebSession.permissions` snapshot is
hydrated by the proxy, the gate consults
`team.session.force_logout` for the team-sessions section. The
role-tier fallback above applies only when the snapshot has not
been hydrated yet (demo flavor + live bootstrap stage).
