### 4. Adversarial: forged Aloha (NCR Voyix) webhook signature

- A bad actor sends a forged Aloha webhook to
  `/v1/webhooks/aloha_ncr_voyix/<operator_id>/<location_id>`.
- The proxy invokes `InboundWebhookHandler.dispatch`. The
  `AlohaNcrVoyixWebhookSignatureVerifier.verify` call returns
  `valid = false`,
  `failureReason = 'HMAC mismatch on NCR-Webhook-Signature header'`.
- Expected outcome:
  - **Widget under test:** none (server-side flow).
  - HTTP status `403`.
  - `WebhookOutcome.signatureInvalid`.
  - `inbound_webhook_idempotency.attempt_count` increments to 1.
  - No canonical fact written.
- After three forged retries: `inbound_webhook_dead_letter` row
  with `failure_kind = 'signature_invalid'`. No DLQ tile in
  observability admin (V1 lean cut 2 trim); the row stays for
  forensic read by support via the proxy debug console.

### 5. Adversarial: malformed Aloha (NCR Voyix) payload

- NCR Voyix (or a forged source) sends a payload with the expected
  signature but an unexpected field shape (e.g., `numberOfGuests`
  is a JSON object instead of an int).
- Expected outcome:
  - **Widget under test:** none.
  - The adapter's `_canonicalize` produces a `covers` field of the
    wrong type; `factSink.upsertCheckFact` throws when the production
    sink validates against the canonical fact schema.
  - `WebhookOutcome.adapterError`.
  - HTTP status `500` so NCR Voyix retries.
  - `inbound_webhook_idempotency.attempt_count` increments;
    after three failures the event lands in
    `inbound_webhook_dead_letter` with
    `failure_kind = 'adapter_error'`.
  - Queue is NOT poisoned. **No `parse_warnings` or `parse_partial`
    is recorded** (V1 lean cut 2 removed those columns).

### 6. Adversarial: future-dated Aloha (NCR Voyix) event

- NCR Voyix sends a webhook with `openedAt = now() + 5 days`.
- The handler runs steps 1-3 (signature, binding, idempotency) all
  green. Step 4 — vendor timestamp sanity guard — fires.
- Expected outcome:
  - **Widget under test:** none.
  - `VendorTimestampSanity.evaluate` returns `failed = true`,
    `rule = SanityRule.openedInFuture`,
    `rule!.sqlValue = 'opened_in_future'`.
  - `WebhookOutcome.sanityDropped`.
  - HTTP status `200` (we accept the request from NCR Voyix's
    perspective; we just never write a canonical fact).
  - `sanity_log` row written with `rule = 'opened_in_future'`,
    `payload_summary` carrying `opened_at` + `now`.
  - `connector_sync_log` row written with
    `event_kind = 'sanity_drop'`.
  - No canonical fact written. The dashboard's
    business-date-2026-W18-Mon view stays clean.

### 7. Adversarial: closed_at < opened_at

- NCR Voyix sends a webhook with `closedAt` an hour BEFORE
  `openedAt`.
- Expected outcome:
  - `VendorTimestampSanity.evaluate` returns `failed = true`,
    `rule = SanityRule.closedBeforeOpened`,
    `rule!.sqlValue = 'closed_before_opened'`.
  - `WebhookOutcome.sanityDropped`.
  - `sanity_log` row written with
    `rule = 'closed_before_opened'`.
  - `connector_sync_log` row written with
    `event_kind = 'sanity_drop'`.
  - No canonical fact written.

### 8. OAuth near-expiry refresh

- Time-travel the test clock so an existing
  `vendor_credentials.token_expires_at` is `now() + 30 minutes`
  (within the 24-hour `kRefreshExpiryHorizon`).
- The `pg_cron` job invokes
  `OAuthRefreshCronRunner.runOnce`. The NCR Voyix partner re-mints
  a fresh access token via the documented `client_credentials`
  exchange (no refresh-token round trip — the
  `client_credentials` flow does not issue a refresh token; the
  framework re-mints by replaying the credentials envelope).
- Expected outcome:
  - `connector_sync_log` row written with
    `event_kind = 'auth_refresh'`.
  - `vendor_credentials.consecutive_refresh_failures = 0`.
  - Connection stays `connected`.
  - **No `pg_advisory_lock` involved at V1 (lean cut 2 trim).**
