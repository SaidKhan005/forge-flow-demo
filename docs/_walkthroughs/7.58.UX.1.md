# 7.58.UX.1 Walkthrough — Per-axis dollar attribution renders on PRIMARY DRIVER card

**Slice:** 7.58.UX.1 (Phase 7.58 — Primary Driver audit, render-side wiring)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-05

This slice wires the per-axis dollar attribution function shipped by
7.58.1 (`LaborModel.attributeDollarImpactByAxis`) into the deep
`LeverCardWidget` instances at:

- `lib/screens/variance/variance_this_week_tab.dart:90` — Variance > This
  Week PRIMARY DRIVER card (live WTD gap).
- `lib/screens/week_detail_screen.dart:138` — Week Detail PRIMARY DRIVER
  card (frozen-at-close gap).

Pre-7.58.UX.1 the function was unused. The card already named the dominant
lever id (`COVERS CAME IN LIGHT`); 7.58.UX.1 adds a `DOLLAR ATTRIBUTION`
section under WHAT HAPPENED naming how many of those gap dollars each
axis contributed. Operator narrative: "covers explained $112 of the $180
gap" alongside the existing "what / why / study" copy.

## What changed

### `lib/widgets/lever_card.dart`

`LeverCardWidget` gains an optional named param
`dollarImpactByAxis: Map<String, double>?`. When `null` (or omitted) the
card renders unchanged. When non-null, a new `_DollarAttributionSection`
is inserted between WHAT HAPPENED and the divider above WHAT TO STUDY:

- Section header: `DOLLAR ATTRIBUTION` (mono11 small caps, matching the
  existing `WHAT HAPPENED` / `WHAT TO STUDY` headers).
- Primary sentence (body15): `<axis> explained $X of the $Y gap.` —
  `<axis>` is the axis label for `data.id`, `$X` is the absolute dollar
  contribution of that axis pair, `$Y` is the absolute total gap (sum
  of all 16 entries).
- Per-axis breakdown rows (mono12 dollar value + body13 axis label) —
  one row per axis pair whose absolute contribution is at least $1
  (rounding noise filtered), sorted descending by absolute value:
  - Unfavorable (over-model, value > 0) renders `−$X` in
    `AppColors.negative` — matches `DollarImpactCard`.
  - Favorable (under-model, value < 0) renders `+$X` in
    `AppColors.positive`.

The 16 lever ids collapse to 8 axis pairs by stripping the
`_up`/`_down`/`_over`/`_under` suffix:

| axis label | lever id pair                     |
| ---------- | --------------------------------- |
| covers     | `covers_down` / `covers_up`       |
| ppa        | `ppa_down` / `ppa_up`             |
| cplh       | `cplh_down` / `cplh_up`           |
| splh       | `splh_down` / `splh_up`           |
| foh wage   | `foh_wage_down` / `foh_wage_up`   |
| boh wage   | `boh_wage_down` / `boh_wage_up`   |
| foh hours  | `foh_hours_under` / `foh_hours_over` |
| boh hours  | `boh_hours_under` / `boh_hours_over` |

Per `LaborModel.attributeDollarImpactByAxis` only one half of each pair
is non-zero, so summing the pair gives the signed per-axis contribution.

### `lib/screens/variance/variance_this_week_tab.dart`

Around line 110 the `_ThisWeekContent.build` now reads the active target
profile via the existing `ActiveTargetProfileNotifier?` provider and
calls `LaborModel.attributeDollarImpactByAxis` with WeekData inputs +
profile wages + per-side blended actuals (derived from
`weekData.storedTotalFohLaborDollar / weekData.totalFohHours` and the
BOH counterpart). The resulting map is threaded into the existing
`LeverCardWidget` at the PRIMARY DRIVER `SliverToBoxAdapter`. When the
notifier is out of scope (legacy widget tests), `dollarImpactByAxis` is
`null` and the card renders unchanged — the same backward-compatible
posture 7.58.UX.5 set when introducing `LeverCardNotYetAvailable`.

### `lib/screens/week_detail_screen.dart`

Around line 137 the PRIMARY DRIVER section now computes
`dollarImpactByAxis` from `WeekRecord.storedTarget*` + actual blended
wages (when `hasActualBlendedWageTruth`). When any of `targetCPLH`,
`targetSPLH`, `targetPPA`, `targetFohWage`, `targetBohWage` is null
(legacy week record without locked targets), attribution is skipped
honestly — no silent re-modeling — and the card renders unchanged.

## Demo seed shape (relevant for this walkthrough)

- `MockIntegrationReplaySeed.output` produces 8 historical
  `WeekRecord`s (W12 → W05, newest first). Default business date
  `2026-03-27` (Friday in W13).
- `weekRecords[0]` (W12, the most recent closed week) has
  `primaryLeverId = 'covers_down'`, `dollarGap = -4.85`, `totalCovers
  = 1152`, `forecastCovers = 1202`. None of the historical week
  records carry stored locked targets (`targetCPLH`, `targetSPLH`,
  `targetPPA`, `targetFohWage`, `targetBohWage` are all `null` in the
  seed) — those are populated by the per-shift backfill that runs
  after seed insertion. Pre-backfill the Week Detail PRIMARY DRIVER
  card renders unchanged; post-backfill the same card renders the
  attribution.
- Variance > This Week's `WeekData` is built from the current week's
  closed `ShiftRecord`s by `ShiftService.getWeekToDate`, which always
  threads the active target profile's wages — so the
  `ActiveTargetProfileNotifier?` read returns the same target wages
  WeekData was built from, and the attribution is exact (per-axis
  sum equals `weekData.dollarGap`).

## Click path (text trace)

### Step 1 — Launch the operator app in demo mode

`lib/main_forgeflow.dart` boots the operator shell with the
`MockIntegrationReplaySeed` attached and
`ActiveTargetProfileNotifier` in scope (provided at app root). Default
business date `2026-03-27` (Fri W13).

**Expected:** the operator home renders with seeded current-week data.
`ActiveTargetProfileNotifier?.profile` is non-null at the Variance tab.

### Step 2 — Tap **Variance** → **This Week** tab

The Variance shell opens. The **This Week** tab is the default. Scroll
past `WEEK-TO-DATE vs PLAN` and `DOLLAR IMPACT` to reach the
`StickySectionDelegate('PRIMARY DRIVER')` header.

**Expected:**

- The PRIMARY DRIVER section renders a single `LeverCardWidget` (not
  `LeverCardNotYetAvailable`) since the W13 closed mix posts a real
  lever id through the engine.
- The card's metric line reads the lever metric for whichever axis the
  engine elected (e.g. `COVERS CAME IN LIGHT` when `primaryLeverId =
  'covers_down'`).
- A new section appears **below `WHAT HAPPENED` and above `WHAT TO
  STUDY`** with the header text `DOLLAR ATTRIBUTION` (small-caps mono).
- The primary sentence reads
  `<axis> explained $<X> of the $<Y> gap.` where `<axis>` matches the
  card's dominant lever (e.g. `covers`), `<X>` equals the absolute
  value of `dollarImpactByAxis[primaryLeverId]`, and `<Y>` equals the
  absolute value of `weekData.dollarGap` (per-axis sum).
- A breakdown list renders below the sentence, one row per non-trivial
  axis (≥ $1 absolute), each row a fixed-width 80px dollar column +
  axis label. Unfavorable rows show `−$<value>` in
  `AppColors.negative`; favorable rows show `+$<value>` in
  `AppColors.positive`.

### Step 3 — Verify the per-axis sum equals the dollar gap

Mentally (or with the contract test fixture below) sum the breakdown
rows treating sign:
`(−$A) + (−$B) + (+$C) = sum`. Compare against the `DOLLAR IMPACT`
card above the PRIMARY DRIVER section: the absolute value should match
`weekImpact` shown there.

**Expected:** sum equals `weekData.dollarGap`. This is pinned by the
contract test
`test/labor_model_dollar_attribution_test.dart` (7.58.1) which asserts
"per-axis sum equals `LaborModel.dollarGap` exactly".

### Step 4 — Open Week Detail (frozen-at-close path)

From the operator home, navigate to **History** (or **Previous Weeks**
on the Variance shell) and tap a closed week tile (e.g. `Week 12 ·
Mar 16-22`). `WeekDetailScreen(week: <WeekRecord>)` opens.

Scroll past `WEEKLY SUMMARY vs LOCKED TARGETS` and `DOLLAR IMPACT` to
the `StickySectionDelegate('PRIMARY DRIVER')` section.

**Expected for legacy seed records** (no stored locked targets):

- The `LeverCardWidget` renders unchanged — no `DOLLAR ATTRIBUTION`
  section. This is the honest fallback: when `WeekRecord.targetCPLH`
  / `targetSPLH` / `targetPPA` / `targetFohWage` / `targetBohWage` is
  null, `dollarImpactByAxis` is null and the card stays in pre-UX.1
  shape.

**Expected for post-backfill (or post-7.55q.5-lock) records** with
stored locked targets:

- The card renders the same `DOLLAR ATTRIBUTION` block as Variance >
  This Week, computed against the frozen closed-week numbers
  (`week.totalCovers`, `week.forecastCovers`, `week.totalFohHours`,
  `week.totalBohHours`, `week.avgPPA`, `week.avgCPLH`, `week.avgSPLH`,
  the `storedTarget*` getters, and `week.blendedFohWage` /
  `week.blendedBohWage` when `hasActualBlendedWageTruth`).

### Step 5 — Pinned numerical example (synthetic fixture)

The widget test
`test/widgets/lever_card_test.dart` exercises the renderer against a
fully synthetic, deterministic `dollarImpactByAxis` map. Reproducing
its values here so the click-path has named numbers an operator (or
reviewer) can match:

```
data: LeverCards.coversDown
dollarImpactByAxis: {
  'covers_down':   112.0,
  'ppa_down':       24.0,
  'cplh_down':      32.0,
  'splh_up':       -12.0,
  // every other axis = 0.0
}
```

Renders:

- Header `DOLLAR ATTRIBUTION` — `findsOneWidget`.
- Primary sentence `covers explained $112 of the $156 gap.` —
  `findsOneWidget`. (`156 = 112 + 24 + 32 - 12`.)
- Breakdown rows (sorted by |value| descending):
  - `−$112  covers`     ← dominant, unfavorable
  - `−$32   cplh`       ← unfavorable
  - `−$24   ppa`        ← unfavorable
  - `+$12   splh`       ← favorable
- `+$112` does **not** appear (the dominant row is unfavorable here).
  The favorable-dominant case is pinned separately by the test
  `'favorable dominant axis renders +$ sign on its row'` against
  `LeverCards.coversUp` with `covers_up = -100`, which renders
  `covers explained $100 of the $100 gap.` and `+$100`.

### Step 6 — Null fallback case (regression guard)

The same widget test pins the null path: with `dollarImpactByAxis:
null` (or omitted), `find.text('DOLLAR ATTRIBUTION')` returns
`findsNothing`, and the card renders the pre-UX.1 layout (`WHAT
HAPPENED` then `WHAT TO STUDY`). This is the path Variance > This Week
takes when `ActiveTargetProfileNotifier` is out of scope (legacy
widget tests) and the path Week Detail takes for pre-lock seed
records.
