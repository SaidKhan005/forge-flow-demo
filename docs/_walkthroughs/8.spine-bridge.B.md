## What this slice ships

- **Data Accuracy screen** mounted at `kOperatorWebNavDataAccuracy`
  on the operator-web shell (`/data-accuracy` once routed). Lives
  alongside Account / Vendor connections in the side nav.
- **7 widgets** under `lib/operator_web/widgets/`:
  - `wage_source_toggle.dart` — wage source binary toggle
    (already on disk from a sibling lane).
  - `covers_source_toggle.dart` — per-daypart covers source picker.
  - `covers_manual_entry_sub_card.dart` — inline manual-entry
    sub-card surfaced when a daypart is set to Manual.
  - `data_accuracy_covers_historical_seed_card.dart` — 60-day
    backfill / CSV paste card.
  - `data_accuracy_walk_in_handling_card.dart` — walk-in handling
    radio + daily count input.
  - `polling_tier_status_card.dart` — display-only tier name +
    monthly price label + per-poll-only-vendor cadence list +
    Request tier change button (this lane).
  - `data_accuracy_explainer_card.dart` — static "What this page
    is for" plain-English walkthrough card (this lane).
- **Vendor relativity label** (`vendor_relativity_label.dart`) —
  shared across all five setting cards; reads the connected POS /
  labor / reservation vendor off `VendorConnectionsBundle` and
  composes dynamic English copy.
- **Single-line nav addition** in the operator-web router
  (`kOperatorWebNavDataAccuracy`) wiring side-nav item →
  `DataAccuracyScreen`.

## Click-path — what 8.spine-bridge.B ships today

### 1. Land on `/account`

- **Action:** Sign in via the welcome → password → MFA → T&Cs
  click path with the demo magic-link token. The router emits
  `OperatorWebCompleted` and lands the operator on
  `/account` (the post-onboarding default).
- **Expected:** `Key('operator_web_shell_scaffold')` visible;
  side nav shows **Account** (active), **Vendor connections**,
  and **Data accuracy**. Body is the
  `Key('operator_web_account_screen')`.

### 2. Open the Data accuracy route

- **Action:** Click side nav **Data accuracy**
  (`Key('operator_web_nav_item_data_accuracy')`).
- **Expected:** Body switches to
  `Key('operator_web_data_accuracy_screen')`.
  Title **"Data accuracy"** visible
  (`AppTextStyles.display20`); subtitle reads
  **"Settings for Brio - Chicago Loop (primary location)."**.

### 3. Default fixture renders the relevant cards

- **Action:** Wait for the in-memory data accuracy gateway to
  resolve (one frame). Default fixture has Lightspeed K-Series
  (POS, exposes covers) + Libro (reservations) + QuickBooks Time
  (labor) connected.
- **Expected:** Five cards stack in this order, each as its own
  bordered surface:
  1. `Key('data_accuracy_wage_source_card')` — wage source toggle.
  2. `Key('data_accuracy_covers_source_card')` — covers source per
     daypart.
  3. `Key('data_accuracy_polling_tier_status_card')` — polling
     tier status (display-only).
  4. `Key('data_accuracy_explainer_card')` — "What this page is
     for" explainer.

  The walk-in handling card and the 60-day backfill card are
  **absent** in the default fixture because Lightspeed K-Series
  exposes covers as a first-class field — the contract scopes
  those two cards to POS vendors that don't expose covers.

### 4. Wage source — flip to manual mix

- **Action:** Tap `Key('wage_source_radio_manual_mix')`.
- **Expected:** Selection visibly flips to **"Use my manual mix"**
  (filled radio + sunset-tinted background). Vendor relativity

### 5. Covers source — set dinner to Manual

- **Expected:** Dinner chip flips to selected; the inline

## Permission gating evidence

The Data accuracy screen ships behind the operator-web shell auth
gate (same gate `11W.7` and `11W.8` already audit). The screen is
permitted for `operator_owner` and delegated `operator_manager` users with
the matching permission. A lower-scope manager without that permission lands
on a friendly forbidden surface
(`Key('operator_web_data_accuracy_forbidden')`) reading:

> Data accuracy settings are managed by your operator owner or
> permitted manager; ask them to update them for this location.

This mirrors the `vendor_connections` permission-gate pattern — the
UI is the friendly-error layer; the proxy enforces the gate
server-side via the existing Phase 9 permission key.

## Brand styling

`lib/theme/app_theme.dart` is unchanged. Every new widget reuses the
same `AppColors` palette already used by the Account and Vendor
connections screens:

- Card chrome: `AppColors.backgroundSurface` body,
  `AppColors.borderSubtle` 1px border, 8px corner radius.
- Inner sub-blocks (status pill background, vendor relativity
  label, explainer sub-sections): `AppColors.cardGlow` body,
  `AppColors.borderSubtle` 1px border, 6px corner radius.
- Section headings inside cards: `AppTextStyles.mono11` in
  `AppColors.sunsetDark`.
- Tier pill: `AppColors.peacock` background with
  `AppColors.backgroundSurface` text — matches the brand
  secondary used by other "tier-style" status indicators.
- Outlined "Request tier change" button:
  `AppColors.sunsetDark` foreground + 1px sunset-dark border.
