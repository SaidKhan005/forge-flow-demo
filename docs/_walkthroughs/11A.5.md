# 11A.5 Walkthrough - Debug console (per-operator request log)

**Slice:** 11A.5 (Phase 11A - F&F Operations Console)
**Mode:** `-DemoMode` (admin Flutter Web client + in-memory debug
console gateway, no live proxy required)
**Date:** 2026-05-03

This walkthrough covers the admin click path for the new Debug route
mounted at `/debug` in `lib/admin/admin_routes.dart`. The launch
slice ships the per-operator request log surface with filters,
search, expand-row meta view, and an opt-in live-tail toggle. Two
sibling extension tabs (graph debug for 11A.3.x, MFA diagnostics for
9.UX.1a) are mounted as 501-style stubs so the future surfaces plug
in without re-architecting the screen.

## Authority files exercised

- `lib/admin/admin_routes.dart` - replaces the previous
  `placeholder: true` debug route with a live binding. Adds
  `kAdminDebugConsoleRouteId = 'debug'`, `_buildDebugConsole`, the
  `debugConsoleGateway` field on `AdminConsoleServicesScope`,
  `debugConsoleGatewayOf(context)`, and the
  `_defaultDebugConsoleDemoGateway` fallback. The Health route
  (`/health`) and the Observability placeholder owned by lane 11A.6
  are untouched.
- `lib/main_admin.dart` - resolves
  `HttpDebugConsoleAdminGateway` (mirrors the integration / pricing
  / corpus / feature-flags resolvers) and feeds it into
  `AdminConsoleServicesScope.debugConsoleGateway`. Live builds bind
  the proxy-backed gateway; the in-memory walkthrough fixtures only
  reach the screen in `--dart-define=ADMIN_DEMO_AUTH=true` runs or
  when the proxy URI is missing — never on a live deploy.
- `lib/admin/screens/debug_console_admin_screen.dart` - new
  `DebugConsoleAdminScreen` widget. Three tabs:
  `Request log` (live), `Graph debug` (11A.3.x stub), `MFA
  diagnostics` (9.UX.1a stub). The Request log tab owns the filter
  bar, search bar, live-tail row, and the request table; expand-row
  reveals the full content block only when the operator's
  `feature_flags` opt-in is on AND the actor holds `super_admin`.
- `lib/admin/services/debug_console_admin_gateway.dart` - new
  `DebugConsoleAdminGateway` interface with `listRequests`,
  `getByRequestId`, `getByIdempotencyKey`, `tailRecent`, and
  `listFullContentOptIns`. `HttpDebugConsoleAdminGateway` carries
  the bearer token to the proxy `/v1/admin/debug/*` paths;
  `InMemoryDebugConsoleAdminGateway` ships with the demo seed
  (`kDebugConsoleDemoEntries` / `kDebugConsoleDemoOptIns`) so the
  walkthrough runs end-to-end without a backend.
- `lib/admin/models/debug_console_admin_models.dart` - new typed
  surface: `RequestLogEntry`, `RequestLogStatus`, `RequestLogFilter`,
  `RequestLogTimeWindow`, `FullContentOptIn`, plus the
  `kDebugConsoleFullContentFlagName =
  'debug_console_full_content_enabled'` constant the screen reads
  for opt-in projection.
- `docs/contracts/proxy_health_contract.md` - `proxy_requests` and
  `idempotency_key` are the upstream truth the request log projects
  read-only. The contract bans raw payload bodies from `/health`;
  the same posture extends here to `ff_support` (read-only meta
  view; no full-content reveal even when the operator opt-in is on).
- `docs/contracts/slice_runtime_acceptance_contract.md` - the screen
  follows the performance discipline: cheap initial render (no auto
  fetch on mount), opt-in live-tail (off by default, no in-flight
  stacking), client-side re-filter on chip narrowing.

Launch the admin console with `-DemoMode -Device chrome`, sign in as
`super.admin@forgeflow.test`, click `Debug` in the side nav.

**Expected:**

  names the request log + filter axes + the opt-in gate.

  visible alongside `Last checked: -`.
- The three tabs render
  (`admin_debug_console_tab_request_log`,
  `admin_debug_console_tab_graph_debug`,

## Permission gating evidence

- Client side (admin console): the debug route is only reachable
  when the auth gate admits the caller (`super_admin` or
  `ff_support`); `operator@forgeflow.test` lands on the forbidden
  surface. The `_buildDebugConsole` builder reads the auth source's
  `state.session.roles` and computes
  `canEdit = roles.contains('super_admin')`; the screen consumes
  `editingEnabled` to drive the view-only indicator and the
  expand-row full-content gate.
- Defense-in-depth: even with `editingEnabled = true`, the
  expand-row reveal is also gated on the operator's
  `debug_console_full_content_enabled` `feature_flags` row. Both
  gates must be satisfied — role AND opt-in — before the panel
  renders. Asserted by the widget tests:
  - `super_admin + opt-in ON reveals the full content payload on
    expand`
  - `super_admin + opt-in OFF keeps the full content locked`
  - `ff_support sees view-only indicator and cannot reveal full
    content even when opt-in is on`

## Boundary checks

- No `lib/admin/screens/health_admin_screen.dart`,
  `lib/admin/services/health_admin_gateway.dart`, or
  `lib/admin/models/health_admin_models.dart` files were modified.
  Verify with `git diff master --name-only` — only the new debug
  console files plus `lib/admin/admin_routes.dart` (the `debug`
  route entry, the new builder, the new `debugConsoleGateway` field
  on `AdminConsoleServicesScope`, the new `debugConsoleGatewayOf`
  accessor, and the new `_defaultDebugConsoleDemoGateway` constant)
  appear in the diff.
- No `lib/admin/screens/observability_admin_screen.dart` is created
  here — lane 11A.6 owns that surface and the placeholder route
  block at `lib/admin/admin_routes.dart` for `id: 'observability'`
  is intentionally untouched.
- No `db/migrations/*.sql` changes — the launch slice consumes
  `proxy_requests` and `feature_flags` via the proxy. The migration
  drift scanner does not need to run.
- No proxy code changes — the screen targets the
  `/v1/admin/debug/*` paths the proxy will expose; the proxy
  binding is a follow-up and the launch UX runs against the
  in-memory gateway. The runtime acceptance gate's "live staging
  proof" requirement applies once the HTTP gateway lands; the
  launch slice limits its claim to the in-memory contract. The
  HTTP gateway shape (paths, query parameters, headers) is fully
  spelled out in `lib/admin/services/debug_console_admin_gateway.dart`
  so the proxy implementation has a stable contract to bind to.
- No `feature_flags` mutation. The opt-in row is consumed
  read-only; the toggle path lives on the 11A.7 Feature Flags
  admin surface, which super_admins use to flip
  `debug_console_full_content_enabled` per operator.
- The `proxy_health_contract.md` PII discipline (no raw payloads
  on `/health`) is preserved. Full-content payloads only appear on
  the debug surface, behind the dual gate (role + per-operator
  feature_flags opt-in), and `ff_support` is excluded from the
  reveal even when the opt-in is on.
- Performance posture per
  `docs/contracts/slice_runtime_acceptance_contract.md`:
  - cheap initial page load (no auto-fetch on mount;
    Refresh-button gated)
  - bounded list (`kDebugConsoleListLimit = 100`,
    `kDebugConsoleTailLimit = 25`)
  - no automatic polling of expensive endpoints by default
    (live-tail is opt-in)
  - no stacked in-flight duplicate requests: `_refresh` is guarded
    by `_refreshing`; `_pollTail` is guarded by both `_refreshing`
    and a separate `_tailing` flag so a slow `tailRecent` cannot
    accumulate concurrent calls behind it (asserted by the
    `live-tail polls do not stack when the prior tailRecent has
    not returned yet` widget test)
  - bounded growth: after a tail merge the entry list is clamped
    back to `kDebugConsoleListLimit` so a long live-tail session
    cannot grow the table indefinitely (asserted by the
    `live-tail merge clamps the table back to the bounded list
    limit` widget test)
  - filter and search re-narrow client-side first, sparing the
    proxy a round-trip per chip click
  - timer cancellation on dispose so a closed surface cannot
    keep polling
- Layout posture: the request-log tab body is a single
  `ListView`, not a `Column`. The shell embeds the screen inside
  a tight TabBarView slot (~540x158 on the default 800x600 shell
  viewport), and a `Column` body would overflow there. The
  `screen composes without overflow at the default 800x600
  viewport` widget test plus the
  `11A.5 promotes the debug route from placeholder to live`
  shell test (which asserts `tester.takeException()` is null)
  pin the regression.
