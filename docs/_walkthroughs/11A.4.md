# 11A.4 Walkthrough — Integration management admin surface

**Slice:** 11A.4 (Phase 11A — F&F Operations Console)
**Mode:** `-DemoMode` (admin Flutter Web client + in-memory
integration gateway + KMS stub provider, no live Cloud Run admin
proxy required)
**Date:** 2026-05-01

This walkthrough covers the admin click path called out in the 11A.4
prompt's *Operator walkthrough* section: viewing the masked-display
ledger, rotating a provider key, the one-time reveal modal, the
copy-on-confirm flow, the read-only `ff_support` branch, the KMS
forced-failure path, and the non-admin fail-closed branch. The demo
source is opt-in (`-DemoMode`); production binds the live Firebase
admin auth source + HTTP gateway (`HttpIntegrationAdminGateway`)
against the F&F admin Cloud Run proxy.

## Authority files exercised

- `lib/main_admin.dart` — production binds
  `HttpIntegrationAdminGateway` against
  `--dart-define=ADMIN_PROXY_BASE_URI=...` and wraps
  `AdminConsoleApp` in `AdminConsoleServicesScope` with the
  operator/location, pricing, and integration gateways. Demo falls
  back to the seeded in-memory integration gateway in
  `admin_routes.dart`.
- `lib/admin/admin_routes.dart` — Integrations route promoted from
  placeholder to live; `AdminConsoleServicesScope` grows an
  `integrationGateway` field and a default in-memory demo seed
  (Anthropic + Voyage pre-rotated; Azure DB starts empty so the
  walkthrough exercises the "no row yet → first rotation" path).
- `lib/admin/screens/integration_admin_screen.dart` — the
  Integrations admin surface. Provider-key card with one tile per
  rotatable lane, vendor-connector status card, FX-rate /
  email-provider status card, read-only banner, action error
  banner. The rotate button opens a confirmation dialog →
  plaintext-entry dialog → one-time reveal modal with a Copy
  button.
- `lib/admin/models/integration_admin_models.dart` —
  `IntegrationBundle`, `ProviderKeyRow` (alias `KeyMaskedRow`),
  `ProviderKeyKind`, `RotateKeyCommand`, `RotateKeyResult`,
  `VendorConnectorStatus` (alias `FxRateSourceStatus`). Plaintext
  is intentionally absent from `ProviderKeyRow`; it lives only on
  `RotateKeyCommand` (request) and `RotateKeyResult.plaintextValue`
  (one-time response).
- `lib/admin/services/integration_admin_gateway.dart` — HTTP +
  in-memory gateway implementations.
- `lib/infrastructure/persistence/postgres/repositories/provider_credentials_repository.dart`
  — cross-operator `provider_credentials` SELECT and rotate-in-one-
  transaction UPSERT through `withSystem`. The rotate path runs
  `UPDATE prior is_active = false` then `INSERT new is_active =
  true` inside the same transaction; the partial unique index
  `provider_credentials_active_uq` keeps the "one active row per
  kind" invariant.
- `lib/infrastructure/kms/kms_stub_provider.dart` — KMS provider
  abstraction + stub implementation. The stub returns
  `kms://stub/<uuid>` references, masks plaintext as
  `<first4>***<last4>`, and exposes a `failNextWrite` toggle so
  the audit-on-failure path is exercised end-to-end without a
  real KMS.
- `db/migrations/202605010000_phase_11A_4_provider_credentials.sql`
  — adds `public.provider_credentials` (NOT operator-scoped),
  partial unique index on `(key_kind) where is_active`, and
  `forge_admin` grants. Audit chain reuses `auth_events_audit`
  via the existing system-event writer.
- `tool/advisor_proxy/advisor_proxy.dart` — adds the
  `/v1/admin/integrations*` route block. CORS preflight uses a
  dedicated `_setAdminIntegrationsCorsHeaders` helper (POST + GET +
  OPTIONS only — rotation routes are POST). Method-scoped role
  gate: `kFfIntegrationAdminReadRoles` (`super_admin` +
  `ff_support`) for `GET`; `kFfIntegrationAdminWriteRoles`
  (`super_admin` only) for `POST`. Structured 4xx for unknown
  `key_kind` and missing `plaintext_value`.
- `tool/advisor_proxy/proxy_bootstrap.dart` —
  `RepositoryIntegrationAdminProxyGateway` binding wired from
  `ProviderCredentialsRepository` + `KmsStubProvider` +
  `AuthEventsAuditRepository` over the admin pool. Validates
  `key_kind`, calls KMS, writes `provider_credentials` + audit row
  in distinct phases so a KMS failure NEVER produces a successful
  rotate-success audit row.

Launch the admin console with `-DemoMode -Device chrome` and sign in
as `super.admin@forgeflow.test`.

**Expected:** branded admin shell renders with the side nav
including an `Integrations` item that is now live (no longer the

Click `Integrations` in the side nav.

**Expected:**

- Body region renders the new `Integrations` surface

- Header reads `Integrations` with a one-line subtitle explaining
  that plaintext keys are never displayed after rotation closes.
- `Provider keys` card shows three tiles:
  * `Anthropic API` — masked `sk-a***Q9aB`, `kms://stub/seed-…`
    pointer, `rotated by demo-super-admin at 2026-04-01T14:00…`,

  * `Voyage embeddings` — masked `pa-v***RtZx`, similar metadata,

  * `Azure DB superuser` — empty: `No active credential. Rotate to

  (`Compeat connector`, `Marketman connector`) with status label

### Step 3 — Rotate the Anthropic key

Click `Rotate` on the Anthropic tile.

**Expected:** a confirmation dialog opens
(`Key('admin_integrations_confirm_dialog')`) with the title
`Rotate Anthropic API key?` and a body explaining that an audit row
will be written and the plaintext is shown ONCE in a follow-up
modal. Click `Continue`.

**Expected:** the rotation dialog opens
(`Key('admin_integrations_rotate_dialog')`). Paste a new plaintext
value (≥ 9 characters; the validator rejects shorter values so the
masked display has prefix + suffix). Toggle the show/hide eye to
verify the value, then click `Rotate`.

**Expected:**

- The dialog closes.
- The one-time reveal modal opens
  (`Key('admin_integrations_reveal_dialog')`) with title
  `Anthropic API rotated`, the plaintext value rendered in a
  `SelectableText` block, and a `Copy` button.
- Click `Copy` → button updates to `Copied` (audit-on-copy SnackBar
  reads `Copied Anthropic API plaintext to clipboard.`).
- Click `Close` → modal closes; the masked grid re-renders with the
  new masked display, new `rotated_at`, new `kms_secret_name`, new
  `created_by`/`updated_by`. The original plaintext is NOT visible
  anywhere on the masked grid.

### Step 4 — Confirm the masked grid never re-reveals plaintext

Click anywhere on the Anthropic row outside the Rotate button.

**Expected:** no plaintext affordance exists; only the masked
display. There is no edit pencil, expand button, or hidden tooltip
that surfaces plaintext.

### Step 5 — Verify support identity sees read-only Integrations

Sign out, sign in as `support@forgeflow.test`.

**Expected:** the admin shell still renders (`ff_support` is
admitted to the console). Click `Integrations`. In live mode the
Integrations screen issues `GET /v1/admin/integrations`, which the
proxy admits because `ff_support` is in
`kFfIntegrationAdminReadRoles`. The data renders, and the screen is
in **read-only mode**: the
`View-only: rotating provider keys requires the super_admin role.`
banner shows (`Key('admin_integrations_readonly_banner')`), and
every Rotate button is absent. Asserted by
`test/admin_integration_admin_screen_test.dart` test
`admin shell with ff_support source renders integrations in
read-only mode` driving the full `AdminConsoleApp` and by
`test/proxy_integration_admin_routes_test.dart` test
`11A.4 POST /v1/admin/integrations/rotate-anthropic rejects
ff_support with 403`.

Server-side defence-in-depth: any rotate attempt that bypassed the
UI would still be rejected by the write-only gate
(`kFfIntegrationAdminWriteRoles`).

### Step 6 — KMS failure path (forced)

Sign back in as `super.admin@forgeflow.test`. In a debug build the
`InMemoryIntegrationAdminGateway.kmsProvider.failNextWrite = true`
toggle simulates a KMS failure on the next rotate. Click
`Rotate` on the Voyage tile, confirm, paste a plaintext value,
click `Rotate`.

**Expected:**

- The reveal modal does NOT open.
- The action error banner
  (`Key('admin_integrations_action_error')`) shows the failure
  message.
- The masked grid still shows the prior Voyage row unchanged
  (previous key still active).
- A `rotation_failed` audit row is written
  (`admin.integrations.rotation_failed`); a `rotation_success`
  row is NOT written. Asserted by
  `test/proxy_integration_admin_routes_test.dart` test
  `11A.4 forced KMS failure writes rotation_failed audit and not
  rotation_success`.

### Step 7 — Verify non-admin fail-closed

Sign out, sign in as `operator@forgeflow.test`.

**Expected:** the branded forbidden card renders. The Integrations
surface, side nav, and header bar are absent. Asserted by
`test/admin_operator_location_screen_test.dart` test
`non-admin user is blocked by the admin auth gate` (the gate sits
above the route catalog, so the same fail-closed branch covers
Integrations).

## Permission gating evidence

- Client side (admin console): the integrations route is only
  reachable when the auth gate admits the caller (`super_admin` or
  `ff_support`); `operator@forgeflow.test` lands on the forbidden
  card. The screen exposes an `editingEnabled` flag (default
  `true`) that hides every rotate button and renders a `View-only:
  rotating provider keys requires the super_admin role.` banner;
  the read-only branch is asserted in
  `test/admin_integration_admin_screen_test.dart`.
- Server side (proxy): every `/v1/admin/integrations*` request
  verifies the Firebase bearer token through
  `_resolveVerifiedClaimsOrWrite` and then evaluates a method-
  scoped role set — `kFfIntegrationAdminReadRoles` (`super_admin`
  + `ff_support`) for `GET`, `kFfIntegrationAdminWriteRoles`
  (`super_admin` only) for `POST`. The split lets `ff_support`
  load the read-only integrations view live without weakening the
  rotate gate. Integrations routes use a dedicated
  `_setAdminIntegrationsCorsHeaders` helper (GET + POST + OPTIONS
  only). Asserted by
  `test/proxy_integration_admin_routes_test.dart` 11A.4
  group tests for `operator_owner` GET rejection (403),
  `ff_support` GET admission (200), `ff_support` POST rejection
  (403), unauthenticated (401), and unknown `key_kind` (400).

  pricing surface (`/v1/admin/pricing/*`) are untouched. The new
  integration routes live on a disjoint path prefix
  (`/v1/admin/integrations*`) and do not reorder any existing
  route handlers.
- `admin_routes.dart` only promotes the Integrations route from
  placeholder to live and adds a service lookup
  (`integrationGatewayOf`); the rest of the catalog and order is
  preserved.
- `main_admin.dart` only wires the integration gateway into
  `AdminConsoleServicesScope`; the existing fail-closed live
  wiring, Firebase admin auth, and demo-mode behaviour are
  preserved.
- `tool/advisor_proxy/advisor_proxy.dart` only adds
  `/v1/admin/integrations*` constants, dispatch, validation,
  CORS, and the gateway interface. Existing
  `/v1/admin/operators` / `/v1/admin/pricing/*` / auth routes are
  untouched.
- `tool/advisor_proxy/proxy_bootstrap.dart` only binds the new
  provider credentials repository / KMS stub / gateway into
  production bindings; auth and operator/location and pricing
  bindings are untouched.
- Plaintext is NEVER persisted in `provider_credentials`. The
  table holds only `masked_value` + `kms_secret_name`. The proxy
  surfaces plaintext ONCE on the rotation response; subsequent
  list reads never return it. The screen renders plaintext in a
  modal that closes on `Navigator.pop` and cannot be reopened.
- KMS failure path: when `KmsProvider.writeSecret` throws
  `KmsWriteFailure`, the proxy writes a
  `admin.integrations.rotation_failed` audit row and never calls
  the repository — the prior `is_active = true` row is preserved.
  Asserted by
  `test/proxy_integration_admin_routes_test.dart`.
- Persistence-failure path: when the repository throws after a
  successful KMS write, the proxy writes a
  `admin.integrations.rotation_failed` row with
  `failure_kind: persistence_failed` and the orphaned KMS pointer
  so an operator can investigate; the prior key stays active
  because the repository transaction rolls back.
- `AdminConsoleServicesScope` is now mounted in both demo and
  live modes from `main_admin.dart` so the route builder always
  has access to the `AdminAuthSource` for role-based UI gating.
- Every admin write threads `actorUserId` into `created_by` /
  `updated_by` and into the `auth_events_audit` row inserted via
  `AuthEventsAuditRepository.insertSystemEvent` under
  `admin.integrations.*` event types with the
  `admin.integrations.<METHOD>:<actor>:...` reason string.
- No tracker updates and no commits.

## Retry semantics (HARD-H follow-up, 2026-05-02)

`rotateKey` now forwards a per-action `Idempotency-Key` header to
the proxy. The proxy reserves the key in
`public.admin_request_idempotency` before the KMS call runs;
network-timeout retries replay the cached response instead of
writing a second `provider_keys` row + a second
`auth_events_audit` entry (which would also leave an orphaned KMS
secret behind). The screen mints a new key per rotation submit
(default UUID-shaped, with `idempotencyKeyFactory` injection
point). Header is OPTIONAL on the wire — back-compat for older
callers and the existing test surface.
