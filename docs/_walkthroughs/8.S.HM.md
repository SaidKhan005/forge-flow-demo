# 8.S.HM Walkthrough — Humanity (TCP) labor adapter (lifecycle = documented)

**Slice:** 8.S.HM (Phase 8.S — engineer-all-17 Wave B; Humanity v1
labor / scheduling adapter; legacy username/password auth, pollOnly)
**Mode:** `kDemoMode = true` (operator app, deterministic seed)
**Date:** 2026-05-04
**Lifecycle target at slice close:** `VendorLifecycle.documented`

This slice ships the Humanity (TCP) labor adapter at lifecycle =
`documented` per the engineer-all-17 doctrine
(`memory/project_phase_8_engineer_all_17_doctrine.md`). Humanity is
the framework's first vendor in Wave B that exercises **two new code
paths**:

1. **`authMode = keyPaste`** — Humanity v1 still uses the legacy
   OAuth 2.0 Resource Owner Password Credentials grant
   (`grant_type=password`). The connect modal asks the operator for
   their Humanity username + password; the proxy POSTs them to
   `/oauth2/token`; the issued bearer is stashed in
   `vendor_credentials` (pgcrypto envelope) and the adapter only ever
   sees a `VendorCredentialHandle`. No OAuth, no partnership program,
   no Marketplace listing — any operator with an active Humanity
   account can connect once `8.S.HM.live.*` flips the lifecycle.
2. **`webhookSupport = pollOnly`** — Humanity's documented v1 API
   exposes no webhook delivery surface. The adapter declares
   `webhookSupport = pollOnly` and `handleWebhook` throws
   `UnsupportedError`. The framework router consults
   `capabilityProfile.webhookSupport` before dispatch and never
   hands a webhook to the adapter; the throw stays as a
   defense-in-depth assertion.

Live HTTP is deferred to `8.S.HM.live.sandbox` (sandbox verification
against an F&F-owned demo Humanity account) and `8.S.HM.live.prod`
(production verification against a real operator's credentials when
they opt in). Humanity has 10% estimated operator share per
`memory/project_operator_share_assumptions.md`.

The slice respects every Hard Promise from `CLAUDE.md`:

1. Pure transport — the adapter writes existing canonical labor
   tables only; no business logic in `lib/services/*` is touched.
2. Demo-mode persists — the same vendor-picker chrome renders in
   `kDemoMode = true` and `kDemoMode = false`.
3. No app-logic changes before `7.58` — this slice adds a vendor
   adapter; metric formulas are untouched.
4. Per-operator isolation — every gateway call routes through
   `OperatorScopedRepository.withTenant(operatorId, locationId, ...)`
   (the `HumanityGateway` abstraction; production wires it).
5. Modular Adaptive Agentic RAG — n/a for this surface.
6. Recommendations not commands — n/a (scheduling data inflow only).
7. F&F holds provider keys server-side — the legacy username +
   password live in operator memory and the connect modal only; the
   proxy boundary encrypts the issued bearer into
   `vendor_credentials` immediately and the adapter never sees
   plaintext again. The handle is what the backfill / poll /
   disconnect paths operate against.
8. AI infra is general-purpose — n/a (labor adapter, not AI).
9. AI cost metering — n/a.
10. Backend phase ships operator-facing UX before phase close — the
    Vendor Connections widget already renders the "Coming soon" pill
    for `documented`-lifecycle vendors; this slice plugs Humanity
    into that surface and adds the legacy-auth helper copy
    (**"Humanity uses a username and password (legacy auth). Forge &
    Flow stores these securely and uses them only to read your
    schedule data."**) on top of the existing "Notify me when ready"
    capture for non-live rows.

### Step 3 — Engineering anchor: connect via keyPaste (legacy auth)

The `*.live.*` slice will exercise the live username/password POST
against `https://platform.humanity.com/v1.0/oauth2/token`; this
engineering slice exercises the offline path against
`_FakeHumanityHttpClient.exchangeUsernamePassword`:

```
connect(operator, location, vendor='humanity',
        keyPaste=ConnectKeyPasteCredential(
          apiKey='humanity-test-password-001',
          username='restaurant-admin'))
  → httpClient.exchangeUsernamePassword(
      username='restaurant-admin',
      password='humanity-test-password-001')
  → tokenResponse=HumanityTokenResponse(accessToken='bearer-001')
  → gateway.persistConnection(
      operatorId, locationId, actorUserId,
      credential=VendorCredentialHandle(credentialId='bearer-001'),
      metadata={
        'auth_mode': 'keyPaste',
        'auth_method': 'legacy_username_password',
        'grant_type': 'password',
      })
  → ConnectResult(
      connectionId='humanity-<op>-<loc>',
      status: connected,
      metadata: {'auth_mode': 'keyPaste',
                 'auth_method': 'legacy_username_password'},
      webhookUrl: null,                       # pollOnly
      firstBackfillStarted: true,
    )
```

**Expected:** `result.status == ConnectionStatus.connected`,
`result.webhookUrl == null` (pollOnly — no webhook URL is
provisioned), `result.metadata['auth_mode'] == 'keyPaste'`,
`result.metadata['auth_method'] == 'legacy_username_password'`,
`httpClient.usernamePasswordCalls.length == 1` with the exact
posted username + password. Pinned in Test 5 ("full lifecycle
preserves watermark; reconnect requires re-paste").

### Step 7 — Engineering anchor: future-dated shift drop (sanity guard)

### Step 10 — Engineering anchor: disconnect → reconnect (operator re-pastes)

```
disconnect(reason: operatorAction)
  → httpClient.revokeCredential(credential) [best-effort]
  → gateway.wipeCredentials(operator, location)
  → DisconnectResult(credentialsWiped: true,
                     webhookUnregistered: true,    # pollOnly uniform contract
                     watermarkPreserved: true)

[operator re-opens connect modal, re-pastes username + ROTATED password]

connect(keyPaste=ConnectKeyPasteCredential(
          apiKey='humanity-rotated-password',
          username='restaurant-admin'))
  → httpClient.exchangeUsernamePassword(...)         # 2nd call
  → gateway.persistConnection(...)
  → ConnectResult(status: connected, ...)

watermark.lastModifiedSeen unchanged across cycle
```

**Expected:** `gateway.credential` is null after disconnect (wipe
took effect); after reconnect `httpClient.usernamePasswordCalls.length
== 2` (legacy auth has no refresh-token magic — reconnect MUST
re-exchange username + password); watermark survives the cycle so
the next poll resumes from where the disconnect happened. The
operator dashboard chrome's SPLH card degrades to
`MetricCardNotYetAvailable` while disconnected and flips back to
the live number on reconnect. Pinned in Test 5.
