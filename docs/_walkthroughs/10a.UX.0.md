# 10a.UX.0 Walkthrough — Sync-state badge

**Slice:** 10a.UX.0 (Phase 10a — Shared Multi-Device State V1, UX
sub-slice family)
**Mode:** Demo (`kDemoMode = true`) — fake bridge notifier drives the
connection-state stream so the click path runs without a live
WebSocket. The 10a.0 substrate (real `RealtimeSubscription`) is the
production-mode wiring; the badge is consumer-only and sees no
difference.
**Date:** 2026-05-03

This walkthrough exercises the sync-state badge that the operator
sees in the app bar. The badge surfaces the bridge connection state
(`RealtimeConnectionState`) shipped by 10a.0 so the operator can tell
at a glance whether realtime updates are live, in flight, or
recovering.

## State → pill mapping

| `RealtimeConnectionState` | Pill chrome | Tooltip |
| --- | --- | --- |
| `connected` | Green dot + "Live" | "Realtime updates connected" |
| `connecting` | Amber dot + "Connecting…" | "Connecting to realtime channel" |
| `reconnecting` | Amber dot + "Reconnecting…" | "Realtime channel dropped — reconnecting" |
| `idle` | Hidden (`SizedBox.shrink()`) | — |

The visible pill is fixed at `132px` wide so the surrounding
notifications / settings actions don't shift when the label changes
length between "Live" and "Reconnecting…".

## Click path (demo-mode walkthrough)

Mirrors the demo path scripted in
`docs/phases/phase_10a/phase_10a_shared_state_v1_plan.md` lines
304–310. A test or demo harness mounts the shell with a
`StreamController<RealtimeConnectionState>` plugged into
`AppShell.realtimeConnectionState`.

1. **Cold launch** — controller has not emitted; `initialState` is
   `idle`. App bar shows the notifications + settings actions but no
   sync pill (badge is `SizedBox.shrink`).
2. **Push `connecting`** — controller emits
   `RealtimeConnectionState.connecting`. App bar reveals the amber
   "Connecting…" pill to the left of (standalone) or before
   (embedded Barrio) the icon actions.
3. **Push `connected`** — controller emits
   `RealtimeConnectionState.connected`. Pill flips to the green
   "Live" chrome at the same width — no layout shift on the icon
   actions.
4. **Simulated drop** — controller emits
   `RealtimeConnectionState.reconnecting`. Pill flips to amber
   "Reconnecting…", same width, same position. The 10a.0 substrate
   is the producer side: in production, this transition fires when
   the WebSocket closes and the back-off timer is armed.
5. **Recovery** — controller emits
   `RealtimeConnectionState.connected` again. Pill returns to green
   "Live" at the same width.
6. **Tear-down / sign-out** — in production, the bootstrap-level
   `RealtimeAuthBridge` calls `subscription.clearTenantContext()`
   on the transition to `AuthSessionUnauthenticated`. That tears
   down the active channel, cancels any pending reconnect timer,
   increments the generation token (so an in-flight stale connect
   cannot bind under the cleared scope), and emits `idle`. The
   pill collapses to `SizedBox.shrink()`. The subscription stays
   alive — the broadcast streams the badge listens on are NOT
   closed — so the next sign-in resumes the lifecycle without
   rebuilding the badge tree.

   Importantly, the bridge sits ABOVE the navigator. If the
   operator pops the embedded F&F destination back to the Barrio
   home and THEN signs out, the bridge listener is still attached
   (it never depended on `AppShell` being mounted) and the tenant
   still gets cleared. Demo-mode harnesses simulate this by
   emitting `RealtimeConnectionState.idle` directly through their
   controller.

## Trace summary

The badge is purely a consumer; there is no proxy / Postgres / outbox
trace owned by this slice. The relevant production trace lives on
`RealtimeSubscription` (10a.0):

- `realtime.connectFailed` — connect attempt failed; subscription is
  about to schedule reconnect, badge will see `reconnecting`.
- `realtime.channelError` — active channel errored; subscription
  tears it down and schedules reconnect, badge will see
  `reconnecting`.
- `realtime.frameParseFailed` — orthogonal to the badge (frame
  decoding error during a `connected` lifetime); badge stays green.

## Permission gating

None. The badge is always visible to an authenticated operator
because the realtime channel is per-operator (JWT-scoped). No
admin-role gate, no `kDemoMode` toggle.

## Out of scope (explicit follow-ups)

- **Subscription dispose at app shutdown.** The bootstrap constructs
  the subscription but never explicitly disposes; for a long-lived
  Cloud Run client the OS process tear-down is the dispose path.
  Wiring an explicit dispose on `WidgetsBindingObserver.detached`
  is a tidy-up follow-up, not blocking for 10a.UX.0.
- **Multi-instance fan-out.** The bridge in 10a.0 ships an
  in-process publisher; only events the same proxy instance's
  bridge claims reach the badge owner. The `CloudPubSubRealtimePublisher`
  is the documented Phase 10a follow-up.
- **Last-sync per-table freshness rows** — owned by 10a.UX.1 in
  Settings.
- **Peer-edit toast** — owned by 10a.UX.1.
- **Conflict-resolution chrome** — Phase 10b, not 10a.
