# 9.UX.1 - Settings Account MFA

Date: 2026-04-30

## Scope

Add self-service authenticator app MFA to Settings -> Account for every signed-in user.

## Operator Walkthrough

1. Sign in with a production-backed ForgeFlow session.
2. Open Settings.
3. Select Account.
4. Confirm the MFA section appears below Account actions.
5. Confirm the section first says "Checking status..." and then shows the current authenticator app state.
6. If no app is enrolled, select Add authenticator app.
7. Confirm the QR code is centered and the setup URL and secret each have a copy affordance.
8. Verify with the 6-digit code from an authenticator app.
9. Confirm no recovery-code list, copy button, or code-entry fallback appears.
10. Confirm the factor row updates to "Authenticator app" with consumer-facing status copy.
11. From the MFA challenge screen, confirm the only code entry is the
    authenticator-app 6-digit code and that users without app access are
    routed to "Contact your admin."

## Contract Notes

- The app uses the live `MfaOperationsGateway` passed from runtime bindings. The in-memory demo gateway is test/demo-only and must be opted into explicitly.
- Factor list and removal use proxy routes:
  - `POST /v1/auth/mfa/factors/list`
  - `POST /v1/auth/mfa/factors/revoke`
  - `POST /v1/auth/mfa/factors/removal/cancel`
- The challenge-screen "Contact restaurant admin" action posts to
  `POST /v1/auth/mfa/recovery/request`. The proxy returns a generic accepted
  response and, when the account and restaurant admin recipients resolve,
  queues `auth.user.mfa_recovery_requested` through `event_outbox`.
- Recovery-code display and challenge entry are intentionally not exposed in
  the app UX. Lost-authenticator flows use admin reset / delayed removal.
- Removal starts the existing 24-hour delayed-removal contract and audits `mfa_factor_revocation_initiated`. It does not immediately remove the factor.
- Pending self-removal can be cancelled from Settings before the worker
  completes it; cancellation audits `mfa_factor_revocation_cancelled`.
- Pending staff removal can be cancelled from Team when the user row carries
  `mfa_removal_request_id`; it uses the same audit event.
- Recovery codes are not a visible launch UX surface and must not be pasted
  into walkthrough evidence.
- The durable notification event is queued in this slice. Actual inbox email
  delivery still depends on the Phase 10a outbox-to-email worker/provider.
