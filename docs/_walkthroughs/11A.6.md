# 11A.6 Walkthrough - Observability dashboard

**Slice:** 11A.6 (Phase 11A - F&F Operations Console)
**Mode:** `-DemoMode` (admin Flutter Web client + in-memory observability
gateway, no live cost / dormancy / Cloud Run admin proxy required)
**Date:** 2026-05-03

This walkthrough covers the admin click path called out in the 11A.6
phase doc (`docs/phases/phase_11A_operations_console/phase_11A_operations_console_plan.md`,
lines 345-369): opening the new Observability route, running the
manual observability check, and stepping through the six tabs (Cost,
Top-N, Operators, Cap events, Graph, Cloud Run) so every cost
telemetry axis, the dormancy flag, the per-tier margin estimate, the
cap-event stream, the graph approval / inferred / rejected /
isolated counts, and the per-route latency + Cloud Run instance
shape are exercised end-to-end. The /health envelope viewer is
deliberately untouched: that surface (`11A.UX.health`) lives at the
Health route and is linked out of the Observability header.

The demo source is opt-in (`-DemoMode`); production binds the live
Firebase admin auth source + HTTP gateway
(`HttpObservabilityAdminGateway`) against the F&F admin Cloud Run
proxy at `/v1/admin/observability`.

## Authority files exercised

- `lib/main_admin.dart` - production resolves
  `HttpObservabilityAdminGateway` against
  `--dart-define=ADMIN_PROXY_BASE_URI=...` with the Firebase
  ID-token bearer source and injects it into
  `AdminConsoleServicesScope` so the live route does not silently
  fall back to the in-memory demo envelope. Demo mode
  (`--dart-define=ADMIN_DEMO_AUTH=true`) returns null, which routes
  the surface through `_defaultObservabilityDemoGateway` for the
  walkthrough.
- `lib/admin/admin_routes.dart` - the placeholder Observability slot
  is replaced with `_buildObservability`, which reads
  `ObservabilityAdminGateway` from `AdminConsoleServicesScope` and
  hands it to the new screen. The `kAdminObservabilityRouteId`
  constant is added so audit logs and route observers have a stable
  name. `_defaultObservabilityDemoGateway` is the seeded in-memory
  fallback used by the walkthrough.
- `lib/admin/screens/observability_admin_screen.dart` - new screen
  with six tabs, an as-of strip with dormant / underwater / cap-event
  summary chips, a manual-confirmed run button, and section cards for
  cost telemetry by axis, cache hit rate, model mix, batch-mode
  share, dormancy, margin, cap events, graph counts + freshness, and
  Cloud Run + per-route latency.
- `lib/admin/services/observability_admin_gateway.dart` - the
  `ObservabilityAdminGateway` interface plus
  `HttpObservabilityAdminGateway` (production binding hits
  `GET /v1/admin/observability` with `cost_telemetry_limit` and
  optional `query_class` query parameters) and
  `InMemoryObservabilityAdminGateway` (demo + widget tests; honors
  the same request shape). `ObservabilityFetchRequest` carries the
  bounded request: server-side limit clamped to
  `kObservabilityCostTelemetryLimit = 100`, plus an optional
  `query_class` filter. The seeded `kObservabilityAdminDemoEnvelope`
  is the deterministic envelope the walkthrough reads; the
  in-memory gateway applies the filter + limit to the seed and
  injects the `cost_telemetry_meta` block (`total_count`,
  `truncated`, `query_class_filter`) so the screen can render the
  truncation hint without a live proxy.
- `lib/admin/models/observability_admin_models.dart` - typed parsers
  for the envelope: `CostTelemetryEntry`, `CacheHitRateEntry`,
  `ModelMixEntry`, `BatchModeShareEntry`, `TopExpensiveEntry`,
  `OperatorDormancyEntry`, `MarginEstimateEntry`, `CapEvent`,
  `GraphObservability`, `RouteLatencyEntry`, `CloudRunInstanceMetric`,
  and the `ObservabilityEnvelope` wrapper. Hard-coded constants:
  `kObservabilityDormancyDaysThreshold = 30`,
  `kObservabilityCostTelemetryLimit = 100`. `OperatorDormancyEntry`
  preserves a null `last_active_at` rather than collapsing to `as_of`
  — never-active operators surface as `NEVER ACTIVE · DORMANT`
  (negative chip) so the precompute-skip lever covers a producer
  that has never reported a row for an operator. The proxy MAY also
  send an explicit `days_silent` integer; the model honors it as
  authoritative when present. The envelope carries
  `costTelemetryTotalCount` + `costTelemetryTruncated` +
  `costTelemetryQueryClassFilter` so the cost surface can render a
  truncation hint and the active filter chip.
- `test/admin/observability_admin_screen_test.dart` - the widget
  test asserts the click path described below.

## Click path (text trace)

### Step 1 - Sign in as super_admin and open Observability

Launch the admin console with `-DemoMode -Device chrome`, sign in as
`super.admin@forgeflow.test`, click `Observability` in the side nav.

**Expected:**

- The screen shell renders with the manual-run prompt
  (`Key('admin_observability_manual_prompt')`). The first paint does
  NOT issue a fetch because the cost-telemetry / dormancy / margin
  producer queries scan rolling windows on `usage_logs` and can be
  expensive against staging (per
  `docs/contracts/slice_runtime_acceptance_contract.md` performance
  defaults).
- A "Run observability check" button is visible in the header
  (`Key('admin_observability_refresh_button')`).
- Below the header, the "View health envelope on the Health surface"
  link hint (`Key('admin_observability_health_link_hint')`) tells
  the operator the dependency probes / tier-1 metric tiles still
  live on the Health route.

### Step 2 - Run the observability check

Click `Run observability check`.

**Expected:**

- The confirmation dialog
  (`Key('admin_observability_confirm_dialog')`) opens with copy
  explaining that the producer queries are read-only but can take
  10-30+ seconds.
- Click `Run check`
  (`Key('admin_observability_confirm_run')`); the dashboard
  populates.
- The as-of strip (`Key('admin_observability_as_of_strip')`)
  renders the envelope timestamp + summary chips: `Dormant: 1`
  (Sunset Cafe Group), `Underwater: 1` (Sunset Cafe Group),
  `Cap events: 2`. The dormant + cap-events chips render warning;
  the underwater chip renders negative.
- Six tabs render with stable keys
  (`admin_observability_tab_cost`, `..._top`, `..._operators`,
  `..._cap_events`, `..._graph`, `..._cloud_run`).

### Step 3 - Cost tab: telemetry by every phase_11A axis

The Cost tab is selected by default. Above the cost-telemetry table,
a filter bar renders:

- A `query_class` text field
  (`Key('admin_observability_cost_query_class_filter')`).
- An `Apply` button
  (`Key('admin_observability_cost_query_class_filter_apply')`)
  that re-fetches the envelope through the gateway with the scope
  narrowed server-side.
- A "Showing N of M rows" hint
  (`Key('admin_observability_cost_count')` when the result is
  exhaustive, `Key('admin_observability_cost_truncated')` when the
  proxy hit `kObservabilityCostTelemetryLimit = 100` and clamped).

The cost-telemetry section then renders four rows from the demo
envelope, exercising every axis called out in phase_11A lines 356-359:

- `(operator_id, location_id, usage_class, query_class)` for the
  Demo Diner Yorkville advisor_qa total
  (`Key('admin_observability_cost_row_..._advisor_qa')`).
- `(operator_id, location_id, staff_id, usage_class, query_class)`
  for the staff Owner @ Demo Diner coach_qa row.
- `(operator_id, location_id, workflow_id, usage_class, query_class)`
  for the workflow `wf_pl` row.
- `(operator_id, location_id, usage_class, query_class)` for the
  Sunset Cafe Group total (low cost).

The table is rendered inside a fixed-height
(`admin_observability_cost_table_viewport`) virtualized
`ListView.builder` so an envelope at the 100-row server cap renders
only the visible window. Type `wf_pl` into the filter and click
`Apply`; the table re-fetches with `query_class=wf_pl`, the active
filter chip
(`Key('admin_observability_cost_query_class_filter_chip')`) appears,
and only the workflow row remains in the table.

Below the cost table:

- **Cache hit rate per query_class** -
  `advisor_qa` (61% green), `coach_qa` (48% green), `wf_pl` (22%
  warning — under the 30% yellow threshold so chip flips warning).
- **Model mix per query_class** - `advisor_qa` 78/22 Haiku-Sonnet
  (green), `coach_qa` 55/45 (Sonnet share above the 40% ceiling →
  warning), `wf_pl` 10/90 (within the 95% ceiling for the planner
  workflow → green).
- **Batch-mode share per query_class** - `wf_pl` 62% (above 50%
  target → green), `wf_schedule` 34% (below target → neutral).

Click `Run observability check` again, confirm.

**Expected:**

- The dashboard re-fetches; the as-of timestamp updates to the new

### Step 10 - Edge: empty envelope renders the empty states

Re-seed the in-memory gateway with the demo envelope minus

In live mode, an envelope where the proxy returns a 200 with
zero rows for any section produces the matching empty caption (one
per section card). A 4xx / 5xx response from the proxy is rendered
through `Key('admin_observability_load_error')` with the typed
gateway error message.

## Permission gating evidence

- Client side (admin console): the Observability route is reachable
  whenever the auth gate admits the caller (super_admin or
  ff_support); `operator@forgeflow.test` lands on the forbidden card.
  The screen has no mutate affordances, so there is no
  `editingEnabled` branch.
- Server side (proxy): the live HTTP gateway hits
  `GET /v1/admin/observability`. That route lands behind the same
  admin-read role gate the rest of 11A's read endpoints use. Live
  evidence is a follow-up: at the time this slice ships the proxy
  endpoint is not yet wired, so production wiring falls back to the
  in-memory demo gateway via the `_defaultObservabilityDemoGateway`
  scope fallback. The screen surfaces a typed
  `ObservabilityAdminGatewayError` with status code + error code +
  message when the live endpoint returns non-2xx, so once the proxy
  lands, failure modes are already handled.

## Performance posture (slice runtime acceptance contract §Performance Defaults)

- **No auto-polling.** The first paint shows the manual-run prompt,
  not a spinner. The producer queries (cost-telemetry rolling-window
  scans on `usage_logs`, dormancy `last_active_at` lookups,
  per-route latency aggregations) are not on a refresh timer. Every
  fetch requires an explicit click.
- **Confirmation dialog.** Before any fetch fires, the operator
  confirms the run via `Key('admin_observability_confirm_dialog')`.
- **No stacked in-flight requests.** The `_refreshing` guard on the
  screen state blocks duplicate calls; the
  `_BlockingObservabilityGateway` widget test asserts that a second
  confirmed click while the first fetch is pending is a no-op.
- **Long-call timeout.** The HTTP gateway uses
  `kAdminHealthHttpRequestTimeout` (60s) because cost / dormancy
  scans can be slow.
- **No /health duplication.** The screen explicitly does NOT consume
  the `/health` envelope's tier-1 / tier-2 / tier-3 metric tiles. A
  header hint sends the operator to the Health route for those
  signals so the producer queries do not fan out twice.
- **Bounded cost-telemetry result.** The HTTP gateway always sends
  `cost_telemetry_limit` (clamped to
  `kObservabilityCostTelemetryLimit = 100`); the proxy mirrors the
  cap server-side. The rendered table is a virtualized
  `ListView.builder` inside a fixed-height viewport, so a 100-row
  result paints only the visible window. The truncation hint
  surfaces when the proxy clamps; the operator narrows the scope
  via the `query_class` filter input. This honours the runtime
  acceptance contract's "scoped data only / pagination /
  virtualization for large admin tables" rule.
