# 10a.UX.1 Walkthrough — Peer-edit toast + Settings freshness rows

**Slice:** 10a.UX.1 (Phase 10a — Shared Multi-Device State V1, UX surface 1 of 2)
**Mode:** Consumes the shared `RealtimeSubscription` instantiated by sibling lane 10a.UX.0 in `bootstrapAndRunApp`. UX.0's `RealtimeAuthBridge` owns the auth-driven lifecycle (`setTenantContext` / `clearTenantContext`); this slice pipes the same subscription's `events` into the bus and clears the freshness map on hard sign-out / operator change.
**Date:** 2026-05-03

This walkthrough exercises the operator-facing fan-out from a real
WebSocket frame all the way to two shell-mounted surfaces:

1. A transient "Peer edit: <table>" SnackBar — the [PeerEditToast]
   widget wraps `MaterialApp.home`, so the SnackBar fires across
   every route the operator navigates to.
2. A "Data freshness" section in Settings → Data with one row per
   shared-state table, flipping from "Never" to a relative timestamp
   ("just now", "2 min ago", …) on each frame; the absolute UTC ISO
   timestamp surfaces in the row's tooltip.

The Hard Promise this slice realizes:

> Every backend phase ships its operator-facing UX before phase close.
> Phase docs include a `Frontend Exposure` section. UX-exposing slices
> include a demo-mode walkthrough.

10a.0 lands the realtime push channel; 10a.UX.0 owns the sync-state
badge in the app bar; 10a.UX.1 (this slice) owns the operator-facing
acknowledgement that another device has just changed shared state.

    2. **`_RealtimeProducerWiring`** widget consumes the **shared**

## End-to-end runtime data flow

```
Postgres event_outbox row
  ↓ (Phase 10a.0 bridge, claim + publish)
RealtimeEventPublisher
  ↓
/v1/realtime WebSocket  ← Cloud Run proxy
  ↓
WebSocketChannelRealtimeTransport (lib/services/realtime/)
  ↓
RealtimeSubscription
  ↓ (.events stream)
_RealtimeProducerWiring  ← shell-mounted (lib/forge_flow_app.dart)
  ↓ (subscription.events.listen(bus.publish))
RealtimeEventBus
  ↓ (.events broadcast)
  ├── PeerEditToast ─→ ScaffoldMessenger SnackBar (shell-level wrap)
  └── LastSyncedTimestampsNotifier ─→ SettingsDataFreshnessSection rows
```

`AuthSessionNotifier` is the orthogonal input: when the session
flips, sibling lane 10a.UX.0's `RealtimeAuthBridge` (mounted above
the app shell in `bootstrapAndRunApp`) calls
`subscription.setTenantContext(operatorId, firebaseIdToken)` on
sign-in and `subscription.clearTenantContext()` on sign-out. UX.1's
`_RealtimeProducerWiring` watches the same notifier independently,
but only for its own concern: clearing
`LastSyncedTimestampsNotifier` on hard sign-out and on operator
change so the prior tenant's freshness rows do not survive the
session.

## Topic + payload extraction rule

Both surfaces apply the same Phase 11a §Lock 9 rule:

1. **Topic gate.** The frame's topic MUST start with
   `shared_state.<operator_id>.<table>`. Any other topic
   (`auth.*`, `usage.cap.*`, `rollup.invalidate.*`, …) is ignored —
   those are not shared-state row pushes even if they carry a
   `table` payload field, and stamping freshness or toasting for
   them would mislead operators about which channel is alive.
2. **Within a qualifying frame**, `payload['table']` (the Lock 9
   canonical field) takes precedence as the table name; the topic
   last segment is the fallback for producers that haven't migrated
   to the locked payload schema yet.

## Manual demo path

The shell wires the producer end-to-end in production today. The
walkthrough below assumes a Postgres + proxy + Flutter web setup
(same as `docs/_walkthroughs/10a.0.md`) and proves the slice from
real `event_outbox` row to operator surfaces.

1. **Start a local Postgres** with the migration catalog applied
   so `event_outbox` + the trigger exist (same step as 10a.0).
2. **Run the proxy** with `POSTGRES_URL` / `POSTGRES_ADMIN_URL` set.
   The bridge log line `realtime.bridge.*` confirms the bridge is
   running (10a.0).
3. **Run the Flutter shell** with both:

   ```sh
   --dart-define=FORGE_FLOW_USE_FIREBASE_AUTH=true \
   --dart-define=FORGE_FLOW_PROXY_BASE_URI=http://localhost:8080
   ```

   The same URI shape that drives the existing REST clients
   (`http://`/`https://`) drives the realtime channel — sibling lane
   10a.UX.0's `_toWebSocketUri` in `main_forgeflow.dart` normalizes
   the scheme to `ws://`/`wss://` before instantiating
   `RealtimeSubscription`. Production deploys use
   `https://forge-flow-proxy.run.app`, which becomes
   `wss://forge-flow-proxy.run.app/v1/realtime` at the transport.
   `bootstrapAndRunApp(realtimeSubscription: …)` wires the same
   instance into a `Provider<RealtimeSubscription?>` that UX.1's
   producer widget consumes for `events`.
4. **Sign in.** `AuthSessionNotifier` flips to
   `AuthSessionAuthenticated`. UX.0's `RealtimeAuthBridge` (which
   sits above the app shell) calls
   `subscription.setTenantContext(operatorId, firebaseIdToken)`.
   The subscription opens `ws://localhost:8080/v1/realtime` with
   the bearer token. UX.1's `_RealtimeProducerWiring` is already
   subscribed to `subscription.events` and pipes frames into the
   bus from the same instance UX.0's badge reads `connectionState`
   from. UX.1 also takes this signal as a freshness-clear gate
   (cleared on hard sign-out and on operator change).
5. **Open Settings → Data.** The "Data freshness" card sits between
   "Data status" and "Data management". Eight rows; every row
   reads "Never" (no shared-state frame seen yet this session).
6. **In a separate terminal**, INSERT a fake outbox row using the
   topic shape Phase 11a §Lock 9 reserves for shared-state pushes:

   ```sql
   begin;
   select set_config('app.operator_id',
     '11111111-1111-1111-1111-111111111111', true);
   select set_config('app.location_id',
     'aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa', true);
   insert into public.event_outbox (operator_id, topic, payload)
   values (
     '11111111-1111-1111-1111-111111111111',
     'shared_state.11111111-1111-1111-1111-111111111111.weekly_plan_snapshots',
     jsonb_build_object(
       'event_id', gen_random_uuid()::text,
       'occurred_at', to_char(now() at time zone 'utc',
         'YYYY-MM-DD"T"HH24:MI:SS.MS"Z"'),
       'schema_version', 1,
       'table', 'weekly_plan_snapshots',
       'op', 'UPDATE',
       'primary_key', 'plan-2026-W18',
       'version', 47
     )
   );
   commit;
   ```

7. **Within ~1 second**, the bridge claims the row, publishes
   through the in-process publisher, and the WebSocket delivers
   the frame. The shell:
    - surfaces a SnackBar reading "Peer edit: weekly_plan_snapshots"
      (the toast wraps the home, so it fires regardless of which
      route the operator is on); and
    - flips the `weekly_plan_snapshots` row in Settings → Data →
      Data freshness from "Never" to "just now". Hover the
      timestamp — the tooltip shows the absolute UTC ISO instant.
8. **INSERT a second row** with a different topic (e.g.
   `shared_state.<op>.connector_configs`). The toast fires again
   with "Peer edit: connector_configs" and the
   `connector_configs` row flips while the
   `weekly_plan_snapshots` row keeps its earlier timestamp.
9. **INSERT a non-shared row** (e.g. topic
   `rollup.invalidate.variance_week`). Neither the toast nor any
   freshness row reacts — the topic gate excludes it, even if the
   payload happens to carry a `table` field.

## Out of scope (explicit Phase 10a/10b follow-ups)

- **Same-device suppression of the freshness map clear path.** UX.0's
  `RealtimeAuthBridge` calls `clearTenantContext` on sign-out which
  closes the socket; UX.1 also clears the freshness map on the same
  signal. There's no shared coordination point between the two —
  each lane wires its own `AuthSessionNotifier` listener for its own
  reset concern. That's deliberate; the lanes own different state.
- **Same-device suppression.** The phase doc calls for suppressing
  the toast when the same device made the change (line 285-286).
  That requires a device-id origin filter, which depends on the
  proxy stamping `payload['origin_device_id']` and the client
  knowing its own device id. Both are Phase 10b work and slot into
  `_PeerEditToastState._onEvent` without changing the public API.
- **"Row the user is viewing" filtering.** Today the toast fires
  for every `shared_state.*` frame. Filtering by which row the
  operator is currently looking at (line 283-284) lives in Phase
  10b alongside the conflict-resolution UI.
- **Cold-start persistence of the freshness map.** The notifier is
  in-memory only. Surviving a process restart needs a SQLite cache
  of `(table, last_synced_at)` pairs; that lands in Phase 10b's
  full-offline-sync work.
