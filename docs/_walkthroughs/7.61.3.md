## What changed

### `lib/dev/demo_fixture_data.dart`

- Lines 89-92 (now lines 89-114):
  `static LeverCardData get primaryLeverCard => LeverCards.all.firstWhere(
  (l) => l.id == primaryLeverId, orElse: () => LeverCards.coversDown)`
  → the getter now delegates to a new `resolveLeverCard(String id)`
  helper that calls `LeverCards.lookup(id) ?? (throw StateError(...))`.
  `primaryLeverId` is sourced from `LaborModel.determineLever` (an
  R-PROD-1 producer), which always returns a catalog id, so the
  StateError branch is defense-in-depth. If a future producer
  regression ever lands an id outside the catalog, the demo fixture now
  fails loudly at the call site instead of silently materializing
  `LeverCards.coversDown` and pretending the engine picked it.
- The resolver was split out as a separately-callable static method
  rather than inlined into the getter so the contract test can pin
  the unknown-id failure boundary directly. The deterministic seed
  always mints `'covers_down'`, so calling the getter alone could not
  exercise the StateError branch — pre-fix `firstWhere(orElse: …)`
  would have produced the same `LeverCards.coversDown` instance for
  this id, and any test asserting only against `primaryLeverCard`
  would silently pass against both implementations. The
  `resolveLeverCard` helper is annotated `@visibleForTesting` (already
  in scope via the file's `package:flutter/foundation.dart` import,
  no new dependency).
- Audited the rest of the file for the same pattern. No other
  `firstWhere(orElse: …)` calls remain in `lib/dev/` (verified via
  `Grep` across the full directory). `lib/dev/fixture_seed_data.dart`
  hardcodes the `'ON_MODEL'` sentinel for non-closed scenarios per
  R-PROD-3 — that file has no consumer path that resolves through
  `LeverCards.lookup`, so it is intentionally out of scope (per the
  slice prompt's "Files to leave alone" list).
- Carries a one-block comment naming the slice and citing R-CONS-1 +
  R-STOR-7 + R-PROD-1, plus a docstring on `resolveLeverCard`
  cross-referencing the renderer-side R-CONS-3 contract on
  `lib/models/shift_dashboard_read_model.dart`.

### `test/contracts/phase_7_61_driver_key_test.dart`

- New import: `package:forge_and_flow/dev/demo_fixture_data.dart` (the
  test file already imports other `package:forge_and_flow/...` paths;
  no new dependency).
- New group `F-3 — demo_fixture_data primaryLeverCard resolves through
  LeverCards.lookup, never silently maps unknown ids to coversDown`
  with five assertions covering both the deterministic getter and the
  parameterized resolver helper:
  1. **Lookup-path equivalence (golden path on the getter)** —
     `identical(ShiftSnapshot.primaryLeverCard, LeverCards.lookup(ShiftSnapshot.primaryLeverId))`.
     Confirms the getter still returns the same instance lookup
     returns for the seed-minted id (`'covers_down'`).
  2. **Catalog-membership round-trip on the getter** —
     `card.id == primaryLeverId` AND `card.id ∈ _expectedCatalog`.
     Pins the R-CONS-1 rule that the resolved card id equals the
     engine-minted id.
  3. **Unknown id throws StateError naming the offending id
     (regression pin)** — `expect(() =>
     ShiftSnapshot.resolveLeverCard('made_up_lever'),
     throwsA(isA<StateError>().having((e) => e.message, 'message',
     contains('made_up_lever'))))`. This is the assertion that
     actually catches a revert: pre-fix
     `firstWhere(orElse: () => LeverCards.coversDown)` would have
     silently returned `LeverCards.coversDown` instead of throwing,
     and this expectation would fail. Asserts the message names the
     id so the failure is debuggable.
  4. **`on_model` sentinel throws StateError** — same shape as
     assertion 3 but for the sentinel branch (R-STOR-6). A future
     "treat sentinel as coversDown" regression would slip past an
     unknown-id-only pin; this assertion closes that gap.
  5. **Known catalog id resolves to the matching card via the
     resolver helper (golden-path regression guard)** —
     `identical(ShiftSnapshot.resolveLeverCard('cplh_down'),
     LeverCards.cplhDown)`. Catches a refactor that breaks the lookup
     direction (e.g. a resolver that throws for every input).

The pre-existing F-2 holdout test stays `skip:`-marked — removing the
skip is owned by `7.61.2`. Together the five F-3 assertions exercise
both branches of the resolver (lookup-hit via the getter; lookup-miss
via the helper), so a revert to the banned `firstWhere(orElse: …)`
pattern fails assertion 3 (and 4) regardless of what `primaryLeverId`
happens to be on the deterministic seed.

## Why dev-only / no UX sub-slice

`ShiftSnapshot.primaryLeverCard` (the specific getter changed by this
slice) is consumed by:

- Test suites only — `shift_dynamic_truth_test.dart`,
  `shift_driver_trust_audit_test.dart`,
  `current_state_alignment_test.dart`. Each uses the getter to assert
  the read-model resolves the right card for the deterministic demo
  seed. Pre-fix and post-fix behavior is identical for the golden
  path (the engine always returns a catalog id, so the lookup always
  resolves), so the tests stay green without modification.
- `Grep`-verified zero call sites under `lib/`. Production rendering
  of the primary-lever card flows through
  `lib/models/shift_dashboard_read_model.dart:298`
  (`primaryLeverCard: leverCard`), which already uses
  `LeverCards.lookup(leverId)!` per `7.58.UX.5` (R-CONS-3, audited at
  `phase_7_61_audit_plan.md` line 313-316).

## Demo / dev path verification

The fixture's two consumer paths still render correctly under the
default deterministic seed:

- `ShiftSnapshot.primaryLeverId` resolves to a catalog id via
  `LaborModel.determineLever(actualCovers: 52, forecastCovers: 82,
  ...)`. With `actualCovers = 52` (light) and `forecastCovers = 82`,
  the engine picks `'covers_down'` (the demo fixture's intended
  driver — the file's surrounding comments call out the
  "covers light" narrative explicitly at lines 46, 55, and 72).
- `ShiftSnapshot.primaryLeverCard` returns
  `LeverCards.coversDown` via `LeverCards.lookup('covers_down')` —
  byte-identical to the pre-fix return for this seed (the
  `firstWhere` would have matched the same card on the first
  iteration of `LeverCards.all`).
- Downstream test assertions (`primaryLeverCard.whatHappened` is
  non-empty, `primaryLeverCard.id == primaryLeverId`, etc.) pass
  unchanged.

The only behavioral difference is at the failure boundary: an
unknown id now throws StateError instead of returning
`LeverCards.coversDown`. This is the intended R-CONS-1 enforcement.
