# 8.star-target-server-truth Walkthrough

Date: 2026-05-06

## Operator Story

1. Closed shift history exists for the 60-day calibration window.
2. Mobile shows star-shift candidates from cached closed shift rows.
3. Manager selects or clears stars on the Baseline Manager screen.
4. In live Firebase/proxy builds, mobile posts each changed decision to the
   proxy with an idempotency key before updating the SQLite mirror.
5. The proxy verifies caller scope, checks `forgeflow.baseline.override` for
   writes, and writes selected-star decision truth plus audit events.
6. Server projection consumes current server-selected stars, replaces the
   active target cycle under the once-per-cycle guard, and writes active target
   profile truth plus a profile version row.
7. Mobile sync pulls selected-star decisions, target cycles, active profiles,
   and target profile versions through proxy read routes.
8. Another device sees the same selected-star and target-profile truth after
   sync because SQLite is only a cache.

## Important Failure States

- Missing auth token: mobile blocks the star-selection write and asks the user
  to sign in again.
- Permission denied: mobile keeps the screen open and leaves the local cache
  unchanged.
- Missing star-target proxy route: sync reports an unavailable star-target
  mirror instead of inventing local truth.
- Empty sync page: proxy returns `next_cursor: null`, so mobile terminates the
  page loop cleanly.
- Once-per-cycle denial: server target-cycle repository rejects the second
  manager override and no active profile projection is written.
