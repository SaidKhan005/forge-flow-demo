# 11A.3b Walkthrough - Graphify candidate review console

**Slice:** 11A.3b (Phase 11A - F&F Operations Console)
**Mode:** `-DemoMode` (admin Flutter Web client + in-memory corpus
gateway, no live Voyage / Anthropic / Cloud Run admin proxy required)
**Date:** 2026-05-01

This walkthrough covers the admin click path called out in the 11A.3b
prompt's *Operator walkthrough* section: opening the new "Graph
candidates" tab on the Corpus admin screen, reviewing the three
classification buckets (EXTRACTED / INFERRED / AMBIGUOUS) the
Graphify importer produced, bulk-approving the EXTRACTED bucket,
per-edge approving an INFERRED candidate, editing one AMBIGUOUS
candidate before approving, rejecting one INFERRED candidate (which
must NOT land in the canonical-graph tables), and verifying that the
AGE rebuild button surfaces the launch-slice 501 stub. The demo
source is opt-in (`-DemoMode`); production binds the live Firebase
admin auth source + HTTP gateway (`HttpCorpusAdminGateway`) against
the F&F admin Cloud Run proxy.

## Authority files exercised

- `lib/main_admin.dart` - production binds
  `HttpCorpusAdminGateway` against
  `--dart-define=ADMIN_PROXY_BASE_URI=...` and wraps
  `AdminConsoleApp` in `AdminConsoleServicesScope` with the corpus
  gateway alongside the operator/location and pricing gateways.
- `lib/admin/screens/corpus_admin_screen.dart` - the corpus admin
  surface gains a TabBar (`admin_corpus_tab_bar`) with two tabs
  (`admin_corpus_tab_versions`, `admin_corpus_tab_graph_candidates`).
  The new `_GraphCandidatesTab` widget owns the graph-candidate diff
  load + per-bucket render + per-row approve/reject/edit affordances
  + bulk-approve EXTRACTED button + Commit batch button + Discard
  queue button + AGE rebuild button + 501 stub banner +
  ff_support read-only path.
- `lib/admin/models/corpus_admin_models.dart` - new types
  `GraphCandidate`, `GraphCandidateLabel`, `GraphCandidateKind`,
  `GraphCandidateDiff`, `ApprovalDecision`, `GraphDecisionKind`,
  `BatchCommitCommand`, `BatchCommitResult`, plus the launch-time
  warning threshold (`kGraphCandidateConfidenceWarningThreshold = 0.7`).
- `lib/admin/services/corpus_admin_gateway.dart` - the
  `CorpusAdminGateway` interface grows three new methods
  (`listGraphCandidates`, `commitGraphCandidatesBatch`,
  `requestAgeRebuild`); `InMemoryCorpusAdminGateway` accepts
  `graphCandidateSeed` and exposes `debugApprovedNodes /
  debugApprovedEdges / debugRejectedAudit` for the demo and for
  widget tests; `HttpCorpusAdminGateway` adds the matching
  `graphCandidatesPath / graphCandidatesCommitPath / ageRebuildPath`
  bindings against the proxy.
- `lib/infrastructure/persistence/postgres/repositories/graph_repository.dart`
  - `GraphRepository.commitBatch` is the single write boundary.
  Approves write to `public.graph_nodes` / `public.graph_edges`
  with full provenance (admin actor, approval timestamp, source
  doc, source ref, Graphify version, source commit). Rejects write
  to `public.graphify_review_audit` only — the audit table has zero
  FKs back to canonical-graph rows, so AGE traversal physically
  cannot reach a rejected candidate. Mixed batches sort nodes
  before edges so the composite FK on `graph_edges.from_node_id /
  to_node_id` always finds its target inside the same transaction.
  Audit-logs fan-out is gated by `AuditLogsCutoverFlag`.
- `db/migrations/202605020001_phase_11A_3b_graphify_review_audit.sql`
  - `public.graphify_review_audit` table (`audit_id`, `operator_id`,
  `location_id`, `decided_by`, `decided_at`, `decision`,
  `reason`, `candidate_kind`, `candidate_payload`,
  `target_graph_scope`, `target_graph_version`, `source_file`,
  `source_ref`, `confidence_label`, `confidence_score`,
  `idempotency_key`). Tenant-leading B-tree indexes
  (`graphify_review_audit_recent_idx`,
  `graphify_review_audit_target_idx`). RLS via wrapper
  (`public.app_current_operator()`); append-only by grant shape
  (UPDATE/DELETE explicitly REVOKEd from service_role and
  forge_admin). Composite FK to `public.locations(operator_id,
  location_id)` so a cross-operator location pointer is a database
  error.
- `tool/advisor_corpus/advisor_corpus.dart` -
  `GraphifyCandidateImporter` reads `graphify-out/graph.json` (the
  Graphify v5 producer artifact), applies the corpus_manifest
  scope filter (drops candidates whose `source_file` is not in
  `manifest.documents[*].source_path`), normalizes Graphify-emitted
  node/edge types into the F&F approved vocabulary
  (`kGraphifyApprovedNodeTypes`, `kGraphifyApprovedEdgeTypes`),
  fans out hyperedges with arity ≥ 2 to pairwise edges with a
  shared `hyperedge_id` in payload, dedupes by candidate_id, and
  emits deterministic JSONL artifacts under
  `graphify-out/candidates/`
  (`graphify_node_candidates.jsonl`,
  `graphify_edge_candidates.jsonl`,
  `graphify_candidate_manifest.json`).
- `tool/advisor_proxy/advisor_proxy.dart` -
  `/v1/admin/corpus/graph-candidates` (`GET`),
  `/v1/admin/corpus/graph-candidates/commit-batch` (`POST`),
  `/v1/admin/age/rebuild` (`POST`). Method-scoped role gate:
  `kFfCorpusAdminReadRoles` (`super_admin` + `ff_support`) for
  GET; `kFfCorpusAdminWriteRoles` (`super_admin`) for POST.
  Idempotency-Key header required on every non-GET route. CORS
  preflight (`_setAdminCorpusCorsHeaders`) admits the new paths
  through the same OPTIONS branch the corpus admin uses.
  Defense-in-depth manifest scope filter
  (`_enforceGraphCandidateSourceScope`) rejects any decision whose
  `payload.source_file` is not in the manifest with a typed
  `source_out_of_scope` 403. AGE rebuild route returns 501
  `not_implemented` with a typed banner message — the rebuild
  infrastructure ships in a follow-up slice.
- `tool/advisor_proxy/proxy_bootstrap.dart` -
  `RepositoryGraphCandidatesProxyGateway` binding wired from
  `GraphRepository`. The launch binding raises a typed
  `graph_candidates_not_configured` 503 from `listGraphCandidates`
  and `commitBatch` until the operator-id resolution from the F&F
  admin actor is finalized in a follow-up slice; the demo gateway
  runs end-to-end via `InMemoryCorpusAdminGateway` for the
  walkthrough.

### Step 7 - Edge: manifest-out-of-scope file is filtered from the diff

The importer reads the corpus manifest before writing the JSONL
artifacts the proxy serves. A graph node sourced from a markdown
file the manifest does NOT list (e.g., `unmanifested_doc.md`) is
dropped at importer time (`droppedOutOfScopeCount` counter). The
proxy applies the same filter again as defense-in-depth on every
commit-batch request body — any decision whose
`payload.source_file` is not in the manifest scope returns
`403 source_out_of_scope`.

**Expected:**

- The `Graph candidates` tab never shows a candidate referencing an
  out-of-scope source file. There is no UI surface for a hand-
  crafted out-of-scope decision; the proxy's defense-in-depth
  filter is asserted by
  `test/services/proxy_graph_candidates_routes_test.dart` test
  `POST commit-batch with decisions[*].source_file outside the
  manifest scope returns 403 source_out_of_scope`.

## Permission gating evidence

- Client side (admin console): the corpus route is only reachable
  when the auth gate admits the caller (`super_admin` or
  `ff_support`); `operator@forgeflow.test` lands on the forbidden
  card. The `_GraphCandidatesTab` widget honours `editingEnabled`
  (default `true`); when `false` (the live ff_support path), every
  mutate affordance is hidden and the diff still renders. Asserted
  in `test/admin/corpus_admin_graph_candidates_test.dart` test
  `editingEnabled: false (ff_support) hides every mutate
  affordance but still renders the diff`.
- Server side (proxy): every
  `/v1/admin/corpus/graph-candidates*` and
  `/v1/admin/age/rebuild` request verifies the Firebase bearer
  token through `_resolveVerifiedClaimsOrWrite` and then evaluates
  a method-scoped role set — `kFfCorpusAdminReadRoles`
  (`super_admin` + `ff_support`) for GET, `kFfCorpusAdminWriteRoles`
  (`super_admin` only) for every mutation method. Asserted by
  `test/services/proxy_graph_candidates_routes_test.dart`.

## Idempotency evidence

- Every non-GET graph-candidate route requires the `Idempotency-Key`
  header. Missing key → 400 `missing_idempotency_key`.
- **Launch-slice posture: in-process Future cache.**
  `RepositoryGraphCandidatesProxyGateway` keeps an in-process
  `Map<String, Future<Map<String, Object?>>>` keyed by
  `idempotencyKey`. The `commitBatch` wrapper is intentionally
  non-async so it reserves the in-flight `Future` synchronously
  before the first await — two overlapping retries in the same
  isolate share the same `Future` and only one transaction opens.
  On pre-graph-commit error the cache entry is removed so a fresh
  retry can succeed; on success or post-graph-commit audit failure
  the cache entry stays populated so a retry returns the cached
  success without re-running canonical writes (which would trip
  the canonical UNIQUE on
  `(operator_id, graph_scope, graph_version, node_key)`).
- **Multi-instance dedup is a follow-up.** This launch posture
  covers the single-Cloud-Run-instance shape and the F&F admin
  screen's retry behaviour. Multi-instance fan-out — promoting
  the dedup to the table-backed
  `proxy_requests(route, idempotency_key)` ledger that the 11A.3a
  rollback path already lights up via
  `CorpusRepository.rollbackToVersion(idempotencyKey: ...)` —
  lands in a follow-up slice. The contract surface (header
  required, replay returns cached response) does not change when
  the backing store moves to the table.
- **Auth-events audit is best-effort post-commit.** The graph
  commit's hash-chained system audit row (`public.audit_logs`)
  fires inside the same tenant transaction as the canonical
  graph writes via
  `graph_repository.dart`'s `_fanOutToAuditLogs`, so the SOC-2
  audit trail commits or rolls back atomically with the data.
  The secondary `auth_events_audit` row written by
  `_audit(...)` after the graph commit is best-effort: a failure
  there is logged to stderr but does NOT propagate to the caller
  and does NOT clear the idempotency cache. Without that
  swallow, an audit-only blip would re-execute graph writes on
  retry and trip canonical UNIQUE for an operation that already
  succeeded.
- Asserted in
  `test/services/repository_graph_candidates_proxy_gateway_test.dart`
  tests:
  - `idempotency-key replay returns cached result without
    re-running GraphRepository.commitBatch` — pins the
    success-replay path.
  - `concurrent commitBatch calls with the same idempotency-key
    share one transaction (in-flight Future is cached BEFORE
    awaits, so two overlapping retries cannot both stamp
    duplicate audit rows or trip canonical UNIQUE)` — pins the
    sync-prefix concurrent-dedup contract.
  - `audit failure AFTER graph commit does not clear
    idempotency cache; retry returns cached success without
    re-running graph writes` — pins the best-effort
    auth_events_audit semantics.
- Route-level enforcement also asserted in
  `test/services/proxy_graph_candidates_routes_test.dart` tests
  `POST commit-batch with same Idempotency-Key replayed returns
  the same payload (gateway dedupes)` and
  `POST /v1/admin/age/rebuild without Idempotency-Key returns
  400`.
