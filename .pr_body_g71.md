## G71 — Admin 401 token-refresh-and-retry (cross-surface parity §0b)

> ⚠️ **AUTH-TOUCHING SLICE — explicit operator merge approval is required
> regardless of audit verdict.** This changes the admin HTTP auth-failure
> recovery path. Per `CLAUDE.md` workflow, auth-critical slices do not
> auto-merge on a clean audit.

### Problem

Admin had **no** `401 → refresh-token → retry-once` recovery on any admin
gateway. A clock-skewed device or a mid-rotation Firebase ID token surfaced
as a hard 401, so destructive admin actions hard-failed on a transient
token problem that **mobile and operator-web silently recover from** (G61).
This slice is the admin parallel of G61.

### The 401-retry contract

One centralized chokepoint — `sendAdminHttpRequest`
(`lib/admin/services/admin_http_timeout.dart`), the layer **all 21
mutating/destructive admin `Http*` gateways funnel through** via their
`_dispatch` helpers. No per-gateway hacks; one chokepoint, mirroring the
established mobile pattern (`lib/services/sync/http_sync_proxy_client.dart`
`_getJson`/`_postJson` 401→refresh→retry-once shape).

On the chokepoint
(`lib/admin/services/admin_http_timeout.dart:103-148`):

| Case | Behaviour |
|---|---|
| 401, **no** refresh hook wired (demo / share-preview / tests) | return the 401 — **pre-slice behaviour, byte-equivalent** |
| 401, hook wired, refresh **succeeds** | rebuild the **identical** request, swap **only** the bearer, send **once**, return whatever comes back |
| 401, hook wired, refresh **returns null / throws** | return the original 401 — genuine-auth-failure path, no retry |
| 401 then 401 (retry still fails) | the second 401 is the **final** answer — exactly one retry, **no loop** |
| any **non-401** status | returned untouched, refresh hook never consulted, exactly one send |

- Refresh-once only: `_AdminRequestSnapshot` is taken **before** the first
  send (`http.BaseRequest` is single-use); the retry sends the rebuilt
  request exactly once, then returns regardless of outcome
  (`admin_http_timeout.dart:138-147`). No recursion, no loop.
- The pre-existing 403 `mfa_freshness_required` interception
  (`admin_http_timeout.dart:149-177`) runs on whatever response is final
  — unchanged.

### Idempotency-key preservation proof (the G60/G70 bug class)

Every admin gateway stamps a **caller-stable** `Idempotency-Key` on the
request before calling the chokepoint (e.g.
`lib/admin/services/admin_security_gateway.dart:424`,
`lib/admin/services/members_admin_gateway.dart:962`,
`lib/admin/services/admin_account_gateway.dart:163`,
`lib/admin/services/integration_admin_gateway.dart:194`,
`lib/admin/services/pricing_tier_admin_gateway.dart:154`).

The retry rebuild **copies every header verbatim** and re-stamps **only**
`authorization`:
`_AdminRequestSnapshot.rebuildWithBearer`
(`lib/admin/services/admin_http_timeout.dart:163-201`) iterates the
snapshotted headers and overwrites in place only the case-insensitive
`authorization` key — `Idempotency-Key` (and body, method, URL, encoding,
redirect policy) flow through **unchanged**. The key is **never re-minted**
(that is the G60/G70 bug class). Test `401 then success` asserts
`first.headers['Idempotency-Key'] == retry.headers['Idempotency-Key'] ==
'idem-key-abc-123'` and `retry.body == first.body`
(`test/admin/admin_http_timeout_test.dart:54-72`).

### Behaviour-neutrality

The **only** change is: on a 401, admin now refreshes the token once and
retries the identical request. Every non-401 path is byte-equivalent —
`_sendOnce` (`admin_http_timeout.dart:182-200`) is the verbatim extraction
of the pre-slice send+timeout body (same timeout envelope, same
`AdminHttpTimeoutException` mapping). When no hook is wired (the demo /
share-preview / default / test state) the first 401 returns exactly as
before.

### Tests

`test/admin/admin_http_timeout_test.dart` (6 new G71 tests, group
`G71 — admin 401 force-refresh-and-retry-once`):

1. **401 then success** — request retried **once** with the refreshed
   token and the **identical** idempotency key + body; first attempt
   carried the stale bearer, retry carried `Bearer fresh-token-v2`,
   `Idempotency-Key` reused verbatim, method/URL/body preserved.
2. **401 then 401** — surfaces the same 401 the caller saw before this
   slice; refresh fired exactly once, exactly two sends, **no third send /
   no loop**; retry still carried the same idempotency key.
3. **Non-401 (500) error path unchanged** — 500 returned untouched,
   refresh hook never consulted, exactly one send (pre-slice
   byte-equivalent).

Plus 3 supporting edge tests: no hook wired (demo) → no retry; refresh
returns null (signed out) → original 401, no retry; refresh throws
(network) → original 401, no retry.
